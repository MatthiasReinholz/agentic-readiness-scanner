## Summary

Do not rely on an accessibility overlay widget: fix the barriers in your theme and content instead, and consider removing the overlay once the fixes are in place. If you keep it, make sure it does not change the page for people who did not ask for it, and do not describe it as making your store compliant.

## Agent prompt

This store loads an accessibility overlay widget (for example accessiBe, UserWay, AudioEye, EqualWeb or Max Access). Do not remove it without the owner's approval. Instead: 1) Find where it is loaded (theme files, tag manager, an app or plugin) and report that to the owner. 2) Run an automated accessibility checker (axe, Lighthouse or WAVE) on the home page, a category page and a product page with the overlay script blocked, so the results reflect the real templates. 3) Fix the barriers found in the source: page language, titles, alt text, form labels, accessible names for links and buttons, zoom in the viewport tag, heading order, colour contrast and visible focus. Prefer native HTML elements over ARIA. 4) List what still needs manual testing with a keyboard and a screen reader. 5) Check the accessibility statement and any marketing text for claims such as "fully compliant thanks to" the overlay, and flag them for the owner to remove or have reviewed by a lawyer. 6) Prepare, but do not apply, a change that removes the overlay script, so the owner can decide once the fixes are live.
