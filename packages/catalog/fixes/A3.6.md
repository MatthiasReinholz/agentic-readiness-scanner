## Summary

Answer requests for URLs that do not exist with HTTP 404 (or 410), not with a 200 page or a redirect to the home page, so agents can tell a missing page from content.

## Agent prompt

A scan requested a URL on this site that cannot exist and did not get HTTP 404 or 410 back. It got a 200 page (a soft 404), a redirect, or another status. Make the site return HTTP 404 (or 410 for removed pages) for unknown URLs. Find the handler, front controller, redirect plugin, CDN or hosting rule that currently answers 200 with an HTML page or redirects to the home page, and correct it. Keep the friendly not-found page, but send it with the 404 status. Keep specific redirects for URLs that really moved. Verify with `curl -s -o /dev/null -w '%{http_code}' https://<host>/this-page-does-not-exist-7f3a9`: the output must be 404 or 410.

## On WordPress

Turn off any "redirect all 404s to the home page" option in a redirect plugin, and check that the theme's `404.php` keeps the 404 status.
