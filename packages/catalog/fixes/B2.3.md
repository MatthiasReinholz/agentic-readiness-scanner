## Summary

Expose variable products as a ProductGroup whose hasVariant lists each variation with its own sku, identifiers and offer.

## Snippet

```json
{
  "@context": "https://schema.org",
  "@type": "ProductGroup",
  "name": "Stoneware Mug",
  "productGroupID": "MUG-350",
  "variesBy": ["https://schema.org/color"],
  "hasVariant": [
    {
      "@type": "Product",
      "sku": "MUG-350-BLU",
      "color": "Blue",
      "offers": {
        "@type": "Offer",
        "price": "24.00",
        "priceCurrency": "EUR",
        "availability": "https://schema.org/InStock"
      }
    }
  ]
}
```

## Agent prompt

Sampled products on this site are sold in variants (sizes, colours), but their markup does not expose the variants, or the variants lack a unique sku or gtin, or the ProductGroup lacks name or productGroupID. For every product with variants, output a schema.org ProductGroup with name, productGroupID (the parent's stable ID, such as the parent SKU), variesBy and a hasVariant array with one Product per variant, each with its own unique sku, gtin where available, the varying attribute values and its own Offer. Alternatively, give each variant its own page whose Product links to the group with isVariantOf. Generate the markup from the catalog data so new variants appear without manual edits, and give every variant its own SKU in the product admin. Verify a variable product URL in Google's Rich Results Test and check in the Schema Markup Validator that each variant has its own sku and Offer.

## On WooCommerce

WooCommerce core describes a variable product as one Product. Filter its JSON-LD (woocommerce_structured_data_product) and build hasVariant from the product's variations.
