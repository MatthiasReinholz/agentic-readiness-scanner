## Summary

Informational, nothing to fix. This check records whether a Luma-based theme, a Hyvä theme or a headless front end serves the Adobe Commerce store, and which theme it is. None of these is better for agents by itself; what counts is the HTML each serves, which the other checks score.

## Agent prompt

No change is needed: this check is informational and never fails. It records how the Adobe Commerce (Magento) storefront is built, as listed in the evidence: a theme on the Luma and Blank stack (RequireJS and x-magento-init scripts), a Hyvä theme, or a headless front end, with the theme's Vendor/theme path. Use it to know where a fix from another check belongs. In a Luma-based or Hyvä theme, markup, structured data and meta tags live in the theme's layout XML and .phtml templates under app/design/frontend/<Vendor>/<theme>, which override the parent theme's files; never edit the default Luma or Blank files, which upgrades overwrite. In a headless front end (PWA Studio, a Next.js or Nuxt storefront), the front-end application renders every page, so fixes go into its code. Only if the recorded theme is wrong, check that the home page still loads assets from /static/frontend/<Vendor>/<theme>/, and rescan.
