## Summary

Switch on Ecwid's clean URLs in the store's integration code and add the server rewrite rules Ecwid documents, so every product and category gets a real URL instead of a `/#!/` address. On Instant Site, WordPress and Wix this is automatic.

## Snippet

```html
<script>
  window.ec = window.ec || {};
  window.ec.config = window.ec.config || {};
  window.ec.config.storefrontUrls = window.ec.config.storefrontUrls || {};
  window.ec.config.storefrontUrls.cleanUrls = true;
  window.ec.config.storefrontUrls.slugsWithoutIds = true;
</script>
```

## Agent prompt

This site embeds an Ecwid store whose product and category pages use hashbang URLs (for example /store/#!/product-name/p/123456). The part after #! never reaches the server, so crawlers and agents cannot fetch a single product page. Follow Ecwid's guide "Enable clean store URLs on a custom website": add window.ec.config.storefrontUrls.cleanUrls = true and window.ec.config.storefrontUrls.slugsWithoutIds = true in a script that runs before the Ecwid script, and add the server rewrite rules the guide gives for the web server in use, so every URL under the store page returns that page. Keep the store on one page path. Test a product URL directly in a private window: it must load the product. Then update the sitemap and internal links to the clean URLs. If the site is on WordPress or Wix, use Ecwid's plugin for that platform instead, which provides clean URLs and static page copies automatically.
