## Summary

Put shipping details and a return policy in the structured data: once for the store on the Organization node, or on each Offer, generated from the shipping settings and the return policy.

## Snippet

```json
"shippingDetails": {
  "@type": "OfferShippingDetails",
  "shippingRate": { "@type": "MonetaryAmount", "value": "4.90", "currency": "EUR" },
  "shippingDestination": { "@type": "DefinedRegion", "addressCountry": "DE" },
  "deliveryTime": { "@type": "ShippingDeliveryTime", "transitTime": { "@type": "QuantitativeValue", "minValue": 1, "maxValue": 3, "unitCode": "DAY" } }
},
"hasMerchantReturnPolicy": {
  "@type": "MerchantReturnPolicy",
  "applicableCountry": "DE",
  "returnPolicyCategory": "https://schema.org/MerchantReturnFiniteReturnWindow",
  "merchantReturnDays": 30,
  "returnMethod": "https://schema.org/ReturnByMail",
  "returnFees": "https://schema.org/FreeReturn"
}
```

## Agent prompt

The Product JSON-LD on sampled product pages of this store lacks shipping details or a return policy, or a policy lacks a field Google requires. Add both, generated from the store's shipping zones and rates and its return policy so they match the policy pages. For terms that are the same for every product, add hasShippingService (a ShippingService with shippingConditions) and hasMerchantReturnPolicy to the Organization or OnlineStore JSON-LD on the home page. For products whose terms differ, add shippingDetails (OfferShippingDetails with shippingDestination.addressCountry, shippingRate and deliveryTime) and hasMerchantReturnPolicy to their Offer. A MerchantReturnPolicy needs merchantReturnLink, or applicableCountry plus returnPolicyCategory, plus merchantReturnDays for a finite return window. Use ISO 3166-1 two-letter country codes. Verify a product URL and the home page in Google's Rich Results Test under Merchant listings.
