## Summary

Keep Adobe Commerce's GraphQL endpoint open for read-only catalog queries over GET: remove firewall, CDN or robots.txt rules that block /graphql for anonymous clients, and let the full-page cache serve the GET answers.

## Agent prompt

This Adobe Commerce / Magento store does not answer an anonymous catalog query on /graphql. Adobe documents that queries may be sent with GET and that GET answers for products and categories are cacheable, so read access is safe to allow. Check, in order: CDN and WAF rules (Fastly, Cloudflare, Akamai) that block or challenge /graphql for non-browser clients; nginx or Varnish configuration that denies GET on /graphql; robots.txt rules under Content > Design > Configuration > Search Engine Robots that disallow /graphql; and extensions that disable GraphQL modules (Magento_GraphQl, Magento_CatalogGraphQl). Allow GET requests for queries, keep rate limiting for abusive clients, and leave mutations protected. Do not enable anonymous REST access for this; it is a different, broader switch. Verify with: curl -s 'https://<domain>/graphql?query=%7Bproducts(search:%22a%22,pageSize:1)%7Bitems%7Bname%20sku%7D%7D%7D' returning JSON with data.products.items.
