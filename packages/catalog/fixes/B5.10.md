## Summary

Publish only public keys in the UCP profile, each with a unique kid and the members UCP requires. If a private key was ever published, treat it as compromised: create a new key pair, publish the new public key and remove the old one.

## Agent prompt

The UCP profile at /.well-known/ucp of this store publishes signing keys that agents and platforms cannot use safely. Find where the profile is generated (a plugin, an app, middleware or a static file). If any key carries private members (d, p, q, dp, dq, qi, oth or k) or is a symmetric oct key, the private key is exposed: generate a new key pair (ES256 on P-256 is the baseline every verifier supports), keep the private key in a secret store the server reads, publish only the public JWK (kid, kty, crv, x and, for EC keys, y), remove the exposed key from keys, and check logs and history to find how it leaked. Give every key a unique kid, because verifiers look keys up by it. Serve the array as the top-level keys of the profile (releases before 2026-08-25 called it signing_keys). Verify by fetching /.well-known/ucp and confirming that no key contains d or k and every key has kid, kty, crv and x.
