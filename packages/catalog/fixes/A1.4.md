## Summary

Send Link response headers on the home page and product pages that point agents at the machine-readable resources the site has: llms.txt, a Markdown copy, an API catalog, an RSL licence or the UCP profile.

## Snippet

```http
Link: </llms.txt>; rel="llms-txt"; type="text/markdown", </.well-known/api-catalog>; rel="api-catalog"
```

## Agent prompt

The scanner found no Link response header with a relation an agent can use on this site's home page or a sampled product page. The relations that count are ucp, api-catalog, service-desc, describedby, llms-txt, license with type application/rsl+xml, and alternate with type text/markdown. List the agent-facing resources the site already serves, then add a Link response header (RFC 8288) for each of them to the home page and product pages, for example `</llms.txt>; rel="llms-txt"; type="text/markdown"`, `</.well-known/api-catalog>; rel="api-catalog"` or `</.well-known/ucp>; rel="ucp"`. Add the header in server, CDN or application middleware so it is sent next to existing Link headers, not instead of them. Do not advertise resources that do not exist. Verify with `curl -sS -D - -o /dev/null <url> | grep -i '^link:'` on the home page and on a product page, and open each linked URL to confirm it answers HTTP 200.

## On WordPress

Add the header from a small plugin with the send_headers action, passing false as the second argument of header() so the REST API Link header stays. Check that the page cache keeps custom headers.
