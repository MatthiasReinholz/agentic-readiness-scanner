## Summary

Keep every usage-preference signal you declare syntactically valid: Content-Signal and Content-Usage lines inside a robots.txt group, an RSL License line with an absolute https URL, and a TDM reservation file as a JSON array. Declaring none is fine.

## Snippet

```robots
User-agent: *
Content-Signal: search=yes, ai-input=yes, ai-train=no
Allow: /
```

## Agent prompt

At least one AI usage-preference signal this site declares is malformed. Check each place a signal can live and fix the malformed ones, each in its own vocabulary. Content-Signal lines in robots.txt use `ai-train`, `search` and `ai-input` set to `yes` or `no` (for example `Content-Signal: ai-train=no, search=yes, ai-input=yes`) and sit inside a User-agent group. Content-Usage lines in robots.txt and the Content-Usage response header use the IETF vocabulary `train-ai`, `ai-use` and `search` set to `y` or `n`. An RSL `License:` line in robots.txt carries an absolute https URL of an RSL XML document. /.well-known/tdmrep.json is a JSON array of objects, each with a `location` and a `tdm-reservation` of 0 or 1, and tdm-reservation headers or meta tags carry 0 or 1. Do not translate one vocabulary into another. Verify by fetching /robots.txt, the home page headers (`curl -sI`) and /.well-known/tdmrep.json and comparing each value with these rules.

## On WordPress

Add robots.txt lines in the SEO plugin's robots.txt editor, and response headers through a send_headers hook in a small plugin or a server rule.
