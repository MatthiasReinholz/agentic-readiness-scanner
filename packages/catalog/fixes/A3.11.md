## Summary

Start every page with `<!doctype html>`, declare the character encoding first, and keep the head free of anything but title, meta, link, script, style, base, noscript and template, so crawlers read the title, canonical and robots directives. Never redirect with a meta refresh.

## Snippet

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>Stoneware Mug 350 ml | Berlin Ceramics</title>
    <link rel="canonical" href="https://example.com/product/stoneware-mug/" />
    <meta name="description" content="Hand-thrown stoneware mug, dishwasher safe, 350 ml." />
    <!-- scripts, styles and other metadata follow. No iframe, img or div in the head -->
  </head>
</html>
```

## Agent prompt

A scan found pages of this store where the title, canonical, robots or hreflang metadata sits after an element that does not belong in the head (or in the body), a meta refresh redirect, a missing doctype or charset, or a content type other than text/html. Audit the page templates. Make `<!doctype html>` the first bytes of every page and `<meta charset="utf-8">` the first element in the head (or send charset in the Content-Type header). Move any element that is not title, meta, link, script, style, base, noscript or template out of the head. Tag managers and consent tools that inject an iframe, img or div into the head are the usual cause, and they must inject into the body instead. Place the title, rel=canonical, robots meta, description and hreflang links before any script that could inject such an element. Replace any meta refresh redirect with an HTTP 301. Verify by fetching a product page with curl and reading the raw head, not the browser's element inspector.
