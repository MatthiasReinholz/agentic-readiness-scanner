## Summary

Allow crawlers to fetch the site's own JavaScript and CSS: remove robots.txt Disallow rules that cover script and stylesheet paths, or add Allow rules for them.

## Snippet

```text
User-agent: *
Allow: /assets/*.js
Allow: /assets/*.css
Disallow: /admin/
```

## Agent prompt

This site's robots.txt disallows some of the same-origin scripts or stylesheets that its product pages load, for Googlebot or for Bingbot. Open robots.txt and find the Disallow rules that match the site's script or stylesheet URLs (typical culprits: `Disallow: /assets/`, `/static/`, `/*.js$`, `/*.css$`). Either delete those rules or add explicit Allow rules for the asset paths (for example `Allow: /assets/*.js`, `Allow: /assets/*.css`). Under RFC 9309 the longest matching rule wins, whatever the order. Googlebot, Bingbot and Applebot need these files to render the page. Verify by evaluating one script URL and one stylesheet URL from a product page against the new robots.txt for Googlebot.

## On WordPress

The usual culprits are `Disallow: /wp-includes/` and `/wp-content/plugins/`. Allow `/wp-includes/js/` and the plugin scripts and stylesheets (`Allow: /wp-content/plugins/*.js`, `Allow: /wp-content/plugins/*.css`) and keep `/wp-admin/` disallowed.
