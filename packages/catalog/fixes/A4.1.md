## Summary

If the site runs an MCP server for outside agents, publish a server card at `<endpoint>/server-card` and list it in `/.well-known/ai-catalog.json`, the two routes the MCP Server Card extension describes. Link the endpoint from llms.txt as well.

## Snippet

```json
{
  "identifier": "urn:air:example.com:shop",
  "type": "application/mcp-server-card+json",
  "url": "https://example.com/mcp/server-card"
}
```

## Agent prompt

A scan found an MCP server card for this site only at a community path (`/.well-known/mcp/server-card` or `.json`), or a card URL that answers 200 without a card that names the server and its endpoint. Only act if the site operates an MCP (Model Context Protocol) server that outside agents may use. Publish a server card (name, version, description and `remotes` with the Streamable HTTP endpoint URL) at `<endpoint>/server-card`, served as `application/mcp-server-card+json` with `Access-Control-Allow-Origin: *` and a public cache lifetime. Add an entry of type `application/mcp-server-card+json` that points at it to `/.well-known/ai-catalog.json`, and link the endpoint from llms.txt. Do not publish a card for a server that does not exist. Verify with `curl -s https://<host>/.well-known/ai-catalog.json` and `curl -s <endpoint>/server-card`: the card must be JSON with a name and the endpoint URL.
