## Summary

Regenerate the public product feed at least once a day and send a Last-Modified header that says when it was last rebuilt.

## Agent prompt

The public product feed of this store is older than a day, or the scanner could not tell its age: the response has no Last-Modified header and the feed carries no date it reads (lastBuildDate or pubDate in RSS, updated in Atom, a top-level updated_at, generated_at, last_updated or updated in JSON). Schedule regeneration at least once a day, hourly if stock changes often, from a real scheduler, not from a request. Write the file atomically so its modification time marks a complete build, set Last-Modified to the build time (never to the request time), and set lastBuildDate in an RSS channel. Exclude the feed from page caching or purge it after each build. Verify with `curl -sI <feed-url>`: Last-Modified must be less than 24 hours before the Date header.

## On WordPress

Feed plugins usually run on WP-Cron, which fires only when someone visits the site. On a quiet store, run wp-cron.php from a server cron job instead.
