## Summary

If you publish llms.txt, make it a plain-text Markdown file with an H1 naming the site, a short blockquote summary and link lists. If you do not publish one, nothing is lost: no major assistant documents reading it, so let /llms.txt answer 404.

## Snippet

```markdown
# Example Shop

> Independent retailer of hand-made ceramics, shipping to the EU and UK.

## Catalog

- [Product feed](https://example.com/feed/products.xml): Google-format XML, refreshed hourly
- [Product sitemap](https://example.com/product-sitemap.xml)

## Policies

- [Shipping](https://example.com/shipping/)
- [Returns](https://example.com/returns/)
```

## Agent prompt

This site answers /llms.txt with something that is not a usable llms.txt file: a status other than 200, 404 or 410, an HTML page (often a soft 404 or a challenge page), a file without a level-one heading, or a file without links. If the owner does not want an llms.txt, make /llms.txt answer HTTP 404. Otherwise serve it as text (text/markdown or text/plain, never HTML) with a first line `# <site name>`, a one-paragraph blockquote summary and H2 sections (for a store: catalog, policies, APIs) with Markdown links, each written as link text in square brackets followed by the URL in round brackets. Link only public pages that exist. Verify with `curl -sS -D - https://<domain>/llms.txt`: status 200, a content type other than text/html and a body whose first line is the `#` heading with the site name.

## On WordPress

Upload llms.txt as a static file to the web root, or use a plugin that generates it, and exclude it from page caching and minification.
