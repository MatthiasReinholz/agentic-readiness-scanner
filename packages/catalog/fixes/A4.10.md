## Summary

If you want personal agents to work with your store through the Personal Agent Protocol (Poppy), publish `/.well-known/poppy.json` on your own domain, with `organization.domain` set to that exact host and at least one of `agent`, `apis` or `web`. If the domain has an OAuth issuer, make its metadata list the domain, or personal agents will not use the document.

## Snippet

```json
{
  "protocol_version": "0.4",
  "organization": { "name": "Example Store", "domain": "example.com" },
  "web": {},
  "apis": [
    {
      "type": "mcp",
      "url": "https://example.com/mcp",
      "description": "Product search, stock and order status"
    }
  ]
}
```

## Agent prompt

The scan read `/.well-known/poppy.json` on this site, the discovery document of the Personal Agent Protocol (Poppy, draft 0.4), and found problems a personal agent checks before it uses the document; the evidence lists them. Only act if the store owner wants personal agents to use Poppy. Fix what the evidence names, following section 3 (Discovery) of the Personal Agent Protocol specification 0.4 (personalagentprotocol.org/docs/0.4/spec) and its JSON Schema (kit/company/schemas/poppy.schema.json in the protocol's repository). Serve the file at exactly `/.well-known/poppy.json` over HTTPS, as `application/json`; a redirect is allowed only to HTTPS and only to the same path, with no query. Set `organization.domain` to the host that serves the file (for example `example.com` when `www.example.com` redirects there), give `protocol_version` as major.minor, and declare at least one of `agent` (the company agent's conversation endpoints), `apis` (OpenAPI or MCP interfaces, each with a type, an HTTPS url and a description) or `web` (the website; `{}` is enough when agents browse as signed-out visitors). Every URL in the file must be HTTPS. If the domain publishes `/.well-known/oauth-protected-resource`, its `resource` must be exactly `https://{domain}`; with more than one authorization server, set `auth.issuer` to the one personal agents use, and make that issuer's `/.well-known/oauth-authorization-server` metadata list `https://{domain}` in `protected_resources`, with a token endpoint, a revocation endpoint and the `refresh_token` grant. If the store offers personal agents no sign-in, leave out `auth.issuer`, `signed_in` access and the Mediated Sign-In extension. Do not declare endpoints that do not exist. Verify with `curl -s https://<host>/.well-known/poppy.json | jq '.organization, (.agent, .apis, .web)'` and rescan.

## On Shopify

Shopify themes offer no standard way to publish your own files under `/.well-known/`. Shopify exposes stores to agents through UCP and its agentic storefront, which B5.8 covers.
