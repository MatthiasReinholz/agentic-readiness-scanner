## Summary

Let anonymous visitors read the WordPress REST API: allow the wp/v2 read routes in the security plugin that blocks them, rather than switching the API off, and keep write routes protected by authentication as WordPress already does.

## Agent prompt

The WordPress REST API on this site refuses anonymous reads or is not served. Find what blocks it. Security plugins (Wordfence, iThemes/Solid Security, All in One WP Security, Disable REST API, Perfmatters and similar) often have a "disable REST API for visitors" option. A `rest_authentication_errors` filter in the theme or a must-use plugin can return `rest_not_logged_in`. Server or CDN rules can block `/wp-json/`. Change the setting so unauthenticated GET requests to public read routes (wp/v2/pages, wp/v2/posts, wp/v2/media and, on a store, wc/store/v1) succeed. If the goal was to stop user enumeration, block only wp/v2/users for visitors. Do not expose private content or write routes, which WordPress already protects with authentication. If `/wp-json/` answers 404, save Settings > Permalinks once and check the server rewrite rules. `?rest_route=/` is the fallback. Verify with an anonymous request that `GET /wp-json/wp/v2/pages?per_page=1` returns 200 and a JSON array.
