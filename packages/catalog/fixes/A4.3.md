## Summary

If the MCP server needs authorization, publish OAuth 2.0 protected resource metadata (RFC 9728) for its path, answer unauthenticated requests with 401 and a WWW-Authenticate header naming it, and point it at an authorization server with RFC 8414 metadata.

## Snippet

```json
{
  "resource": "https://example.com/mcp",
  "authorization_servers": ["https://auth.example.com"],
  "scopes_supported": ["catalog:read"]
}
```

## Agent prompt

For the MCP endpoint of this site, publish /.well-known/oauth-protected-resource/<endpoint path> (and the root form) with a resource field and an authorization_servers list, return 401 with `WWW-Authenticate: Bearer resource_metadata="<that URL>"` on unauthenticated requests, and make sure the authorization server serves /.well-known/oauth-authorization-server. Follow the MCP authorization specification's discovery order.
