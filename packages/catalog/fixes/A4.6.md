## Summary

Informational. If you want browser agents to use the site's forms as tools, declare them with WebMCP: `toolname` and `tooldescription` on the form (both are required) and `toolparamdescription` on its fields, or `document.modelContext.registerTool` in script. Do not turn the API off with `Permissions-Policy: tools=()` on pages that declare tools. The API is an origin trial, so nothing is lost by waiting.

## Agent prompt

Act only if the owner wants to experiment with WebMCP, the draft browser API that lets a page declare its actions as tools for agents in the browser. The scan reported WebMCP declarations on this site, a form with `toolname` but no `tooldescription`, or a `Permissions-Policy: tools=()` header on a page that declares tools. Annotate the key forms (search, add to cart, contact) with a `toolname`, a `tooldescription` (the browser registers no tool without both) and per-field `toolparamdescription` attributes, as Chrome's declarative WebMCP documentation describes, or register the same actions with `document.modelContext.registerTool` behind a feature check. Make sure no Permissions-Policy header on those pages contains `tools=()`. Test with the WebMCP flag in Chrome or the site tools menu of the ChatGPT desktop browser. Leave production behaviour unchanged for browsers without the API. Verify with `curl -s <URL> | grep -oE 'tool(name|description)="[^"]*"'`.
