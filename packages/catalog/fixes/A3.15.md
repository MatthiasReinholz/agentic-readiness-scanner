## Summary

Informational, nothing to fix. This check records whether a block theme, a classic theme or a headless front end renders the WordPress site, which theme it is and which page builder it uses. None of these is better for agents by itself; what counts is the HTML each one serves, which the other checks score.

## Agent prompt

No change is needed: this check is informational and never fails. It records how the WordPress site is built (block theme, classic theme or headless front end, the theme and child theme, and any page builder), as listed in the evidence. Use it to know where a fix from another check belongs. In a block theme, templates and template parts are edited in the Site Editor (Appearance > Editor) or in the theme's templates/ and parts/ folders. In a classic theme, the PHP templates of the theme or, better, of a child theme carry the markup, and functions.php the hooks. In a page builder, the builder's own templates usually render headers, product pages and footers. In a headless front end, the front-end application renders every page, so fixes to markup, structured data and headers go there, not into WordPress. Only if the recorded theme is wrong, check that the home page still carries the wp-theme- body class (WordPress 6.8 and later) or loads assets from /wp-content/themes/, and rescan.
