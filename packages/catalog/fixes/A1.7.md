## Summary

Give every sitemap entry a lastmod that shows when the page's content last changed, not when the sitemap was generated. Crawlers use it to decide what to refetch, and they ignore it once every entry shows the same timestamp.

## Snippet

```xml
<url>
  <loc>https://example.com/product/stoneware-mug/</loc>
  <lastmod>2026-10-28T09:14:00+00:00</lastmod>
</url>
```

## Agent prompt

The scanner read this site's sitemaps and found that too few entries carry a valid <lastmod> (under 80 percent, or none), or that every entry carries the same value, which is a timestamp written at generation time. Make the product and page sitemaps emit <lastmod> for each URL from the content's real modification time, in W3C datetime format (`2026-10-28` or `2026-10-28T09:14:00+00:00`, always with a timezone when a time is given). Update that time when visible content changes (title, description, price, availability, images), not on deploys or cache purges. Verify by fetching the product sitemap: a product edited today must show today's date, an untouched product must keep its older date, and the values must differ from one another.

## On WordPress

Prefer an SEO plugin's sitemap or the wp_sitemaps_posts_entry filter, which can take lastmod from each post's modified date. Check that product imports and stock syncs update that date.
