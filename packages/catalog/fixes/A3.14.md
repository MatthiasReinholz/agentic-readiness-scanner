## Summary

Give every control in the product form a name a screen reader would announce: visible text on the add-to-cart button (or an aria-label when it shows only an icon) and a label element for the quantity field and every option select.

## Snippet

```html
<form action="/cart/add" method="post">
  <label for="size">Size</label>
  <select id="size" name="size">
    <option>Small</option>
    <option>Large</option>
  </select>
  <label for="quantity">Quantity</label>
  <input id="quantity" name="quantity" type="number" value="1" min="1" />
  <button type="submit" aria-label="Add to cart">
    <svg aria-hidden="true"><!-- cart icon --></svg>
  </button>
</form>
```

## Agent prompt

On this store's product pages, the add-to-cart form has controls without an accessible name, so browser agents that read the accessibility tree (OpenAI documents this for the ChatGPT agent in Atlas) cannot tell what they do. Open the product page template and find the form that contains the add-to-cart button. Make sure the button has visible text such as "Add to cart", or an aria-label when it shows only an icon. Give the quantity input and every option control (size, colour and other variant selects, radio buttons or swatches) a label element linked with for and id, or an aria-label. Mark decorative icons inside buttons with aria-hidden="true". Keep the visible design unchanged. Verify by fetching a product page with curl and confirming that each button, input and select in the form has text, a value, a label or an aria-label in the server HTML.

## On WooCommerce

WooCommerce's default product templates name these controls. An unnamed control usually comes from a theme override in the child theme's woocommerce folder or from a variation swatch plugin, so fix it there.

## On Shopify

The product form lives in the theme's main product section. Icon-only buttons and colour swatches in custom or third-party themes are the usual gaps.
