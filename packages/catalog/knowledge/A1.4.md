## In short

A Link response header is a signpost in the HTTP response itself. It tells any client that reads headers, including AI agents (software that finds, compares or buys on a person's behalf), where related resources live: a commerce profile, an API catalog or a Markdown copy of the page. This check passes when your home page or a product page carries at least one link relation an agent can act on.

## What this check looks at

RFC 8288, Web Linking, defines the `Link` header. One header can carry several links separated by commas. Each link has a target in angle brackets, a `rel` parameter naming the relation, and optional parameters such as `type`:

```http
Link: </.well-known/ucp>; rel="ucp", </.well-known/api-catalog>; rel="api-catalog"
```

The scanner reads the `Link` headers of your home page and of one sampled product page. It parses them per RFC 8288, so extra parameters on a link, such as a `version`, do not hide its relation. It also reads the `<link>` elements in the home page's HTML head for one relation, `ucp`, because Hydrogen storefronts (Shopify's framework for custom storefronts) declare it there instead of in a header.

These relations count:

| Relation                                  | What it points at                                                 |
| ----------------------------------------- | ----------------------------------------------------------------- |
| `ucp`                                     | The store's Universal Commerce Protocol (UCP) business profile    |
| `api-catalog`                             | A list of the site's APIs, defined by RFC 9727                    |
| `service-desc`                            | A machine-readable description of an API, such as an OpenAPI file |
| `describedby`                             | A resource that describes this one                                |
| `llms-txt`                                | The site's llms.txt file                                          |
| `license` with type `application/rsl+xml` | A Really Simple Licensing (RSL) licence for the content           |
| `alternate` with type `text/markdown`     | A Markdown copy of the page                                       |

Any other relation, such as WordPress's REST API link or a `shortlink`, is recorded in the evidence but does not count.

## Why it matters for AI agents

An agent that lands on a page has to work out what else the site offers. Without a signpost it guesses well-known paths, one request each. A Link header answers that question in the response the agent already has, before it parses any HTML.

Today the relation with a documented reader is `ucp`. Shopify's Online Store sends it on every response, so agents built for the Universal Commerce Protocol can find a store's [UCP business profile](/knowledge-base/ucp-business-profile) from any page. The other relations are established conventions without a widely documented consumer yet. That is why the check carries weight 1: it is worth adding when you already have the resources, and it never blocks a level.

Advertise only what exists. A Link header that points at a missing file costs an agent a wasted request and erodes trust in your other signals.

## How the scanner decides

- **Pass:** at least one of the relations in the table above appears in a `Link` header on the home page or the sampled product page, or a link element with `rel="ucp"` appears in the home page's head.
- **Fail:** the pages carry `Link` headers, but none with a relation from the table.
- **Fail:** neither page carries a `Link` header, and the home page has no `ucp` link element.

The scanner does not fetch the link targets here. Whether a UCP profile, an API catalog or a Markdown copy actually works is judged by the checks for those resources, such as the [API catalog check](/knowledge-base/api-catalog) and the [Markdown copy check](/knowledge-base/markdown-copy-of-product-pages).

## How to fix it

First list the agent-facing resources your site already serves. Then add one link per resource, on the home page and on product pages.

### WordPress and WooCommerce

- WordPress already sends a `Link` header pointing at its REST API. That relation does not count, so you need to add your own.
- Add headers from a small plugin or a must-use plugin with the `send_headers` action, not from theme templates:

```php
add_action( 'send_headers', function () {
    header( 'Link: </llms.txt>; rel="llms-txt"; type="text/markdown"', false );
} );
```

- Pass `false` as the second argument so your header is added next to the existing ones instead of replacing them.
- If a page cache serves stored responses, check that it keeps custom headers, or add the header at the web server or CDN instead.

### Shopify

- Shopify's Online Store sends a `Link` header with `rel="ucp"` on storefront responses, so most Online Store themes pass without changes. Confirm it with the command below.
- Hydrogen storefronts declare the same relation as a link element in the document head. The scanner accepts that form on the home page.
- You do not need other relations to pass. If you serve further resources, such as a Markdown copy, link them as well.

### Any other stack

- Add the header in your application's response middleware, your web server configuration or a CDN rule. Nginx's `add_header` and an edge function both work.
- Send it on the home page and product pages at least. Sending it on every HTML response is simpler and harmless.
- Combine several links in one header, separated by commas, or send several `Link` headers. RFC 8288 treats both the same.
- Use the exact relation names from the table. A typo such as `rel="api_catalog"` is a different relation.

## Verify it yourself

Print only the `Link` headers of a page:

```bash
curl -sS -D - -o /dev/null https://example.com/ | grep -i '^link:'
curl -sS -D - -o /dev/null https://example.com/products/example | grep -i '^link:'
```

Replace the second URL with one of your product pages. Look for one of the relations in the table, and open each target URL to confirm it exists.

## Common mistakes

- **Counting the default WordPress header.** The REST API link and the shortlink are not agent resources in the sense of this check.
- **Advertising resources that do not exist.** A `rel="api-catalog"` pointing at a 404 is worse than no link at all.
- **Missing the type parameter.** `rel="alternate"` alone usually means a translation. It counts here only with `type="text/markdown"`, and `rel="license"` only with `type="application/rsl+xml"`.
- **A cache stripping the header.** Some page caches store the body but not custom headers. Test the cached response, not just the first one.

## FAQ

### What is an HTTP Link header?

It is a response header, defined by RFC 8288, that lists related resources with a relation type, for example `</.well-known/ucp>; rel="ucp"`. It works like a link element in HTML, but any client can read it without parsing the page.

### Do AI agents read Link headers?

Some do. Agents built for the Universal Commerce Protocol use the `ucp` relation that Shopify sends. Other relations are conventions with no widely documented reader yet, which is why this check is weight 1.

### Should I put a link to llms.txt in a Link header?

You can, and the scanner counts the `llms-txt` relation. It helps only if your llms.txt exists and is useful. See the [llms.txt check](/knowledge-base/llms-txt-valid).

### Can I use a link element in HTML instead of a header?

For the `ucp` relation on the home page, yes. The scanner accepts both. For the other relations it reads the response headers only, so use a header there.
