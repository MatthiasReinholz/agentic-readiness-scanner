## In short

This check records how a BigCommerce store's storefront is built: a Stencil theme, which BigCommerce renders from Handlebars templates, or a headless storefront such as Catalyst, BigCommerce's storefront framework built on Next.js. The result is informational and never scored. It tells you where the fixes from the other checks belong.

## What this check looks at

The check reads the home page the scan already fetched. It makes no extra request.

| Trace                                                              | What it shows                                                      |
| ------------------------------------------------------------------ | ------------------------------------------------------------------ |
| a `stencilBootstrap` script                                        | a Stencil theme. Every Stencil theme starts its scripts through it |
| Next.js's own markers, such as `self.__next_f` or `/_next/static/` | a headless storefront on the stack of Catalyst                     |
| another framework's markers, such as `/_nuxt/`                     | a headless storefront built with that framework                    |

BigCommerce serves product images from paths like `/images/stencil/500x659/` on its CDN, whatever the storefront. Headless storefronts load the same images, so the check does not count that path as a sign of a Stencil theme.

## Why it matters for AI agents

Agents read the HTML a store serves. Stencil themes render on BigCommerce's servers, so their pages arrive complete. Catalyst renders on the server too. Other headless front ends may render in the browser, and then an agent that does not run JavaScript sees an empty page. [Server-rendered content](/knowledge-base/server-rendered-product-content) checks that, whatever the storefront.

The build also decides where a fix goes:

- In a Stencil theme, structured data, titles and links live in the theme's Handlebars templates.
- In Catalyst or another headless storefront, the front-end application renders every page, so fixes go into its code.

## How the scanner decides

This check runs only when the scan recognised BigCommerce (see [platform detection](/knowledge-base/ecommerce-platform-detection)). It has weight `info`: it is reported, never scored, and gates no level.

1. A `stencilBootstrap` script means a Stencil theme. A Stencil theme written from scratch need not call it, and then the check records no fact rather than guess.
2. Otherwise, Next.js markers mean a headless storefront such as Catalyst. Catalyst is the common case, but any Next.js front end looks the same, so the fact says "such as Catalyst".
3. Otherwise, another recognised framework means a headless storefront built with it.

It always passes when it runs. The fact appears at the top of the report next to the platform, for example "Storefront: Stencil theme". When none of the traces is there, no fact is recorded.

## How to fix it

There is nothing to fix. If you want to change the storefront, these are the usual paths.

### BigCommerce

- **Changing Stencil themes.** Try the new theme as a draft first, and compare product pages for prices, structured data and links before publishing it.
- **Moving to Catalyst.** Catalyst renders on the server, so product content reaches agents. Check structured data, the sitemap and robots.txt after the move, because the Stencil theme no longer provides them.

## Verify it yourself

Look for the Stencil script and Next.js markers:

```bash
curl -s https://example.com/ | grep -oE 'stencilBootstrap|self\.__next_f|/_next/static/' | sort | uniq -c
```

In the BigCommerce control panel, Storefront > Themes shows the active Stencil theme. A headless storefront is listed under Channel Manager as its own channel.

## Common mistakes

- **Reading `/stencil/` in image URLs as a Stencil theme.** BigCommerce's image CDN uses that path for every storefront.
- **Assuming headless means invisible to agents.** Catalyst renders on the server and serves complete pages.
- **Forgetting the sitemap and robots.txt after going headless.** The front end has to serve them.

## FAQ

### How do I know if a BigCommerce store uses a Stencil theme?

Its home page calls `stencilBootstrap` in a script, as Cornerstone and the themes built on it do. In the control panel, Storefront > Themes shows the active Stencil theme either way.

### How do I know if a BigCommerce store runs Catalyst?

Catalyst is built on Next.js, so the page shows Next.js markers such as `/_next/static/` while its images come from BigCommerce's CDN. Another Next.js front end looks the same, so the scanner says "such as Catalyst".

### Is Catalyst better for AI agents than a Stencil theme?

Not by itself. Both render pages on the server. What agents need is complete HTML with prices, structured data and working links.
