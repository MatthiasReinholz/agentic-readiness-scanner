## In short

This check records which e-commerce platform serves the store: WooCommerce, Shopify, WordPress without WooCommerce, or none the scanner knows. It reads fingerprints from the home page only. The result is informational and never scored, but it decides which platform-specific checks run, such as the WooCommerce Store API checks.

## What this check looks at

The scanner looks at the HTML of the home page and tests for platform fingerprints in a fixed order. The first match wins.

| Platform    | Fingerprints the scanner looks for                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WooCommerce | a `woocommerce` class on the body, a generator meta tag that mentions WooCommerce, WooCommerce block markup (`wc-block`), or a reference to `/wp-json/wc/` in the page |
| Shopify     | a generator meta tag that mentions Shopify, assets loaded from `cdn.shopify.com`, or the `Shopify.theme` object in the page                                            |
| WordPress   | a generator meta tag that mentions WordPress, a link with `rel="https://api.w.org/"` (the WordPress REST API), or paths under `/wp-content/`                           |

When nothing matches, the platform is recorded as unknown. The evidence in the report lists the platform, the generator tag and any body classes that mention WooCommerce or Shopify, so you can see what the decision rested on.

## Why it matters for AI agents

Agents read stores through whatever the platform exposes. A WooCommerce store has a public Store API at `/wp-json/wc/store/v1`. A Shopify store has its own public product endpoints. A store on a custom stack has neither, and an agent has to rely on product pages, structured data and feeds.

The scanner works the same way. Knowing the platform lets it test the interfaces that actually exist, and skip the ones that cannot. A Shopify store is not marked down for lacking a WooCommerce endpoint, and the reverse.

The platform also selects a scan profile. Profiles decide which checks apply and how high a store can score, so that a blog on WordPress is not judged against commerce criteria it never claimed.

## How the scanner decides

This check always passes when it runs. Its message names the result: "WooCommerce detected", "Shopify detected", "WordPress detected without WooCommerce", or "no known platform detected". It carries no weight and is never part of the score or of any level gate.

What follows from the result:

- **WooCommerce** turns on the checks that require it, starting with [Store API reachable](/knowledge-base/store-api-reachable), then [Store API rate limits](/knowledge-base/store-api-rate-limits) and [Store API product completeness](/knowledge-base/store-api-product-completeness).
- **Shopify** turns on the Shopify-specific checks, such as [Shopify products.json](/knowledge-base/shopify-products-json).
- **WordPress or unknown** runs the platform-neutral checks only. Platform-bound checks are reported as not applicable, with a message saying which platform they require.

When the home page refuses the scanner, for example with a firewall challenge, the platform cannot be read. It is recorded as unknown and most checks are not evaluated. The [honest fetch check](/knowledge-base/no-block-on-honest-fetch) explains that case.

Detection only reads fingerprints. It never decides whether a store is trustworthy, and a fingerprint can be wrong.

## How to fix it

There is nothing to fix. This check has no failing state. If the detected platform is wrong, the cause is usually one of the cases below.

### WordPress and WooCommerce

- If a WooCommerce store is detected as plain WordPress, the home page probably carries no WooCommerce fingerprint. That happens when the home page is a landing page built without shop blocks and the theme removes the `woocommerce` body class.
- Some security and performance plugins remove the generator meta tag. That is fine, as long as another fingerprint remains.
- A WooCommerce store detected as WordPress loses the Store API checks. Its catalog can still be judged through the sitemap and product pages.

### Shopify

- A Shopify store normally loads assets from `cdn.shopify.com`, so detection is reliable.
- A headless storefront built on Shopify but served from your own frontend may load no Shopify assets on the home page. It is then detected as unknown, and the Shopify-specific checks do not run.

### Any other stack

- Stores on other platforms are recorded as unknown. That is not a penalty. Every platform-neutral check, including sitemaps, structured data, feeds and policies, still runs.

## Verify it yourself

Look for the same fingerprints the scanner uses:

```bash
curl -s https://example.com/ | grep -ioE 'name="generator"[^>]*|woocommerce|wc-block|/wp-json/wc/|cdn\.shopify\.com|shopify\.theme|/wp-content/' | sort | uniq -c
```

A WooCommerce store usually shows several WooCommerce matches. A Shopify store shows `cdn.shopify.com`. A WordPress site without a shop shows only `/wp-content/` or a WordPress generator.

## Common mistakes

- **Expecting a score for the platform.** No platform scores higher than another. This check only routes the scan.
- **Hiding all fingerprints for security.** Removing the generator tag hides a version number. It does not hide the platform from anyone who looks at asset paths, and it can cost you the platform-specific checks.
- **Scanning a landing page.** If the scanned URL is a marketing site on another system and the shop lives elsewhere, the scanner detects the landing page's platform. Scan the shop's own origin.

## FAQ

### How do I tell if a website uses WooCommerce?

Look at the home page source for a `woocommerce` class on the body, WooCommerce block markup, or references to `/wp-json/wc/`. You can also request `/wp-json/wc/store/v1/products` and see whether it returns a JSON list of products.

### How do I tell if a store runs on Shopify?

Shopify storefronts load scripts, styles and images from `cdn.shopify.com`, and most carry a Shopify generator tag. A headless storefront may show neither.

### Does the detected platform change my score?

Not directly. The check itself is never scored. But the platform decides which checks apply, so the set of checks behind the score differs between WooCommerce, Shopify and other stacks.

### My WooCommerce store was detected as WordPress. What now?

Make sure the home page shows at least one WooCommerce fingerprint, for example a shop block or the default body classes. Otherwise the Store API checks are skipped, and the catalog is judged through your sitemap, product pages and feeds instead.
