## In short

This check records which platform serves the store, for example WooCommerce, Shopify or Adobe Commerce. The scanner recognises 13 platforms from fingerprints on the home page. The result is informational and never scored, but it decides the profile of the scan and which platform-specific checks run.

## What this check looks at

A platform is the software that runs the site: a shop system such as WooCommerce or Shopware, or a site builder such as Wix or Webflow. Each one leaves traces in the home page: a generator tag (a meta tag that names the software), typical file paths, asset hosts (the servers that deliver scripts and images) or response headers.

The scanner reads the home page once and tests these fingerprints in a fixed order. The first platform with a match wins. Shop systems come before the site builders that can host them, so an Ecwid shop embedded in a WordPress site counts as Ecwid, and WooCommerce (a shop plugin for WordPress) comes before WordPress.

| Platform                  | Fingerprints the scanner looks for                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| WooCommerce               | a `woocommerce` class on the body, a WooCommerce generator tag, WooCommerce block markup (`wc-block`), or a reference to `/wp-json/wc/`  |
| Shopify                   | a Shopify generator tag, assets from `cdn.shopify.com`, or the `Shopify.theme` script                                                    |
| BigCommerce               | an `X-BC-Store-Id` header, assets from a BigCommerce asset host such as `cdn11.bigcommerce.com`, or the Stencil bootstrap script         |
| Adobe Commerce (Magento)  | a `text/x-magento-init` script, a Magento theme asset path under `/static/frontend/`, or an `X-Magento-` header                          |
| Shopware                  | assets under `/bundles/storefront/`, an `sw-language-id` or `sw-currency-id` header, or a Shopware generator tag                         |
| PrestaShop                | the `var prestashop =` script object, a PrestaShop generator tag, or a `Powered-By: PrestaShop` header                                   |
| Salesforce Commerce Cloud | paths under `/on/demandware.static/` or `/on/demandware.store/`, or assets from a `demandware.net` or `demandware.edgesuite.net` host    |
| Square Online             | a Square Online generator tag, or assets from `editmysite.com`                                                                           |
| Ecwid                     | an Ecwid Instant Site generator tag (`ec-instant-site`), the `app.ecwid.com/script.js` storefront script, or assets from `app.ecwid.com` |
| Wix                       | an `X-Wix-Request-Id` header, the generator `Wix.com Website Builder`, or assets from `static.parastorage.com` or `static.wixstatic.com` |
| Squarespace               | a `Server` header that names Squarespace, the `This is Squarespace.` comment in the page, or the `SQUARESPACE_CONTEXT` script            |
| Webflow                   | a `data-wf-site` attribute on the `html` element, or a Webflow generator tag                                                             |
| WordPress                 | a WordPress generator tag, a link with `rel="https://api.w.org/"` (the WordPress REST API), or paths under `/wp-content/`                |

No vendor documents these traces as fingerprints. Each was seen on live stores, and the scanner matches them loosely enough to survive theme changes. When nothing matches, the platform is unknown.

## Why it matters for AI agents

Agents read a store through whatever the platform offers. A WooCommerce store has a public Store API (a built-in interface that returns products as data) at `/wp-json/wc/store/v1`. A Shopify store has its own public product endpoints and an agent catalog. An Adobe Commerce store answers catalog queries on `/graphql`. A store on a custom stack has none of these, and an agent relies on product pages, structured data and feeds.

The scanner works the same way. Knowing the platform lets it test the interfaces that exist and leave out the ones that cannot. A Shopify store is not marked down for lacking a WooCommerce endpoint, and the reverse.

## How the scanner decides

This check always passes when it runs. Its message names the result, for example "Shopify detected", "WordPress detected without WooCommerce" or "no known platform detected". It has weight `info`: it is reported, never scored, and gates no level. The evidence shows the platform, the fingerprint that matched and the generator tag.

The platform changes the scan in three ways.

- **Profile.** A profile decides which checks apply. WooCommerce gets the `woocommerce-store` profile. Shopify, BigCommerce, Adobe Commerce, Shopware, PrestaShop, Salesforce Commerce Cloud, Square Online and Ecwid only run shops, so they get `other-store`. WordPress, Wix, Squarespace, Webflow and unknown sites get `other-store` when the home page shows signs of a shop (a cart link, product markup or product pages), and `content-site` otherwise. A content site gets only the ingestion checks, so this check does not run there either.
- **Platform checks.** Some checks read an interface or a setting only one platform has. They run only on that platform. On any other platform they do not run, reports leave them out, and the JSON result lists them as not applicable.
- **Fix notes.** A fix can carry advice for one platform. A report adds it only when the scan recognised that platform.

These are the platform checks:

- **WordPress** (and WooCommerce, which runs on it): [search engine visibility](/knowledge-base/wordpress-search-engine-visibility) and [REST API readable](/knowledge-base/wordpress-rest-api-readable).
- **WooCommerce:** [Store API reachable](/knowledge-base/store-api-reachable), [Store API rate limits](/knowledge-base/store-api-rate-limits), [Store API product completeness](/knowledge-base/store-api-product-completeness), [sitemap matches Store API](/knowledge-base/sitemap-matches-store-api) and [guest checkout and cart API](/knowledge-base/guest-checkout-and-cart-api).
- **Shopify:** [products.json](/knowledge-base/shopify-products-json) and [agentic storefront](/knowledge-base/shopify-agentic-storefront).
- **Adobe Commerce:** [catalog over GraphQL](/knowledge-base/adobe-commerce-graphql-catalog).
- **BigCommerce:** [Storefront MCP](/knowledge-base/bigcommerce-storefront-mcp), where MCP (Model Context Protocol) is a standard way for AI agents to call a service.
- **Shopware:** [agentic files](/knowledge-base/shopware-agentic-files).
- **PrestaShop:** [friendly URLs](/knowledge-base/prestashop-friendly-urls).
- **Salesforce Commerce Cloud:** [robots.txt not on the staging preset](/knowledge-base/salesforce-robots-txt-staging-preset).
- **Square Online:** [search visibility](/knowledge-base/square-online-search-visibility).
- **Ecwid:** [clean store URLs](/knowledge-base/ecwid-clean-store-urls).
- **Wix:** [site MCP server](/knowledge-base/wix-site-mcp-server).
- **Squarespace:** [AI crawler setting](/knowledge-base/squarespace-ai-crawler-setting).
- **Webflow:** [traffic control](/knowledge-base/webflow-traffic-control).

When the home page refuses the scanner, for example with a firewall challenge, there is nothing to read. The platform stays unknown and this check is not evaluated. The [honest fetch check](/knowledge-base/no-block-on-honest-fetch) explains that case.

## How to fix it

There is nothing to fix. This check has no failing state. If the detected platform is wrong, the cause is usually one of these.

### WordPress and WooCommerce

- A WooCommerce store detected as plain WordPress shows no WooCommerce trace on its home page. That happens when the home page is a landing page without shop blocks and the theme removes the `woocommerce` body class. It then loses the Store API checks, and its catalog is judged through the sitemap and product pages.
- Security and performance plugins often remove the generator tag. That is fine as long as another fingerprint remains.

### Shopify

- A Shopify store loads assets from `cdn.shopify.com`, so detection is reliable.
- A headless storefront (your own front end that reads Shopify data) is still recognised as Shopify when it loads Shopify assets. Shopify does not serve products.json or the agent catalog on that domain, so those two checks are reported as not applicable. A headless front end that loads no Shopify assets is unknown.

### Any other stack

- A headless front end on any platform often hides the platform's traces, so it is detected as unknown. The same goes for platforms outside the list above.
- Unknown is not a penalty. Every platform-neutral check, including sitemaps, structured data, feeds and policies, still runs.

## Verify it yourself

Look for the generator tag and a few common traces:

```bash
curl -s https://example.com/ | grep -ioE 'name="generator"[^>]*|woocommerce|/wp-json/wc/|cdn\.shopify\.com|x-magento-init|/bundles/storefront/|demandware|app\.ecwid\.com|/wp-content/' | sort | uniq -c
```

Some platforms announce themselves in headers instead:

```bash
curl -sI https://example.com/ | grep -iE '^(server|powered-by|x-bc-store-id|x-wix-request-id|x-magento|sw-)'
```

## Common mistakes

- **Expecting a score for the platform.** No platform scores higher than another. This check only routes the scan.
- **Hiding all fingerprints for security.** Removing the generator tag hides a version number, not the platform, and it can cost you the platform checks.
- **Scanning a landing page.** If the scanned site runs on one system and the shop lives elsewhere, the scanner detects the landing page's platform. Scan the shop's own address.

## FAQ

### Which platforms does the scanner recognise?

13: WordPress, WooCommerce, Shopify, BigCommerce, Wix, Adobe Commerce (Magento), Squarespace, Square Online, PrestaShop, Salesforce Commerce Cloud, Shopware, Ecwid and Webflow. Any other platform is recorded as unknown.

### How do I tell if a website uses WooCommerce?

Look in the home page source for a `woocommerce` class on the body, WooCommerce block markup or references to `/wp-json/wc/`. You can also request `/wp-json/wc/store/v1/products` and see whether it returns a JSON list of products.

### Does the detected platform change my score?

Not directly. This check is never scored. But the platform decides which checks apply, so the set of checks behind the score differs from platform to platform.

### My store was detected as the wrong platform. What now?

Make sure the home page shows the platform's own traces, such as its default body classes, scripts or generator tag. If it shows the traces of another system that hosts or embeds the shop, the first match in the order above wins.
