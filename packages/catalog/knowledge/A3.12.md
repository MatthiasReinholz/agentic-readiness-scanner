## In short

PrestaShop can build product URLs as query strings (parameters after a `?`), such as `index.php?id_product=27&controller=product`, or as readable paths, such as `/2-music-players/27-ipod-nano-green`. The Friendly URL option decides which. This check warns when any sampled product URL is a query string, because a readable path tells people, search engines and agents what the page is before they open it.

## What this check looks at

The Friendly URL option sits in the SEO & URLs settings, under Shop Parameters, Traffic & SEO, in the PrestaShop back office. PrestaShop documents the two forms:

| Friendly URL | Example product URL                          |
| ------------ | -------------------------------------------- |
| Off          | `index.php?id_product=27&controller=product` |
| On           | `/2-music-players/27-ipod-nano-green`        |

PrestaShop warns that you should switch the option on only if your server supports URL rewriting. Otherwise the shop may become unavailable. Its documentation asks you to test the change.

The check looks at the product URLs the scan sampled. It does not fetch anything new.

## Why it matters for AI agents

An agent can judge a link by its URL before it fetches the page, for example when it reads a sitemap or a category page. `/27-ipod-nano-green` says what the product is. `index.php?id_product=27` says nothing until the page is fetched and read.

Google's URL structure guidance recommends simple, descriptive URLs with readable words rather than long ID numbers. Query-string URLs also invite duplicates: the same product can appear under several parameter orders and combinations, which makes it harder to tell which URL is the main one.

Friendly URLs do not make a product page better on their own. They make it easier to identify and to cite.

## How the scanner decides

This check runs only on PrestaShop stores, when the scan recognised the platform (see [platform detection](/knowledge-base/ecommerce-platform-detection)). On other platforms it does not run and reports leave it out. It makes no extra request.

A URL counts as a query string when it has an `id_product` or `controller` parameter, or when its path is `index.php`.

- **Pass:** every sampled product URL is a readable path.
- **Warn:** at least one sampled product URL is a query string. The message gives the count and an example, and says that Friendly URL is off.
- **Not applicable:** no product pages were found to sample.

The evidence lists all sampled URLs and the query-string ones among them. The weight is 1, which means nice to have. It gates no level.

## How to fix it

Confirm that the server supports URL rewriting, switch the option on, and test the shop.

### PrestaShop

1. Ask your host, or check the server, whether URL rewriting is available. On Apache this is the mod_rewrite module.
2. In the back office, open Shop Parameters, Traffic & SEO.
3. In the SEO & URLs settings, set Friendly URL to Yes and save.
4. Open a product, a category and the cart in a private window. If pages fail to load, switch the option back off and fix the server configuration first.
5. If you use "Generate robots.txt" on the same page afterwards, keep a copy of your current robots.txt. Generating the file replaces any existing one, so add your custom rules back.
6. Resubmit your sitemap so search engines pick up the new URLs.

Make sure old query-string URLs redirect to the new paths or carry a canonical link to them. See [canonical and hreflang](/knowledge-base/canonical-and-hreflang).

## Verify it yourself

Look at the product links on your home page or in your sitemap:

```bash
curl -s https://example.com/ | grep -oE 'href="[^"]*id_product=[^"]*"' | head
curl -s https://example.com/robots.txt | grep -i '^sitemap'
```

The first command prints product links that are still query strings. No output is a good sign. The second shows where your sitemap is, so you can open it and check its product URLs the same way. Rescan to confirm.

## Common mistakes

- **Switching the option on without URL rewriting.** PrestaShop warns that the shop may become unavailable. Test right after saving.
- **Losing robots.txt rules.** "Generate robots.txt" replaces the existing file. Keep a copy of custom rules.
- **Leaving old links unredirected.** External links and old sitemaps still point to the query-string URLs. Redirect them or add canonical links.
- **Hard-coding query-string links in the theme or in content.** Menus, banners and blog posts written with `index.php?id_product=` links keep the old form after the switch.

## FAQ

### Where is the Friendly URL setting in PrestaShop?

In the back office under Shop Parameters, Traffic & SEO, in the SEO & URLs settings. Set Friendly URL to Yes and save.

### Can turning on friendly URLs break my PrestaShop store?

Yes, if the server does not support URL rewriting. PrestaShop warns that the shop may become unavailable in that case. Test the shop right after the change, and switch the option back off if pages fail to load.

### Do friendly URLs help with AI agents?

They help an agent tell what a page is before it fetches it, and they reduce duplicate URLs for the same product. They do not change what the page itself contains.

### Why does the scanner only warn instead of fail?

Query-string URLs still work. Agents and search engines can read the pages. Readable paths are an improvement, not a requirement, so the check warns and is weighted as nice to have.
