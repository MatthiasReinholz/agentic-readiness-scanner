## In short

llms.txt is an optional Markdown file at the root of a site that summarises it for language models and links to its most useful pages. No major assistant documents reading it, and Google states that Search does not use it, so the scanner never scores its absence. If you do publish one, it must be real text that starts with a heading, not an HTML page.

## What this check looks at

The llms.txt proposal at llmstxt.org describes a file served at `/llms.txt`. It is written in Markdown and has a simple structure:

1. A level-one heading (H1) with the name of the site. This is the only required element.
2. An optional blockquote with a short summary.
3. Optional paragraphs with more detail.
4. Optional sections with level-two headings (H2), each a list of links with a short note.

A store might have sections for its catalog, its policies and its APIs. The idea is that an agent asked about the site can read one short file and know where to go next.

The scanner requests `/llms.txt` on the store's origin, checks the status and the body, and parses the heading, the sections and the links.

## Why it matters for AI agents

Be clear about what this file does today. Google's guidance on AI features states that Search does not use llms.txt. None of the other major assistants documents reading it during crawling or answering. Some coding agents and developer tools read it when a user points them at a site. Chrome's Lighthouse includes an llms.txt audit.

So publishing llms.txt is optional, and leaving it out costs nothing in this scanner. The check carries weight 1, and a missing file is skipped as not applicable rather than failed.

What does cost something is a broken file. A request for `/llms.txt` that returns your home page with status 200, or an HTML error page, tells a tool that reads the file something false. If you have the file, it should work.

## How the scanner decides

- **Skip:** `/llms.txt` answers 404 or 410. The file is optional, so its absence is not scored.
- **Fail:** the response has any other status than 200, such as a 403 or a 500.
- **Fail:** the body is HTML, recognised by a doctype or an `html` tag in its first 500 characters. That is usually a soft 404 or a challenge page.
- **Fail:** the body contains no level-one heading, that is no line starting with a single `#` followed by a space. The first such line is read as the site name.
- **Warn:** the file has an H1 but no Markdown links.
- **Pass:** the file has an H1 and at least one Markdown link.

The scanner is stricter than Lighthouse on the format, because it rejects HTML served at the path. It is more lenient on content: Lighthouse fails a file with no Markdown link or under 50 characters, while this check only warns about a missing link.

## How to fix it

Decide first whether you want the file. If you do not, make sure `/llms.txt` answers 404 rather than your home page. If you do, keep it short and factual, and link to data an agent can use. The [catalog links check](/knowledge-base/llms-txt-links-to-catalog) looks at those links.

### WordPress and WooCommerce

- Upload a static `llms.txt` file to the web root, or use a plugin that generates one. Some SEO plugins offer this.
- A WordPress site answers unknown paths with a 404 page, which is correct. If `/llms.txt` returns status 200 with HTML, a redirect or caching rule is rewriting it.
- After adding the file, exclude it from page caching and minification, which can wrap or alter plain text files.

### Shopify

- Shopify may generate an llms.txt for a store. Fetch `/llms.txt` on your domain to see whether one exists and what it contains.
- If your store serves a file you did not write, review it like any other public page. Check that it names your store in the first line and links to working pages.

### Any other stack

- Serve the file at `/llms.txt` as static text with status 200 and `Content-Type: text/markdown` or `text/plain`.
- Make sure your router's catch-all does not answer `/llms.txt` with the app shell.
- Start with `# Store name`, add a one-line summary as a blockquote, then H2 sections with link lists.
- Use absolute URLs in links, and only link pages that exist.

## Verify it yourself

Check the status, the content type and the first lines:

```bash
curl -sS -D - -o /dev/null https://example.com/llms.txt
curl -sS https://example.com/llms.txt | head -n 15
```

The status should be 200 (or 404 if you do not publish one) and the content type should not be `text/html`. The first non-empty line should start with a single `#` and a space, as the proposal intends. Lighthouse in Chrome DevTools runs its own llms.txt audit if you want a second opinion.

## Common mistakes

- **A soft 404.** A storefront that answers every unknown path with status 200 makes it look as if you publish an llms.txt that is really your home page.
- **No H1.** A file made only of level-two sections or plain links misses the one element the proposal requires. Put `# Store name` on the first line.
- **Copying the sitemap.** A list of hundreds of URLs defeats the purpose. Link to sections, feeds and APIs instead.
- **Expecting it to change search rankings.** Google states that Search does not use it. Treat it as a convenience for tools that read it, not as an SEO lever.

## FAQ

### Do ChatGPT, Gemini or Claude read llms.txt?

None of them documents reading llms.txt when crawling or answering. Google states that its Search does not use it. Some developer tools and coding agents read it when a user asks them to, which is the main audience today.

### Will I lose points if my store has no llms.txt?

No. The scanner skips this check when the file answers 404 or 410, and nothing else in the score depends on it.

### What should an ecommerce llms.txt contain?

A heading with the store name, a one-sentence summary, and short link lists for the catalog (product feed, product sitemap, store API), the policies (shipping, returns, privacy) and any agent endpoints. Keep it to what an agent would use.

### Does llms.txt replace robots.txt or a sitemap?

No. robots.txt sets crawl permissions and a sitemap lists your URLs for crawlers. llms.txt is an optional summary for tools that choose to read it.
