## In short

The Agent2Agent (A2A) protocol lets one AI agent talk to another. A store that runs its own agent, such as a shopping assistant, can describe it in an agent card at `/.well-known/agent-card.json`. This check looks for that card and the eight fields A2A 1.0 requires. No shopping agent documents reading agent cards from stores, so the check carries weight 1, nice to have.

## What this check looks at

A2A is an open protocol, specified at a2a-protocol.org, with 1.0 as its current release. Where MCP connects an agent to tools, A2A connects an agent to another agent. A client agent can hand a task to a remote agent, exchange messages with it and receive results.

The agent card is how a remote agent introduces itself. A2A 1.0 places it at `/.well-known/agent-card.json` and requires eight fields:

| Field                 | What it says                                                  |
| --------------------- | ------------------------------------------------------------- |
| `name`                | The agent's name                                              |
| `description`         | What it does, for humans and models                           |
| `supportedInterfaces` | Where to reach it: URL, protocol binding and protocol version |
| `version`             | The version of the agent itself                               |
| `capabilities`        | Optional features such as streaming or push notifications     |
| `defaultInputModes`   | Media types it accepts, such as `text/plain`                  |
| `defaultOutputModes`  | Media types it returns                                        |
| `skills`              | What it can do, each with an id, name, description and tags   |

A minimal card for a store assistant could look like this:

```json
{
  "name": "Example Shop assistant",
  "description": "Answers product and order questions for Example Shop",
  "supportedInterfaces": [
    { "url": "https://example.com/a2a", "protocolBinding": "JSONRPC", "protocolVersion": "1.0" }
  ],
  "version": "1.2.0",
  "capabilities": { "streaming": false },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    {
      "id": "product-advice",
      "name": "Product advice",
      "description": "Recommends products from the catalog",
      "tags": ["shopping"]
    }
  ]
}
```

Versions before 0.3 used `/.well-known/agent.json` and a single `url` field instead of `supportedInterfaces`.

## Why it matters for AI agents

If a store runs an agent that outside agents may call, the card is the standard way to announce it. A client agent reads the card, picks an interface and knows which skills to ask for.

Most stores have no such agent. Their catalog, policies and checkout are reached through pages, feeds and commerce protocols such as UCP, which the [UCP profile check](/knowledge-base/ucp-business-profile) covers. No shopping agent documents fetching agent cards from merchant sites. That is why this check has weight 1 and gates no level. Do not publish a card for an agent you do not run.

## How the scanner decides

The scanner requests `/.well-known/agent-card.json` first.

- **Pass:** it answers 200 with a JSON object that has all eight required fields.
- **Warn:** it answers 200 with a JSON object that lacks some of the fields. The report names the missing ones.
- **Fail:** it answers 200 but the body is not a JSON object.

When the first URL does not answer 200, the scanner tries the pre-0.3 path `/.well-known/agent.json`. That path is also used by other agent-discovery drafts, so JSON there counts as an A2A card only when it has `name`, `description`, `url` or `supportedInterfaces`, `version`, `capabilities` and `skills`.

- **Warn:** an A2A card was found only at the old path.
- **Fail:** the old path holds JSON in another vocabulary, or neither path holds a card.

The evidence lists which path answered, the fields present and the fields missing.

## How to fix it

Only act if your store runs an agent that speaks A2A. If it does not, leave this check failing.

### WordPress and WooCommerce

- If a plugin provides an A2A agent, check whether it serves `/.well-known/agent-card.json`. Many early implementations still serve only `/.well-known/agent.json`.
- To serve the card yourself, place a static JSON file in the web root under `.well-known/`. Make sure security plugins do not block the `.well-known` folder.

### Shopify

- Shopify themes offer no standard way to publish your own files under `/.well-known/`. Shopify exposes stores to agents through UCP and its MCP endpoint, which the [agentic storefront check](/knowledge-base/shopify-agentic-storefront) covers. Nothing to do here.

### Any other stack

- Serve the card from the same service that runs the agent, so the interfaces and skills stay current.
- Fill all eight required fields. `defaultInputModes`, `defaultOutputModes` and `supportedInterfaces` are the ones most often missing in cards written for older versions.
- Remove the old `/.well-known/agent.json` copy once the new card is live, or keep both identical until your clients have moved.
- Describe authentication in the card's security fields if the agent needs it. Do not put secrets in the card.

## Verify it yourself

Fetch the card and list its top-level fields:

```bash
curl -s https://example.com/.well-known/agent-card.json | jq 'keys'
```

The output should include all eight required fields. If the command returns a 404 page, try the old path `/.well-known/agent.json` and plan the move.

## Common mistakes

- **Only the old path.** A card at `/.well-known/agent.json` alone warns, because A2A moved the card in version 0.3.
- **A card copied from 0.2 examples.** A single `url` and no `supportedInterfaces` leaves the card short of the 1.0 fields.
- **Skills without tags.** A2A 1.0 requires `id`, `name`, `description` and `tags` on each skill. The scanner does not check skill entries, but clients may reject the card.
- **Publishing a card as a marketing signal.** A card for an agent that does not answer misleads every client that reads it.

## FAQ

### What is the difference between A2A and MCP?

MCP connects an AI application to tools and data on a server. A2A connects one agent to another agent that does its own reasoning. A store usually needs neither to be found by AI assistants.

### Where does the A2A agent card go?

At `/.well-known/agent-card.json` on the agent's domain. Versions before 0.3 used `/.well-known/agent.json`, which this check accepts with a warning.

### Does an agent card help my products appear in ChatGPT or Gemini?

No assistant documents reading store agent cards. Product visibility depends on crawlable pages, structured data and feeds.

### Which fields does an A2A 1.0 agent card require?

Eight: `name`, `description`, `supportedInterfaces`, `version`, `capabilities`, `defaultInputModes`, `defaultOutputModes` and `skills`.
