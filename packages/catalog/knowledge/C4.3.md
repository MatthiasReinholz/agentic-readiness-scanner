## In short

An accessibility overlay is a third-party script that adds a toolbar or tries to repair a site's accessibility in the browser. It does not make a site conformant: the US Federal Trade Commission, the European Disability Forum and many accessibility professionals have said so, and stores using overlays are still sued. This check reports when the home page loads a known overlay, so you can review it. It is a technical signal, never scored, and not legal advice.

## What this check looks at

The scanner looks at the scripts in the static HTML of the home page and matches them against known overlay vendors, such as accessiBe, UserWay, AudioEye, EqualWeb and Max Access. Overlays usually do two things: show a widget where visitors can change font size, contrast or spacing, and run automated "remediation" that rewrites the page in the browser.

There is no law that asks for or against an overlay. The laws this check relates to are the ones that ask for an accessible store, and an overlay is not a way to meet them:

- **European Union:** the European Accessibility Act (EAA), Directive (EU) 2019/882, applies to e-commerce services for consumers since 28 June 2025. The European Disability Forum and the International Association of Accessibility Professionals said in a [joint statement in 2023](https://www.edf-feph.org/accessibility-overlays-dont-guarantee-compliance-with-european-legislation/) that overlays do not ensure compliance with European legislation.
- **United States:** the Americans with Disabilities Act (ADA), Title III, covers public accommodations, and courts have applied it to websites. In April 2025 the FTC [finalised an order](https://www.ftc.gov/news-events/news/press-releases/2025/04/ftc-approves-final-order-requiring-accessibe-pay-1-million) requiring accessiBe to pay USD 1 million and barring it from claiming that its automated product can make any website compliant with the Web Content Accessibility Guidelines (WCAG) unless it has evidence. Lawsuit trackers such as UsableNet reported suits in every month of 2025 against US sites that had an overlay installed.

The report lists every law with a link to its official text.

## Why it matters for AI agents

Browsing agents read the page through its accessibility tree, the names, roles and labels a browser builds from the HTML. OpenAI says the agent in its Atlas browser uses these labels and roles, and the [Playwright MCP](https://github.com/microsoft/playwright-mcp) server that many agents use works from the accessibility tree. An overlay injects a second layer on top of the real page:

- **Repairs happen late, or not at all.** The fixes run in the visitor's browser after load. Agents and tools that read the server HTML, or that block third-party scripts, see the unrepaired page.
- **Guesses become facts.** Automatically generated alt text or labels can be wrong. An agent has no way to tell a guessed label from a real one, so it may act on the wrong button.
- **Extra controls compete for attention.** The widget adds its own buttons, dialogs and focus traps, often first in the page. An agent looking for "Add to cart" first meets "Accessibility menu".
- **Behaviour can change.** Some overlays try to detect assistive technology and switch modes when they do, so an agent may see a different page from the one you tested.

Fixing the source HTML gives every reader, human or agent, the same accurate page.

## How the scanner decides

- **Review:** the static HTML of the home page loads a script from a known overlay vendor. The evidence names the vendor and the script URL.
- **Found (no overlay detected):** no known overlay script is loaded. In this check, "found" means the good outcome: nothing to review.

What it cannot see:

- Overlays added later by a tag manager or another script, or vendors not on the list.
- Whether the overlay is active for every visitor or only after a click.
- Whether the site is accessible with or without it.

Detecting an overlay is not a judgement that the site is inaccessible. It is a prompt to check whether the overlay is being relied on instead of real fixes.

## How to fix it

Fix the barriers in the theme and content first, then decide whether the overlay still serves a purpose. Browser and operating system settings already give users zoom, contrast and text spacing.

### WordPress and WooCommerce

- Overlays are usually installed as a plugin or pasted into the theme header or a tag manager. Find the source under Plugins, in `header.php`, or in your tag manager container.
- Fix the basics covered by the [static accessibility basics check](/knowledge-base/static-accessibility-basics) in the theme: language, titles, alt text, form labels, named buttons and zoom.
- Once the fixes are live, deactivate the overlay plugin or remove the script.

### Shopify

- Overlays are usually Shopify apps. Find them under Settings, Apps and sales channels, or as app embeds under Online Store, Themes, Customize, App embeds.
- Disable the app embed first and test the store. Uninstall the app when you no longer need it.
- Fix barriers in the theme code and in product content, such as image alt text.

### Any other stack

- Search the templates and the tag manager for overlay script URLs and remove them once the source is fixed.
- Test with a keyboard and a screen reader, such as NVDA on Windows or VoiceOver on macOS, as well as automated tools.
- If you keep a preferences widget, make sure it never changes the page unless the visitor chooses so, and do not call it a compliance tool.

## Verify it yourself

Look for known overlay vendors in the HTML of your home page:

```bash
curl -s https://example.com/ | grep -oiE "acsbapp|accessibe|userway|audioeye|equalweb|maxaccess" | sort -u
```

Check your tag manager too, since overlays loaded there do not appear in the HTML. To see your real templates, block the overlay script in the browser's developer tools (Network panel, block request URL) and run an accessibility audit.

## Common mistakes

- **Treating the overlay as the accessibility strategy.** It does not fix the source, and legal claims are judged on the site people actually use.
- **An accessibility statement that credits the overlay.** Saying the site is compliant "thanks to" a widget misinforms users.
- **Removing the overlay without fixing anything.** Fix first, then remove.
- **Assuming automated alt text is accurate.** Product images need descriptions written from product knowledge.

## FAQ

### Does this apply to my store?

The check runs for every store, because the laws it relates to ask for an accessible site, not for or against overlays. In the EU, microenterprises providing services are exempt from the EAA: fewer than 10 persons and an annual turnover or balance sheet total of no more than EUR 2 million. ADA Title III has no size threshold. Whether a law applies to your business is a question for a lawyer.

### Is using an overlay illegal?

No law forbids it. The concern is relying on it: it does not make a site conformant, and claims that it does have been challenged, for example by the FTC.

### Why is "found" the good result here?

The legal checks use one set of words. For this check, found means "no overlay detected", so there is nothing to review.

### Can an overlay make things worse?

It can. Disability groups report overlays interfering with screen readers and other assistive technology, and some detect that assistive technology is in use, which raises privacy concerns.

### What should I do instead?

Fix the source: semantic HTML, alt text, labels, contrast and keyboard access, tested with tools and with disabled users. Publish an [accessibility statement](/knowledge-base/accessibility-statement) that states what you did and what is still open.
