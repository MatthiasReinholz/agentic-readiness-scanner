## In short

Google crawls and indexes with its smartphone crawler only, and it documents the meta viewport tag (a line in the HTML head that tells phones how wide to lay out the page) as the signal that a page is built for phones. This check reads the viewport tag of the sampled product pages and passes when each declares `width=device-width`. It warns when the tag is missing, uses a fixed pixel width or forbids zooming. It has weight 1: nice to have, never blocking.

## What this check looks at

The meta viewport tag looks like this:

```text
meta name="viewport" content="width=device-width, initial-scale=1"
```

In the page, that line is a `meta` element in the head.

Without it, phone browsers lay the page out at a desktop width, often around 980 pixels, and shrink the whole page to fit. Text becomes tiny and buttons are hard to tap.

The scanner reads the tag from the server-rendered HTML of each sampled product page, or of the home page when no product page was sampled. It records three properties for each page: whether `width=device-width` is declared, whether the width is a fixed number, and whether zooming is blocked with `user-scalable=no` or a `maximum-scale` below 1.

## Why it matters for AI agents

Most AI assistants answer from search indexes, and Google's is one of the largest. Google completed its move to mobile-first indexing in 2024. Its Search Central blog states that it crawls with the smartphone crawler, and that a site not accessible on a mobile device is no longer indexable.

The viewport tag does not make a page work on a phone by itself. A responsive layout does that. But Google's own documentation names the tag as the signal, and a page without it is very likely a desktop layout squeezed onto a small screen. That page is a weaker candidate for the index the assistants answer from.

Blocking zoom is a separate concern. It does not stop indexing, but it makes the page harder to use for people who need larger text, which is why the scanner records it.

## How the scanner decides

The rules run in this order, and the first one found sets the message.

- **Warn** when any judged page has no meta viewport tag, or an empty one.
- **Warn** when a page has a viewport tag without `width=device-width`, for example `width=1024`.
- **Warn** when a page forbids zooming with `user-scalable=no` (or `0`) or a `maximum-scale` below 1.
- **Pass** when every judged page declares `width=device-width` and allows zoom.

When product pages were sampled but none could be fetched, the check is skipped. The parser is tolerant: it accepts commas or semicolons as separators and ignores case and spaces. The scanner does not render pages, so it cannot judge whether the mobile layout actually shows the same content as the desktop one. That parity is up to you.

## How to fix it

Add one line to the head of every page template. Then make sure the layout responds to it.

### WordPress and WooCommerce

- Every current WordPress theme, including the default block themes, already outputs the viewport tag. A missing tag usually points to an old or heavily customised theme.
- Add the tag to the theme's `header.php`, or through the theme's head hook in a child theme, so an update does not remove it.
- Some page builders and "disable zoom" options add `user-scalable=no`. Remove that setting.
- After the change, open a product page on a phone and confirm the price and the add-to-cart button are visible without sideways scrolling.

### Shopify

- Shopify themes from the Theme Store include the viewport tag in `layout/theme.liquid`. Open it under Online Store, Themes, Edit code, and check the head.
- If an app or an older custom theme changed the tag, restore `width=device-width, initial-scale=1` and remove any `maximum-scale=1` or `user-scalable=no`.

### Any other stack

- Put the tag in the shared layout file that renders the head of every page.
- Use CSS media queries or a responsive framework so the layout adapts below tablet width.
- Do not set a fixed width in the tag to work around a layout that breaks on small screens. Fix the layout instead.

## Verify it yourself

Read the tag from a product page:

```bash
curl -s https://example.com/product/stoneware-mug/ | grep -io 'name="viewport"[^>]*'
```

You should see `width=device-width` and no `user-scalable=no`. To see the page as a phone does, open it in your browser's developer tools with device emulation, or run Lighthouse on a mobile profile.

## Common mistakes

- **Adding the tag with JavaScript.** It must be in the server-rendered HTML so crawlers see it without running scripts.
- **Disabling zoom to stop layout jumps.** `maximum-scale=1` and `user-scalable=no` hurt accessibility. Fix the layout or the input font size instead.
- **A fixed width.** `width=1200` asks phones to render a desktop page. It defeats the purpose of the tag.
- **A tag on the home page only.** Product pages often use a different template. Check one of each.

## FAQ

### Is the viewport meta tag still needed in 2026?

Yes. Google still lists `viewport` among the meta tags it supports and describes it as the way to tell it a page is mobile friendly. Mobile browsers also still need it to lay out a responsive page at the device width.

### Does user-scalable=no hurt my ranking?

The scanner records it as a warning because it blocks zoom for people who need it. Google does not document it as a ranking factor. It is an accessibility problem first, and fixing it costs nothing.

### My site has a separate mobile domain. Does this check cover it?

The scanner judges the pages it samples on the scanned origin. If phones are redirected to a separate mobile host, the desktop pages it reads may lack the tag. Google recommends a responsive design served from one URL over a separate mobile site.

### Does passing this check mean my store works on phones?

No. It shows that the page declares a mobile viewport. Whether the price, variants and buy button are usable on a small screen depends on the layout, which the scanner does not render.
