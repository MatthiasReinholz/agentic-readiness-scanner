## In short

The Universal Commerce Protocol (UCP) is an open protocol for agents to browse, build carts and check out with merchants. Its entry point is a business profile at `/.well-known/ucp` that lists the services, capabilities and payment handlers a store supports. This check reads that profile. It carries weight 2, expected, and it is one of the two alternatives that gate Level 5.

## What this check looks at

UCP is specified at ucp.dev and developed in an open repository. It defines how an agent platform, such as an AI assistant, and a business negotiate what they can do together. The business publishes a profile. The platform publishes its own profile. Each request carries the platform's profile URL, and both sides keep only the capabilities they share, at the highest version both support.

The business profile is a JSON object with a `ucp` member:

- `version` is the specification release the profile follows, as a date such as `2026-08-25`.
- `services` lists API surfaces, such as `dev.ucp.shopping`, each bound to a transport (`rest`, `mcp`, `a2a` or `embedded`) and an endpoint.
- `capabilities` lists features within a service, such as `dev.ucp.shopping.checkout`, with links to their specification and schema.
- `payment_handlers` lists the payment methods the business accepts through UCP.

A top-level `keys` array holds public keys that platforms use to verify signed requests and webhooks. The 2026-08-25 release renamed it from `signing_keys`.

The specification also sets serving rules. The profile URL must not redirect, and clients must not follow a redirect there. Responses must allow shared caching: `Cache-Control: public` with a `max-age` of at least 60 seconds, and never `private`, `no-store` or `no-cache`.

## Why it matters for AI agents

The profile is where an agent learns that a store speaks UCP at all, and how. Without it, an agent that supports UCP has no standard way to find your checkout or catalog interfaces.

Two documented consumers make this concrete. Shopify serves the profile for every eligible Online Store. Google Merchant Center requires it for agentic checkout, and its guides still target version 2026-04-08. That is why the check carries weight 3, blocking: without a profile, no UCP checkout can be found.

A profile is a statement of capability, not proof that a checkout works. Level 5 in this scanner means the public prerequisites of a checkout protocol are in place. It never means an agent completed a purchase. The [UCP checkout check](/knowledge-base/ucp-checkout-and-payment-handler) looks at whether the profile declares a checkout.

## How the scanner decides

The scanner sends one GET request to `/.well-known/ucp` on the store's origin.

- **Pass:** the answer is 200 JSON with a `ucp` object that has a `version` in `YYYY-MM-DD` form, a `services` object and a `payment_handlers` object. Both objects may be empty. The response arrived without a redirect, with the `application/json` content type and with `Cache-Control: public` and a `max-age` of 60 or more.
- **Warn:** the profile is valid, but it came through a redirect, lacks the required caching, has a content type other than `application/json`, or declares version 2026-08-25 or later while still carrying `signing_keys` instead of `keys`. A wrong content type is this scanner's own heuristic, not a rule from the specification. It often means a page is standing in for the document.
- **Fail:** a 404, any other non-200 status, an HTML page, invalid JSON, or JSON that lacks one of the required parts. The message names the missing part.

When the URL answers with a refusal (such as 401, 403 or 429) or a bot-management challenge, the check fails and says so. The profile may exist, but neither the scanner nor an agent can read it.

A profile alone does not reach Level 5 or lift the commerce score's cap of 60. Both need the profile to declare a checkout and a payment handler, which the [UCP checkout check](/knowledge-base/ucp-checkout-and-payment-handler) reads, and that check runs only after this one passes. A warning means the profile is valid but served in a way the specification forbids; fix it so the checkout check can rely on it.

## How to fix it

Declare only what you have implemented. An empty `services` and `payment_handlers` object is valid and honest for a store that is preparing.

### WordPress and WooCommerce

- WooCommerce does not serve a UCP profile on its own. A UCP extension or a payment provider's integration may add it. Check its settings for the profile URL.
- To publish one yourself, serve a JSON file at `.well-known/ucp` from the web root, or return it from a small plugin. Set `Content-Type: application/json` and `Cache-Control: public, max-age=300` in your web server configuration.
- Exclude the path from redirects added by SEO or HTTPS plugins. A redirect from `http` to `https` is fine for the home page, but agents should request the `https` profile URL directly.

### Shopify

- Shopify serves `/.well-known/ucp` for eligible Online Store storefronts. Do not try to write it by hand.
- If the profile is missing, see the [agentic storefront check](/knowledge-base/shopify-agentic-storefront). The usual causes are a password-protected store, a plan without the channel, or a headless storefront on another host.

### Any other stack

- Serve the profile at exactly `/.well-known/ucp` over HTTPS, with no redirect and with shared caching allowed.
- Make sure your firewall or bot management lets automated clients read it. Google publishes network and firewall requirements for UCP in its Merchant Center guides.
- Publish `keys` rather than `signing_keys` when you declare version 2026-08-25 or later.
- Add a `Link: </.well-known/ucp>; rel="ucp"` header to your pages, as Shopify does, so agents that land on a page can find the profile.

## Verify it yourself

Check status, headers and body in one go:

```bash
curl -si https://example.com/.well-known/ucp | head -20
```

Look for `200`, no `location` header, `content-type: application/json` and `cache-control` with `public` and `max-age`. Then pipe the body through `jq .ucp.version` to confirm the version.

## Common mistakes

- **Redirecting the profile.** A redirect from `example.com` to `www.example.com` breaks the rule. Serve the profile on every host agents might use.
- **`Cache-Control: no-cache` from a default server rule.** Many platforms send it for everything. Override it for this path.
- **A catch-all page at `/.well-known/ucp`.** An HTML page with status 200 fails the check, because it is not a profile.
- **Declaring a checkout you do not run.** Agents will try it. Keep `services` and `payment_handlers` empty until the integration is live.

## FAQ

### What is the Universal Commerce Protocol?

UCP is an open protocol, specified at ucp.dev, that lets AI agents and merchants agree on catalog, cart and checkout interfaces. Merchants announce theirs in a business profile at `/.well-known/ucp`.

### Do I need a UCP profile to appear in AI shopping results?

Not to be found. Discovery still runs on crawlable pages, structured data and feeds. The profile matters when an agent wants to transact with you, and Google Merchant Center requires it for agentic checkout.

### Does Shopify create the UCP profile automatically?

Yes, for eligible Online Store storefronts. A headless storefront served from another host does not get it on its own domain.

### Can the UCP profile be empty?

Yes. A profile with a valid version and empty `services` and `payment_handlers` objects passes this check. It says the store knows UCP but offers nothing through it yet.

### Why does the scanner warn about Cache-Control on my UCP profile?

The UCP specification requires `Cache-Control: public` with a `max-age` of at least 60 seconds on the profile. Without it, the profile does not meet the specification.
