## In short

An agent shopping on someone's behalf usually has no customer account on your store. On WooCommerce it needs two things: a cart endpoint that answers anonymous clients, and a checkout that does not demand a login. This check calls the Store API cart at `/wp-json/wc/store/v1/cart` and reads the checkout page for a login wall. It applies only to WooCommerce and carries weight 2, expected.

## What this check looks at

WooCommerce ships the Store API, a public REST API for storefront actions. It lives under `/wp-json/wc/store/v1` and powers the block-based cart and checkout. Unlike the admin REST API under `/wp-json/wc/v3`, it needs no API key. It identifies the shopper by a session cookie or a cart token instead.

The cart endpoint returns the current cart: items, totals, coupons, shipping rates and more. Other routes under `/cart/` add, update and remove items. A guest session that can read the cart can also build one.

Guest checkout is a separate WooCommerce setting. When it is off, a visitor who reaches the checkout sees a login form instead of the order form. A person can register. An agent usually cannot.

A healthy anonymous cart response includes fields like these, among many others:

```json
{
  "items": [],
  "items_count": 0,
  "totals": {
    "total_items": "0",
    "total_price": "0",
    "currency_code": "EUR"
  }
}
```

## Why it matters for AI agents

The Store API is the most direct way for an agent to act on a WooCommerce store. It returns structured JSON instead of HTML that has to be parsed. A store that blocks it for anonymous clients forces every agent back to scraping and clicking.

A login wall at checkout stops the purchase at the last step. An agent can put products in a cart, but it cannot pay without an account it does not have and should not create on its own.

Passing this check shows that the doors are open. It does not prove that an agent can finish a purchase. Payment steps, fraud checks and the agent platform's own rules still decide that.

## How the scanner decides

The check runs only on stores detected as WooCommerce, and only when the [Store API check](/knowledge/store-api-reachable) passed or warned.

The scanner first sends a GET request to `/wp-json/wc/store/v1/cart`.

- **Fail:** the cart answers 401 or 403 (authentication required), 404 (endpoint not found), any other non-200 status or no response, or a body that is not a JSON object with an `items` array and a `totals` object.

If the cart works, the scanner opens the checkout page. It uses the first link on the home page that points to `/checkout/` on the same origin, or `/checkout/` by default. It then looks for login signals.

- **Warn:** the checkout page shows a login notice or a WooCommerce login form, and no checkout form. That is what WooCommerce shows when guest checkout is disabled.
- **Pass:** the checkout page shows a checkout form, or no login wall. A page that shows a login prompt above a guest checkout form still passes.
- **Pass, with a note:** the checkout page did not answer 200. The cart works, but guest checkout was not verified, and the message says so.

## How to fix it

Both fixes are settings or configuration. Neither needs custom code.

### WordPress and WooCommerce

- Enable guest checkout under WooCommerce, Settings, Accounts and Privacy. Tick the option that allows customers to place orders without an account.
- If the cart answers 401 or 403, look for a plugin that restricts the REST API to logged-in users. Security plugins often offer this. Allow the `wc/store` namespace for anonymous requests while keeping the admin routes protected.
- If the cart answers 404, check that pretty permalinks are on under Settings, Permalinks. The `/wp-json/` routes depend on them. Also check that no plugin disables the REST API entirely.
- Exclude `/wp-json/wc/store/` from page caching and from CDN caching. A cached cart can show one shopper's cart to another.
- If your firewall challenges automated clients on `/wp-json/`, the [honest fetch check](/knowledge/no-block-on-honest-fetch) explains why agents fail there.

### Any other stack

This check applies only to WooCommerce. Other platforms are judged by their own checks, for example the [Shopify agentic storefront check](/knowledge/shopify-agentic-storefront).

## Verify it yourself

Call the cart as an anonymous client:

```bash
curl -si https://example.com/wp-json/wc/store/v1/cart | head -20
```

You should see `200` and a JSON body with `items` and `totals`. Then open your checkout page in a private browser window with an empty account. If you see only a login form, guest checkout is off.

## Common mistakes

- **Blocking the whole REST API for guests.** Security hardening guides often suggest it. It breaks the block checkout for real customers as well as agents.
- **Guest checkout off "to collect accounts".** Every shopper without an account, human or agent, has to stop and register.
- **Caching the cart response.** A cached 200 can look healthy while serving stale or foreign carts.
- **A custom checkout URL.** If the checkout lives at another path and the home page does not link `/checkout/`, the scanner checks the default path and may not find your page. The result then says guest checkout was not verified.

## FAQ

### How do I enable guest checkout in WooCommerce?

Go to WooCommerce, Settings, Accounts and Privacy, and allow customers to place orders without an account. Save, then test the checkout in a private window.

### Is the WooCommerce Store API safe to leave public?

Yes, it is designed for anonymous shoppers. It exposes only what the storefront already shows and the shopper's own cart. The admin API under `/wp-json/wc/v3` is the one that needs authentication.

### Why does the scanner say guest checkout was not verified?

The cart worked, but the checkout page did not answer with status 200. The scanner could not read the page, so it passes on the cart alone and says so.

### Do agents need the Store API if my product pages have structured data?

Structured data helps agents read products. The Store API lets them act: check live prices, build a cart and move toward checkout without parsing HTML.
