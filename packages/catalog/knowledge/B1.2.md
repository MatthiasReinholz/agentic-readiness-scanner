## In short

WooCommerce ships a public Store API that returns products as JSON (structured text that programs read) without any key or login. It is the cleanest way for an agent to read a WooCommerce catalog. This check requests one product from `/wp-json/wc/store/v1/products` and passes when the answer is a JSON list. It runs only on WooCommerce stores, has weight 3 (blocking) and is one way to meet the "readable catalog" gate of Level 2.

## What this check looks at

The WooCommerce Store API is a REST API (an HTTP interface that returns structured data) built into WooCommerce. WooCommerce's documentation describes it as unauthenticated: it needs no API keys or tokens, and it exposes only public store data and the current visitor's own cart. Its base path is `/wp-json/wc/store/v1`.

The products endpoint lists published products with their name, permalink, prices, images, stock status and more. It is separate from the older WooCommerce REST API at `/wp-json/wc/v3`, which needs credentials and is meant for store administration.

The scanner sends one request:

```http
GET /wp-json/wc/store/v1/products?per_page=1
```

It records the status, the content type and the `X-WP-Total` header, which WordPress uses to report the total number of items.

## Why it matters for AI agents

An agent that wants to know what a store sells has three options: crawl product pages and parse their HTML, find a feed, or ask an API. The API is the most reliable. It returns the price as a field, the stock status as a true or false value, and the canonical product URL, with no guessing from layout.

For a WooCommerce store, the Store API is already there. It costs nothing to offer and it reflects the live catalog. When a plugin or firewall blocks it, the store throws away its best machine-readable channel and forces agents back to scraping.

That is why a reachable Store API is one way to show that an agent can list the catalog. Among its gates, Level 2, "Readable catalog", needs one of these: product URLs in the sitemap, this Store API, Shopify's products.json, a public product feed, or Shopify's agentic storefront catalog. Any one of them is enough.

A passing check shows that the catalog can be read. It does not mean an agent can or will buy from the store.

## How the scanner decides

This check runs only when the [platform check](/knowledge-base/ecommerce-platform-detection) recognised WooCommerce. On other platforms it does not run and reports leave it out.

- **Fail** when the endpoint answers 401 or 403. The message says the Store API requires authentication.
- **Fail** when it answers any other status than 200, including 404 (the route is disabled or missing).
- **Fail** when the body is not JSON, or is JSON but not a list of products.
- **Pass** on 200 with a JSON list. The message reports the number of products in the first page and the total from `X-WP-Total`.

An empty list still passes this check, because the API answered correctly. The [product completeness check](/knowledge-base/store-api-product-completeness) then reports that there is nothing to read.

The [rate limit](/knowledge-base/store-api-rate-limits) and product completeness checks depend on this one. When it fails, they are skipped.

## How to fix it

The Store API is public by default. If it fails, something added later is blocking it. Find that layer and make an exception for anonymous read requests to `/wp-json/wc/store/`.

### WordPress and WooCommerce

- **Check the status first.** A 401 or 403 usually comes from a plugin. A 404 usually means the REST API is disabled entirely or the permalink settings are broken. A non-JSON answer is often an HTML login page, a maintenance page or a firewall challenge.
- **Security plugins.** Many offer a setting such as "disable REST API for logged-out users". Turn it off, or add `wc/store` to the plugin's allowed routes.
- **REST API restriction plugins.** Plugins that limit the REST API to logged-in users block the Store API too. Allow the `wc/store/v1` namespace.
- **Permalinks.** Under Settings, Permalinks, a plain permalink structure makes `/wp-json/` unavailable. Choose any other structure and save, which also refreshes the rewrite rules.
- **Custom code.** Search the theme and plugins for `rest_authentication_errors` or `rest_endpoints` filters that remove or protect routes.

### Any other stack in front of WooCommerce

- **WAF and CDN rules.** A web application firewall (WAF, a filter in front of the site) or a CDN (content delivery network) bot rule on `/wp-json/` often returns 403 or a challenge page. Allow GET requests to `/wp-json/wc/store/` and keep write endpoints protected.
- **Host-level protection.** Some managed hosts block the REST API for anonymous traffic. Ask them to allow the Store API routes.
- **Caching layers.** A cache that stores the login redirect for `/wp-json/` serves it to everyone. Purge it after you fix the rule.

## Verify it yourself

Request one product without cookies or credentials:

```bash
curl -s -i 'https://example.com/wp-json/wc/store/v1/products?per_page=1' | head -20
```

You should see `HTTP/2 200`, a `content-type` of `application/json`, an `x-wp-total` header and a body that starts with `[`. Run it from a network outside your office as well, because some firewalls trust known addresses.

## Common mistakes

- **Locking down the whole REST API.** A blanket "disable REST API" setting is common hardening advice, but it removes the Store API along with everything else.
- **Testing while logged in.** A logged-in browser gets through rules that block anonymous agents. Test with curl or a private window.
- **Confusing the two APIs.** The `/wp-json/wc/v3` REST API needs keys and should stay protected. The `/wp-json/wc/store/v1` Store API is designed to be public.
- **A firewall challenge that returns 200.** Some bot protections answer with an HTML page and status 200. The scanner fails that as a non-JSON body.

## FAQ

### Is it safe to leave the WooCommerce Store API public?

WooCommerce designs it to be public. Its documentation says it exposes no sensitive store data and no other customers' information, and that writing customer data requires a nonce token. It shows the same product data your shop pages already show.

### What is the difference between the Store API and the WooCommerce REST API?

The Store API at `/wp-json/wc/store/v1` is for storefronts and needs no credentials. The REST API at `/wp-json/wc/v3` manages the store, including orders and settings, and requires authentication. Only the Store API should be open to anonymous agents.

### Why does the Store API return 404?

Usually because the REST API is disabled, the permalink structure is set to plain, or a plugin removed the route. Check Settings, Permalinks first, then any plugin that restricts the REST API.

### Do I need this if my sitemap already lists products?

No. Level 2 accepts any one of several ways to enumerate the catalog, and a product sitemap is one of them. The Store API is still worth keeping open, because it gives agents prices and stock status as data rather than as page text.
