## In short

RFC 9727 defines a well-known address, `/.well-known/api-catalog`, where a site lists its public APIs in a machine-readable linkset. An agent that knows only your domain could read it to find your store API, product feed or checkout endpoints. No answer engine documents reading it yet, so this is a weight 1 convention, nice to have.

## What this check looks at

RFC 9727 is an IETF standard from 2025. It registers the `api-catalog` well-known URI and a link relation of the same name. The catalog document is a linkset, a JSON format defined in RFC 9264, served as `application/linkset+json`.

A linkset is a list of link contexts. Each context has an `anchor`, the thing being described, and one or more link relations pointing to other resources. RFC 9727 uses the `item` relation for "this API is part of the catalog". Other registered relations such as `service-desc` (a machine-readable description, for example an OpenAPI file) and `service-doc` (human documentation) can describe each API further.

A catalog for a WooCommerce store might list the Store API and its documentation:

```json
{
  "linkset": [
    {
      "anchor": "https://example.com/.well-known/api-catalog",
      "item": [
        { "href": "https://example.com/wp-json/wc/store/v1" },
        { "href": "https://example.com/feeds/products.json" }
      ]
    },
    {
      "anchor": "https://example.com/wp-json/wc/store/v1",
      "service-doc": [
        { "href": "https://developer.woocommerce.com/docs/apis/store-api/", "type": "text/html" }
      ]
    }
  ]
}
```

## Why it matters for AI agents

Agents waste requests guessing where a store keeps its data. A catalog answers that in one fetch. It is also cheap to publish: a static file that rarely changes.

The honest caveat is that no assistant or shopping agent documents fetching `/.well-known/api-catalog` today. Publishing one prepares for tools that adopt the standard. It does not change how any current assistant sees your store. That is why the check carries weight 1 and gates no level.

Do not list endpoints that are private, need a staff login or exist only for your own apps. The catalog is public by definition.

## How the scanner decides

The scanner sends one GET request to `/.well-known/api-catalog` on the store's origin.

- **Pass:** the answer is 200 with a JSON object that carries a `linkset` array, and at least one link context in it has at least one link. The report counts the contexts and the `item` links. It also notes when the content type is not `application/linkset+json`, but that alone does not fail the check.
- **Fail:** any other status, including 404 and 410. Also a 200 that is an HTML page (a soft 404 or a challenge), a body without a `linkset` array, or a linkset with no links at all.
- **Skipped:** the request was rate limited (429), hit a gateway error (502, 503, 504) or got no response. Such an answer says nothing about whether the file exists.

## How to fix it

List only APIs that an outside client may call without special arrangement. For most stores that is the platform's public storefront API and perhaps a product feed.

### WordPress and WooCommerce

- WooCommerce exposes the public Store API at `/wp-json/wc/store/v1`. That is the main entry worth listing. The [Store API check](/knowledge/store-api-reachable) confirms it answers.
- Place a static file at `.well-known/api-catalog` in the web root. Your web server must send it as `application/linkset+json`, because the file has no extension. In nginx, use a `location = /.well-known/api-catalog` block with `default_type`. In Apache, use a `<Files>` rule with `ForceType` in `.htaccess`.
- Exclude the admin REST routes under `/wp-json/wc/v3`. They need authentication and are not for agents.

### Shopify

- Shopify themes offer no standard way to publish your own files under `/.well-known/`. Shopify describes its own storefront interfaces, including the UCP profile, so there is nothing for you to add here.

### Any other stack

- Serve the file from your web server or CDN at exactly `/.well-known/api-catalog`, without a redirect.
- Set `Content-Type: application/linkset+json`. RFC 9727 also defines a profile parameter for the media type; adding it is optional for this check.
- If you already publish OpenAPI descriptions, link them with `service-desc` so an agent can learn the API without reading prose.

## Verify it yourself

Fetch the catalog and check status, content type and body:

```bash
curl -si https://example.com/.well-known/api-catalog
```

The first lines should show `HTTP/2 200` and `content-type: application/linkset+json`. The body should be JSON with a `linkset` array. Pipe it through `jq .linkset` to see the entries.

## Common mistakes

- **Serving the file as `application/octet-stream`.** A file without an extension often gets a generic type. The check still passes on valid JSON, but other clients may refuse it.
- **A catch-all route answering 200 with the home page.** Many themes do this for unknown paths. The scanner treats an HTML answer as a failure.
- **An empty linkset.** `{"linkset": []}` parses but lists nothing, so the check fails.
- **Listing authenticated admin APIs.** They are useless to agents and advertise attack surface.

## FAQ

### What is /.well-known/api-catalog?

It is the address RFC 9727 reserves for a site's API catalog. A client requests it to learn which public APIs the site offers, without scraping documentation.

### Does an API catalog help my store rank in ChatGPT or Google AI answers?

No assistant documents reading it, so it has no known effect on AI answers today. It is a forward-looking convention with low weight in this scanner.

### What is the difference between an API catalog and llms.txt?

llms.txt is a Markdown file for language models that links to readable content. The API catalog is a structured list of machine interfaces. They complement each other, and the [llms.txt check](/knowledge/llms-txt-valid) covers the first.

### Do I need an OpenAPI file to publish an API catalog?

No. A catalog with plain `item` links to your API base URLs passes. Linking an OpenAPI description with `service-desc` makes each entry more useful.
