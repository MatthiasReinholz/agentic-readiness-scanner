## In short

Most AI crawlers and agents read the HTML your server sends and do not run JavaScript. If a product page only fills in its title, price and description in the browser, those clients see an empty page. This check passes when every sampled product page carries a title, a price and a description in the raw HTML, as text or as structured data.

## What this check looks at

The scanner fetches the sampled product pages without running any scripts, exactly as a simple crawler would. For each page that answered successfully, it looks for three things:

| Element     | Counts when the raw HTML has                                                                                  |
| ----------- | ------------------------------------------------------------------------------------------------------------- |
| Title       | a page title, or a product name in Product JSON-LD                                                            |
| Price       | a price in a JSON-LD Offer, a currency next to an amount in the page text, or an element with a `price` class |
| Description | a meta description, a description in Product JSON-LD, or more than 80 words of text                           |

JSON-LD is the script block of structured data, in the schema.org vocabulary, that most store platforms embed in product pages. It is read without running JavaScript, so it counts here.

The check also looks at where a product URL lands. A product URL that redirects to a sign-in, account or password page, or that answers with a password form and no product content, is not a product page.

## Why it matters for AI agents

A modern storefront can be a JavaScript application that sends a nearly empty HTML document, often called an app shell, and builds the page in the browser. Google can render JavaScript, but its own documentation describes rendering as a separate, deferred step and recommends server-side rendering or prerendering. Many other crawlers and most agents that fetch a page on demand do not render at all. To them, an app shell has no product.

A page behind a login is worse. Google Merchant Center's landing page requirements state that a product's landing page must not require registration or sign-in. Shopify's storefront password page, used while a store is being built, also makes a store ineligible for its agentic storefronts. An agent sent to such a page cannot see the product, let alone buy it.

This check carries weight 3, the blocking tier. It is a Level 1 gate: a store that fails it cannot reach any level above 0. Most other product checks, from [Product JSON-LD](/knowledge-base/product-json-ld) to [price and availability markup](/knowledge-base/offer-price-currency-availability), read the same raw HTML.

## How the scanner decides

- **Pass:** every sampled product page that answered carries a title, a price and a description.
- **Warn:** some, but not all, of those pages carry all three.
- **Fail:** none of them carries all three. This is what an empty app shell looks like.
- **Fail:** any sampled product URL lands on a sign-in or password page. A product page that merely links to the account area, or shows a login box in its header next to the product, is still a product page.
- **Skip:** no product page was sampled, or none of the sampled pages could be fetched.

A sampled page that could not be fetched, for example because it answered an error, is named in the report and never scored as empty. The verdict is based on the pages that answered.

The check proves that the content is present. It does not prove the content is correct or complete; checks such as [markup matches the visible page](/knowledge-base/markup-matches-visible-page) look at that.

## How to fix it

### WordPress and WooCommerce

- WooCommerce renders product pages on the server with PHP, so a standard theme passes. Failures usually come from a JavaScript-heavy page builder, a headless front end or a plugin that loads prices with Ajax.
- If prices load through Ajax for caching or currency switching, render a default price in the HTML and let the script update it.
- Remove any site-wide "coming soon", maintenance or members-only mode before you go live. These send product URLs to a login or placeholder page.

### Shopify

- Online Store themes render products with Liquid on the server, so they pass by default.
- If your store still shows the storefront password page, remove it under Online Store, Preferences once you are ready to sell. Until then, every product URL lands on the password page and this check fails.
- Hydrogen and other headless storefronts must render product routes on the server. Hydrogen does this by default; check that custom routes do not fetch product data only in the browser.
- Apps that inject prices or descriptions with JavaScript can leave the raw HTML incomplete. Keep the core product fields in the theme's Liquid.

### Any other stack

- Use server-side rendering or static prerendering for product routes. Frameworks such as Next.js, Nuxt and SvelteKit support both.
- Render at least the product name, the price with currency, the availability and the description into the initial HTML.
- Embed Product JSON-LD in the server response, not with a tag manager that injects it later.
- If product pages require a login, for example for trade customers, publish a public version with list prices for the products you want agents to find.

## Verify it yourself

Fetch a product page without JavaScript and look for a JSON-LD price and the JSON-LD block itself:

```bash
curl -sL https://example.com/products/example | grep -o '"price": *"\{0,1\}[0-9.,]*' | head -n 3
curl -sL https://example.com/products/example | grep -o 'application/ld+json' | wc -l
```

Better still, search for the exact product name and price you see in your browser: `curl -sL URL | grep -c 'Stoneware Mug'`. A count of 0 means a crawler does not see it. Google's URL Inspection tool in Search Console shows both the raw and the rendered HTML.

## Common mistakes

- **Client-side rendering only.** The page looks perfect in a browser and is empty to curl.
- **Price loaded after the page.** A placeholder or spinner where the price should be leaves the price out of the HTML.
- **A forgotten password page.** While the Shopify password page is on, every crawler and agent that follows a product link meets a password form.
- **Bot-specific responses.** Serving crawlers a separate, stripped version is hard to keep in step with what shoppers see. Server-render the same page for everyone.

## FAQ

### Can AI crawlers read JavaScript-rendered content?

Google renders JavaScript as a separate step and recommends server-side rendering. Many other crawlers and most agents fetching pages on demand do not run JavaScript, so content added only by scripts is invisible to them.

### Does a Shopify password page block AI agents?

Yes. While it is on, every product URL answers with the password page instead of the product. This check fails, and Shopify states that a password-protected store is not eligible for its agentic storefronts.

### Does structured data count if the visible text is rendered by JavaScript?

For this check, yes: a product name, price and description in server-rendered JSON-LD count. Shoppers and other checks still expect the same information as visible text, so render both.

### What is an app shell?

It is a minimal HTML document that loads a JavaScript application, which then builds the page in the browser. Without running the script, a client sees little more than an empty container.
