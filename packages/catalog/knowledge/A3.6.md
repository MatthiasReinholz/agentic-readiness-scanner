## In short

When a page does not exist, the server should say so with HTTP status 404 or 410. A store that answers 200 with a "not found" page, called a soft 404, makes a missing product look like content to every agent that follows an old link. This check requests a URL that cannot exist and reports the status it gets back.

## What this check looks at

Every HTTP response starts with a status code. RFC 9110, the HTTP standard, defines 404 Not Found for a resource the server cannot find and 410 Gone for one that was removed on purpose. A friendly error page is fine, as long as it is sent with one of those codes.

The scanner sends a single GET request to a random path under your origin, of the form `/agentic-readiness-probe-` followed by a short code derived from the host name. The path is the same on every scan of a host, so results are repeatable. No real store has a page there.

It then looks at three things in the answer: the status code, the final URL after any redirects, and the content type.

## Why it matters for AI agents

Agents follow links from many sources: search indexes, old answers, feeds, a person pasting a URL. Product URLs go stale all the time as products sell out, get renamed or are deleted. The status code is how a machine tells a live product from a dead one.

With a soft 404, the agent receives a normal HTML page with status 200. It may read the "page not found" template, the header navigation and a row of recommended products as the page it asked for. It might quote a price from a recommendation as the price of the missing product. It cannot reliably tell that the product is gone.

Google documents soft 404s as an error it reports in Search Console and handles as not found. A redirect of every unknown URL to the home page has the same problem. Google may treat such redirects as soft 404s too, and an agent loses the information that the page it wanted is missing.

## How the scanner decides

- **Pass:** the probe answers 404 or 410, whatever the body says.
- **Warn:** the probe redirects to the home page.
- **Warn:** the probe answers another redirect, or a status that is neither 404, 410 nor a 200 HTML page, such as a 403 or a 500.
- **Fail:** the probe answers 200 with an HTML page. That is a soft 404.
- **Skipped:** the probe was rate limited with 429, met a gateway error (502, 503 or 504), or got no response. Such an answer says nothing about 404 handling, and a 429 is not a soft 404.

The evidence shows the probe URL, the status, the final URL and the content type.

The weight is 1, which means nice to have. It is not a gate for any level.

## How to fix it

Keep your friendly not-found page, but make sure it is sent with status 404. For products you removed for good, 410 is clearer. For products replaced by a new URL, a redirect to that specific new page is fine. What is not fine is a 200, or a blanket redirect of everything unknown to the home page.

### WordPress and WooCommerce

- WordPress returns 404 for unknown URLs by default. A soft 404 usually comes from a plugin.
- Look for redirect plugins with a setting such as "redirect all 404s to the home page" and turn it off. Keep specific redirects for URLs that really moved.
- Check that the theme's `404.php` template does not change the status code.
- If a page builder serves a custom 404 page, confirm that it keeps the 404 status and is not published as a normal page.

### Shopify

- Shopify returns 404 for unknown paths by default and renders the theme's `404` template with that status.
- URL redirect apps that send every missing page to the home page cause the warning. Use Shopify's built-in URL redirects in the admin for individual moved URLs instead.

### Any other stack

- In a single-page app, make the server return 404 for unknown routes instead of sending the app shell with 200 for every path.
- In a framework, use its not-found mechanism, which sets the status, rather than rendering an error component inside a normal response.
- Check CDN and hosting rules. A catch-all rewrite to `/index.html` or a "custom error page" setting can turn every 404 into a 200.

## Verify it yourself

Request a path that cannot exist and print the status and any redirect target:

```bash
curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" https://example.com/this-page-does-not-exist-7f3a9
```

`404` or `410` is correct. `200` is a soft 404. `301` or `302` with your home page as the target is a redirect to the home page. Google Search Console's Page indexing report lists soft 404s it found.

## Common mistakes

- **Redirecting every 404 to the home page.** It feels helpful, but agents and crawlers lose the signal that the page is gone.
- **Styling a 404 page and losing the status.** A custom template rendered as a normal page sends 200.
- **App shells that answer 200 for every path.** The browser shows "not found", but the status says success.
- **Using 403 or 500 for missing pages.** These mean "forbidden" and "server error", not "does not exist".

## FAQ

### What is a soft 404?

A soft 404 is a page that tells people it does not exist but is sent with status 200. Machines read the status, so they treat it as real content.

### Should I redirect old product URLs to the home page?

No. Redirect an old product to its replacement or closest category when one exists. Otherwise let it answer 404 or 410.

### Should I use 404 or 410 for deleted products?

Both pass this check. 404 says the page is not found. 410 says it was removed on purpose and will not return, which is clearer for discontinued products.

### Why was this check skipped?

The probe got a 429, a gateway error or no answer. Those responses say nothing about how the site handles missing pages, so the scanner does not guess.
