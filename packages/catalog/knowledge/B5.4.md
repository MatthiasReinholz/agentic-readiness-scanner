## In short

ChatGPT's shopping features read product data from feeds that merchants push to OpenAI. The OpenAI product feed specification requires nine fields per item, and checkout needs seller policy links on top. This check samples the public feed the scanner found and reports which of those fields are missing. It carries weight 1, nice to have, because the scanner can only read a public copy.

## What this check looks at

OpenAI publishes a product feed specification as part of its commerce documentation, next to the Agentic Commerce Protocol (ACP) checkout specification. A feed in that format is a list of items with flat fields. The specification names nine required fields:

| Field          | Meaning                          |
| -------------- | -------------------------------- |
| `item_id`      | A stable identifier for the item |
| `title`        | The product name                 |
| `description`  | The product description          |
| `url`          | The product page                 |
| `brand`        | The brand                        |
| `seller_name`  | The merchant selling the item    |
| `image_url`    | The main image                   |
| `availability` | Stock status                     |
| `price`        | Price with currency              |

The specification lists return information separately: `return_policy` (a URL) and the return window. For items that should be purchasable in checkout, it requires `seller_privacy_policy` and `seller_tos`, links to the merchant's privacy policy and terms. An item can opt out of checkout with `is_eligible_checkout` set to false.

One item with all of these might look like this:

```json
{
  "item_id": "SKU-1042",
  "title": "Merino crew sweater, navy",
  "description": "Midweight merino wool sweater with a crew neck.",
  "url": "https://example.com/products/merino-crew-navy",
  "brand": "Example",
  "seller_name": "Example Shop",
  "image_url": "https://example.com/images/merino-crew-navy.jpg",
  "availability": "in_stock",
  "price": "89.00 EUR",
  "return_policy": "https://example.com/returns",
  "return_deadline_in_days": 30,
  "seller_privacy_policy": "https://example.com/privacy",
  "seller_tos": "https://example.com/terms",
  "is_eligible_checkout": true
}
```

## Why it matters for AI agents

A feed without `seller_name` or `price` cannot be listed. A feed without return and policy links can be listed, but a checkout cannot be offered with confidence: the buyer and the agent have no terms to point to. Agentic checkout programmes generally ask for return, privacy and terms information.

The limit of this check is important. OpenAI ingests feeds that merchants push to it. It does not crawl a public feed URL on your site. The scanner can only read a public copy, if you publish one, and assume it matches what you send. That is why the weight is 1. A store that pushes a complete feed privately and publishes nothing loses only this check.

## How the scanner decides

The check depends on the [public product feed check](/knowledge-base/public-product-feed). When no feed was found, it does not apply.

- It skips as not applicable for XML feeds in Google's format, including RSS and Atom. Those use Google attributes, not the OpenAI field names.
- For JSON, JSON Lines, CSV and TSV feeds, it reads up to five items.
- It accepts common aliases: `id` or `sku` for `item_id`, `link` for `url`, `image_link` for `image_url`, and `return_window` for `return_deadline_in_days`. `enable_checkout` counts like `is_eligible_checkout`.

Then it decides:

- **Pass:** every sampled item has the nine required fields, `return_policy`, a return window, and `seller_privacy_policy` and `seller_tos`.
- **Warn:** the required fields are all present, but return fields or seller policy fields are missing. An item with `is_eligible_checkout` (or `enable_checkout`) set to false does not need the policy fields.
- **Fail:** at least one sampled item lacks a required field. The message names each field and how many sampled items lack it.
- **Skipped:** the feed could not be fetched again, could not be parsed, or had no items.

## How to fix it

Fix the feed at its source, in the tool that generates it. Hand edits are lost at the next export.

### WordPress and WooCommerce

- Feed plugins build exports from templates. Create or edit an OpenAI-format template and map `seller_name` to a static value, your store name.
- Map `return_policy`, `seller_privacy_policy` and `seller_tos` to static URLs of your [return policy](/knowledge-base/return-policy-page) and [privacy and terms](/knowledge-base/privacy-policy-and-terms) pages.
- Set `return_deadline_in_days` from your actual return window. If it differs by category, use a custom field per product.

### Shopify

- Shopify stores reach ChatGPT through Shopify's own catalog and the Agentic sales channel. Most stores do not maintain an OpenAI-format feed at all, and this check does not apply to them.
- If you export an OpenAI-format feed with an app, configure the seller and policy fields in that app's feed settings.

### Any other stack

- Add the fields in your feed export. `seller_name` and the policy URLs are usually constants. The return window may vary per product.
- Keep the public copy, if you publish one, identical to the feed you push to OpenAI. Otherwise this check describes a file nobody uses.
- Use `is_eligible_checkout: false` for items you do not want sold through checkout, rather than leaving their policy fields empty.

## Verify it yourself

For a CSV or TSV feed, print the header row one field per line:

```bash
curl -s https://example.com/feeds/openai.csv | head -1 | tr ',\t' '\n\n'
```

For a JSON feed, list the keys of the first item:

```bash
curl -s https://example.com/feeds/openai.json | jq '(.items // .)[0] | keys'
```

Compare the result with the nine required fields, the return fields and the two policy fields.

## Common mistakes

- **Using Google's field names in an OpenAI feed.** `link` and `image_link` are accepted as aliases here, but OpenAI's specification uses `url` and `image_url`.
- **Leaving `seller_name` out.** It is easy to forget on a single-merchant store, and it is required.
- **Policy links pointing to the home page.** The URLs should open the actual return, privacy and terms pages.
- **A stale public copy.** If the published file is weeks older than the pushed feed, the scanner judges old data.

## FAQ

### Which fields are required in an OpenAI product feed?

Nine: `item_id`, `title`, `description`, `url`, `brand`, `seller_name`, `image_url`, `availability` and `price`. Checkout additionally needs `seller_privacy_policy` and `seller_tos`.

### Does OpenAI read the product feed from my website?

No. OpenAI documents feeds being pushed to it. This check reads a public copy on your site, if there is one, to estimate what you send.

### Why is my Google Merchant Center XML feed skipped?

It uses Google's attribute names, not OpenAI's, so the OpenAI fields cannot be compared. The check is not applicable to it.

### Do I need return_policy if my store accepts no returns?

Link a page that states the policy, including "no returns". The field is about telling buyers and agents the terms, whatever they are.
