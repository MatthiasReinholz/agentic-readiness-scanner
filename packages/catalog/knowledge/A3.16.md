## In short

This check records how a Shopify store's storefront is built: an Online Store theme, which Shopify renders from Liquid templates, or a headless storefront such as Hydrogen, which is a separate application that reads Shopify's data. For a theme, it names the theme and its version, and its Theme Store id when Shopify sets one. The result is informational and never scored. It tells you where the fixes from the other checks belong.

## What this check looks at

The check reads the home page the scan already fetched. It makes no extra request.

| Trace                                                                                            | What it shows                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| the `Shopify.theme` object in the page                                                           | an Online Store theme. Shopify writes it through `content_for_header`, which every theme's layout must include. It holds the theme's name, its schema name and version, and its Theme Store id |
| a `powered-by` response header that names Hydrogen                                               | a Hydrogen storefront. Shopify's Oxygen hosting adds itself to the same header                                                                                                                 |
| no Shopify response headers on the domain, and a framework's own markers such as `__NEXT_DATA__` | another headless front end, for example built with Next.js                                                                                                                                     |

Shopify sets a Theme Store id only for its own themes installed from the Theme Store, such as Dawn (id 887). A theme without one may be a custom theme, a theme bought elsewhere, or a Theme Store theme by another developer, so the scanner reads nothing into a missing id.

## Why it matters for AI agents

Agents read the HTML a store serves. Online Store themes render on Shopify's servers, so their pages arrive complete. A headless storefront may render on the server or in the browser, and only the first serves complete pages to an agent that does not run JavaScript. [Server-rendered content](/knowledge-base/server-rendered-product-content) checks that, whatever the storefront.

The build also decides where a fix goes:

- In an Online Store theme, structured data, titles and links live in the theme's Liquid files. A Theme Store theme keeps receiving updates, so change it through its settings or in a duplicated copy.
- In a headless storefront, the front-end application renders every page. Fixes go into its code, and Shopify's own storefront features, such as `/products.json` on the store's domain, may not exist there ([products.json](/knowledge-base/shopify-products-json)).

## How the scanner decides

This check runs only when the scan recognised Shopify (see [platform detection](/knowledge-base/ecommerce-platform-detection)). It has weight `info`: it is reported, never scored, and gates no level.

1. A `powered-by` header that names Hydrogen means a Hydrogen storefront.
2. Otherwise, a `Shopify.theme` object means an Online Store theme, named from its schema name and version.
3. Otherwise, a domain Shopify does not serve means a headless storefront, named by its framework when one is recognised.

It always passes when it runs. The fact appears at the top of the report next to the platform, for example "Storefront: Online Store theme (Dawn 15.4.0, Theme Store id 887)". When none of the traces is there, no fact is recorded.

## How to fix it

There is nothing to fix. If you want to change the storefront, these are the usual paths.

### Shopify

- **Updating a Theme Store theme.** Add the theme's latest version from the Theme Store, move your settings across in the theme editor, and compare product pages before publishing it.
- **Moving to a custom theme.** Keep `content_for_header` in the layout and check that structured data and meta tags survive.
- **Going headless.** Make sure the front end renders product content, prices and structured data on the server, and decide what replaces the theme's sitemap and robots.txt.

## Verify it yourself

Look for the theme object:

```bash
curl -s https://example.com/ | grep -oE 'Shopify\.theme = \{[^;]*\}'
```

Look for Hydrogen's header:

```bash
curl -sI https://example.com/ | grep -i '^powered-by'
```

In the Shopify admin, Online Store > Themes shows the current theme and its version.

## Common mistakes

- **Reading the theme's admin name as its identity.** Merchants rename themes freely, for example "Main - July". The schema name and version say which theme it really is.
- **Assuming headless means invisible to agents.** A headless storefront that renders on the server can serve complete pages.
- **Removing `content_for_header`.** Shopify requires it in every theme layout, and apps and checkout depend on it.

## FAQ

### How can I tell which Shopify theme a store uses?

The page source contains `Shopify.theme`, with the theme's schema name and version. A `theme_store_id` other than null identifies a Shopify-made theme installed from the Theme Store.

### How do I know if a Shopify store is headless?

A Hydrogen storefront sends a `powered-by` header that names Hydrogen. Other headless storefronts show no `Shopify.theme` object, and their domain carries no Shopify response headers.

### Is an Online Store theme better for AI agents than Hydrogen?

Not by itself. Online Store themes always render on the server. A Hydrogen storefront can too, and then serves agents just as well.

### Why does the report show no storefront type?

The home page carried no `Shopify.theme` object and no Hydrogen header, and the domain is served by Shopify, so the scanner records nothing rather than guess.
