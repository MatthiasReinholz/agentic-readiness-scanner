## In short

The Agentic Commerce Protocol (ACP) defines how an AI agent creates and completes a checkout with a merchant. A proposal in the ACP repository adds a public discovery document at `/.well-known/acp.json` that says a seller supports ACP and where its API lives. This check reads that document. It carries weight 1, nice to have, and it is one of the two alternatives that gate Level 5.

## What this check looks at

ACP is an open specification. Its checkout specification is published on OpenAI's developer site, and the protocol is developed in an open repository. The released specification, version 2026-04-17, covers checkout sessions. It does not define discovery: merchants register their checkout endpoint with the agent platform privately.

The discovery document is a separate, merged proposal in the ACP repository. Its status is proposal and its version unreleased. It lets an agent check, without authentication, whether a seller speaks ACP, which versions and transports it offers, and where the API base URL is. It must not contain merchant identifiers, buyer data, keys or tokens.

The proposal's fields:

| Field                         | Meaning                                        |
| ----------------------------- | ---------------------------------------------- |
| `protocol.name`               | Always `acp`                                   |
| `protocol.version`            | The version the seller implements, as a date   |
| `protocol.supported_versions` | Every version the seller accepts, oldest first |
| `api_base_url`                | The base URL of the ACP API                    |
| `transports`                  | Transport bindings, which must include `rest`  |
| `capabilities.services`       | The services offered, such as `checkout`       |

The proposal also asks for `Cache-Control: public, max-age=3600` or longer, and for the document to change no more than once an hour.

## Why it matters for AI agents

For ACP the discovery document is the only public trace of an integration. Everything else, including the endpoint registration, happens between the merchant and the platform. A scanner, a partner or a future agent can only see ACP support through this file.

That is also why the weight is low. OpenAI does not document probing `/.well-known/acp.json`, and the document is not part of the released specification. A store with a working ACP checkout and no discovery document loses nothing in any assistant today. It only loses this check, and it can still reach Level 5 through a UCP profile.

Passing means the document is well formed. It does not mean an agent can complete a purchase. Level 5 in this scanner means the public prerequisites of a checkout protocol are in place, never that a checkout was exercised.

## How the scanner decides

The scanner sends one GET request to `/.well-known/acp.json` on the store's origin.

- **Pass:** the answer is 200 with a JSON object that has `protocol.name` set to `acp`, a non-empty `protocol.version`, an `api_base_url` that is an `https` URL, and a `transports` array that includes `rest`. The report also records `supported_versions`, `capabilities` and `capabilities.services` so you can see what the store claims.
- **Fail:** a 404 or any other non-200 status, an HTML page, a body that is not a JSON object, or a document that lacks any of the required parts. The message lists what is missing.

There is no warning state. The document either carries the minimum an agent needs or it does not. A pass here satisfies the Level 5 gate on its own, as an alternative to a passing UCP profile.

## How to fix it

Publish the document only if the store has a live ACP checkout. It must match the endpoint you registered with the platform.

### WordPress and WooCommerce

- If your ACP checkout comes from a payment provider's plugin or an ACP extension, check whether it can publish the discovery document. Use that over a hand-written file, so versions stay in sync.
- Otherwise serve a static JSON file at `.well-known/acp.json` in the web root, with `Content-Type: application/json` and a public cache header.
- Make sure the path is not swallowed by a permalink rule that returns a WordPress 404 page.

### Shopify

- Shopify themes offer no standard way to publish your own files under `/.well-known/`. Shopify connects stores to agent platforms through its own channel and serves a UCP profile instead. The [UCP profile check](/knowledge/ucp-business-profile) is the one that applies.

### Any other stack

- Serve `/.well-known/acp.json` directly over HTTPS, without authentication.
- Set `api_base_url` to the same base URL your ACP endpoints use. Keep `protocol.version` and `supported_versions` aligned with what the API actually accepts.
- List only implemented services in `capabilities.services`.
- Keep merchant identifiers, keys and buyer data out of the file. It is public by design.

## Verify it yourself

Fetch the document and check the fields the scanner needs:

```bash
curl -s https://example.com/.well-known/acp.json | jq '{name: .protocol.name, version: .protocol.version, api_base_url, transports}'
```

`name` should be `"acp"`, `api_base_url` an `https` URL and `transports` should contain `"rest"`.

## Common mistakes

- **An `http` API base URL.** The scanner requires `https`, and no agent should send checkout data over plain HTTP.
- **Forgetting `transports`.** The field is easy to leave out, and without `rest` the check fails.
- **Putting a merchant ID in the file.** The proposal forbids it to prevent seller enumeration.
- **A document that drifts from the registered endpoint.** If the file names an old API base, it misleads anyone who reads it.

## FAQ

### What is the Agentic Commerce Protocol?

ACP is an open specification for checkout between AI agents and merchants. Its checkout specification is published on OpenAI's developer site and developed in an open repository.

### Is /.well-known/acp.json required to sell through ChatGPT?

Not according to any published documentation. Checkout endpoints are registered with the platform directly, and OpenAI does not document probing the discovery file.

### What is the difference between ACP and UCP?

Both are open protocols for agentic checkout. UCP publishes a full business profile at `/.well-known/ucp`. ACP's released specification covers checkout sessions, with discovery still a proposal. This scanner accepts either for Level 5.

### Should I publish acp.json if I am still testing ACP?

No. Publish it when the checkout is live. A discovery document for an integration that does not work misleads agents and partners.
