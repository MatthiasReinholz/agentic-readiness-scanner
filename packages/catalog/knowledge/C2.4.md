## In short

Global Privacy Control (GPC) is a signal a browser or agent sends with every request to say "do not sell or share my personal information". California and several other US states require covered businesses to treat it as a valid opt-out. This check looks for a `/.well-known/gpc.json` file that declares support, or a mention of GPC in the privacy notice. It cannot see whether the store really honours the signal.

## What this check looks at

GPC is defined by a specification developed at the W3C (World Wide Web Consortium). A browser, extension or agent that has the preference turned on sends the HTTP header `Sec-GPC: 1` with each request and exposes `navigator.globalPrivacyControl` as `true` to scripts on the page. A site can say that it honours the signal by serving a small JSON file at `/.well-known/gpc.json`:

- `gpc`: `true` when the site intends to honour GPC requests, `false` when it does not.
- `lastUpdate`: the date the declaration last changed, in `YYYY-MM-DD` form.

Publishing the file is optional under the specification. The laws care about honouring the signal, not about the file. The file and a sentence in the privacy notice are the parts of that commitment a scanner can read.

Laws that give the signal effect:

- **California, CCPA Regulations §7025.** A business that sells or shares personal information must process an opt-out preference signal such as GPC as a valid request to opt out of sale and sharing. Since the amendments that took effect on 1 January 2026, the business must also show the consumer whether it processed the signal, for example with a message on the site or a privacy setting that reflects it.
- **Colorado Privacy Act.** Controllers must honour universal opt-out mechanisms recognised by the state, and GPC is recognised. Connecticut, Texas, Oregon, Montana, Delaware, Nebraska, New Hampshire, New Jersey, Minnesota and Maryland have comparable rules for universal opt-out mechanisms, each with its own scope and start date.
- **EU, GDPR Art. 21(5).** In the context of online services, a person may exercise the right to object by automated means using technical specifications. Whether GPC is such a means is not settled. It is listed here as related, not as a requirement.

## Why it matters for AI agents

An agent that browses or buys for a person can carry that person's privacy choices with it. If the person runs a browser with GPC turned on, the agent acting for them may send `Sec-GPC: 1` too, on every request to every store, without the person filling in a single form. That is the point of a universal signal: the preference travels with the principal, whoever or whatever does the clicking.

For the store, `/.well-known/gpc.json` is the machine-readable answer to the agent's question "will you respect this?". An agent can read it before it starts a session and tell its principal which stores declare support. A store that honours the signal but never says so leaves that question open.

The signal complements the visible links in [California opt-out links](/knowledge-base/california-privacy-opt-out-links). One is for people clicking, the other for software acting for them.

## How the scanner decides

The check runs when the store appears to sell in the United States, or when you choose that market yourself. Otherwise it is shown as not applicable.

The scanner requests `/.well-known/gpc.json` once and reads the privacy notice the scan already found.

- **Found:** `gpc.json` answers HTTP 200 with valid JSON containing `"gpc": true`, or the privacy notice mentions Global Privacy Control, GPC, `Sec-GPC` or an opt-out preference signal.
- **Review:** `gpc.json` says `"gpc": false`, or there is neither a valid file nor a mention in the privacy notice.

What the scanner cannot see:

- Whether the store actually honours GPC. That happens in the browser, when consent tools and tags read `navigator.globalPrivacyControl`, and the scanner does not run JavaScript.
- Whether the store shows visitors that their signal was processed.
- Whether the store is covered by any of the laws above.

A declaration without the behaviour behind it is worse than no declaration. This is a technical reading of public pages, not legal advice.

## How to fix it

First make the store honour the signal, then declare it. Ask a lawyer whether the state laws apply and to review the privacy notice wording.

### WordPress and WooCommerce

- In your consent management plugin, look for a setting to respect Global Privacy Control, often in its US or CCPA section, and turn it on. Test it with a browser that sends GPC.
- Create the file `.well-known/gpc.json` in the web root with the snippet from the fix, or serve it from a small route if your host does not allow files there.
- Add a paragraph to the privacy policy page that says the store treats GPC as a request to opt out of sale and sharing.

### Shopify

- Shopify's customer privacy controls can treat GPC as an opt-out of data sale or sharing for visitors in the regions where it applies. Check Settings, Customer privacy, and confirm your consent app does the same.
- Shopify does not let you place arbitrary files at the root of the store. Use a URL redirect or an app that serves well-known files, and check that `https://yourstore.com/.well-known/gpc.json` ends with a JSON response containing `"gpc": true`.
- Mention GPC in the privacy policy under Settings, Policies.

### Any other stack

- Read `Sec-GPC: 1` on the server or `navigator.globalPrivacyControl` in the browser, and treat it as an opt-out: no advertising pixels, no data sharing, consent defaults set to opted out.
- Serve `/.well-known/gpc.json` with `Content-Type: application/json` and `{"gpc": true, "lastUpdate": "YYYY-MM-DD"}`. Update `lastUpdate` when your handling changes.
- Show the visitor that the signal was applied, for example in the consent banner or privacy settings.

## Verify it yourself

Fetch the declaration:

```bash
curl -s -H "Accept: application/json" https://example.com/.well-known/gpc.json
```

You should see `"gpc": true`. To test the behaviour, turn on GPC in a browser that supports it, open the store and check in the developer tools that advertising requests stop. Then rescan with this scanner.

## Common mistakes

- **Declaring without honouring.** A `gpc.json` with `true` while pixels keep firing is a public statement that does not match the site.
- **An HTML page at the well-known path.** A storefront that answers every unknown URL with a themed page returns HTML, not JSON. The specification treats that as unknown support.
- **A stale `lastUpdate`.** It should change when your handling of the signal changes.
- **Honouring GPC only on the first page.** The signal arrives with every request and should apply across the visit.

## FAQ

### Does this apply to my store?

California's rule binds businesses covered by the CCPA that sell or share personal information. Colorado and the other listed states have their own thresholds, mostly based on how many residents' data a business processes. The scanner cannot see a business's size or data flows, so it reports review rather than not found. A lawyer can tell you which rules apply.

### Is gpc.json required by law?

No. The laws require honouring the signal. The file is an optional part of the GPC specification that lets machines read your commitment. This check uses it, or a mention in the privacy notice, as the visible evidence.

### What is the Sec-GPC header?

It is the HTTP request header a GPC-enabled browser or agent sends, with the value `1`. Servers should ignore any other value. The same preference is available to page scripts as `navigator.globalPrivacyControl`.

### Can the scanner test whether we honour GPC?

Not reliably. Honouring usually happens in browser scripts that the scanner does not run. A server that changes its response for `Sec-GPC: 1` would be visible, but that setup is rare, so the check reads only the declaration.
