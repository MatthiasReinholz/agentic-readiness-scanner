## In short

Every GTIN (Global Trade Item Number) ends in a check digit calculated from the digits before it. A number whose last digit does not match is not a real GTIN, and agents or merchant programmes cannot use it to identify the product. This check recalculates the GS1 check digit for every GTIN it found and fails if any one of them is wrong.

## What this check looks at

A GTIN is the barcode number of a product: UPC (12 digits), EAN (13 digits), EAN-8 (8 digits) or ITF-14 (14 digits). GS1, the organisation that runs the barcode system, defines the last digit as a check digit. It catches typing errors, swapped digits and numbers that were made up.

The calculation works the same for every length:

1. Take all digits except the last one.
2. Starting from the rightmost of those digits, multiply them alternately by 3 and by 1.
3. Add up the results.
4. The check digit is the amount needed to reach the next multiple of 10. If the sum already is a multiple of 10, the check digit is 0.

For the EAN-13 `4006381333931` the first twelve digits give a weighted sum of 89. The next multiple of 10 is 90, so the check digit is 1, which matches. Change any single digit and the result no longer matches.

The check reads every GTIN that the [GTIN presence check](/knowledge/gtin-present) found. That means the `gtin`, `gtin8`, `gtin12`, `gtin13` and `gtin14` properties in the Product JSON-LD and its variants, and on WooCommerce the Store API value `global_unique_id`.

## Why it matters for AI agents

A GTIN is only useful if it points at the right product. An agent matching offers relies on the number to say "this is the same item". A wrong digit either points at nothing or, worse, at a different product. In both cases the identifier hurts more than a missing one, because it looks authoritative.

Google Merchant Center requires the check digit to be present and correct and points to the GS1 check digit calculator. It also rejects numbers in restricted and coupon ranges. Any system that checks identifiers can catch an invalid number the same way, so a broken GTIN is easy to spot and hard to trust.

This check carries weight 3, which means blocking. It is part of the Level 3 gate, "Identifiable products". The gate is satisfied when this check passes, or when the [MPN fallback check](/knowledge/mpn-when-gtin-absent) passes instead.

## How the scanner decides

The scanner takes every sampled product that has at least one value shaped like a GTIN. It checks every such value on the product and on its variants, not only the first one. For each value it removes spaces and hyphens, confirms the length is 8, 12, 13 or 14 digits and recalculates the GS1 check digit.

- **Pass:** every GTIN found passes the check digit.
- **Fail:** at least one GTIN fails it. The message names up to five of the failing values.
- **Skip:** no sampled product carries a GTIN, so there is nothing to validate. Values with the wrong length are not counted as GTINs at all; they appear as invalid format in the presence check's evidence instead.

The check does not look up the number in the GS1 registry. A value can pass the check digit and still belong to a different product. The check proves the number is well formed, not that it is the right one.

## How to fix it

Start with the evidence in the report. It lists each failing value and the page it came from. Then find the source of the error.

- **Typing and transposition errors.** Two swapped digits usually break the check digit. Compare the value with the barcode on the packaging or the supplier's data sheet.
- **A truncated or extra digit.** A 13-digit EAN with its last digit cut off is 12 digits long. It then gets checked as a UPC, and almost always fails.
- **Internal codes in the GTIN field.** A 13-digit internal article number is not a GTIN. Move it to the SKU or MPN field.
- **Invented numbers.** Remove them. If you own the brand, license real GTINs from GS1.

Lost leading zeros are a common data problem too. They usually change the length, so the value shows up as invalid format in the [GTIN presence check](/knowledge/gtin-present) rather than here.

### WordPress and WooCommerce

- Edit the GTIN, UPC, EAN or ISBN field under Product data, Inventory, on the product or the variation that failed.
- If you import products by CSV, format the GTIN column as text before you save the file, so the spreadsheet does not round or shorten it.
- Add a validation step to your import process or a small snippet that rejects values failing the check digit on save.

### Shopify

- Edit the Barcode field on the variant that failed.
- When you bulk-edit or import by CSV, keep the barcode column as text. Spreadsheet tools can turn long numbers into scientific notation such as `4.00638E+12`.
- Fix the value at the source if a supplier app or PIM (product information management system) syncs it, or it will come back on the next sync.

### Any other stack

- Validate GTINs on input with the algorithm above. It is a few lines of code in any language.
- Store GTINs as strings, never as integers.
- Reject values in your feed export that fail validation, and log them for someone to fix.

## Verify it yourself

GS1 offers a free check digit calculator on its website. Enter the first digits and compare its result with your last digit.

To check a value from the command line, run this with your GTIN in place of the example:

```bash
node -e 'const d=process.argv[1].replace(/[\s-]/g,"");let s=0,w=3;for(let i=d.length-2;i>=0;i--){s+=+d[i]*w;w=4-w}console.log((10-s%10)%10===+d.at(-1)?"valid":"invalid")' 4006381333931
```

Rescan with this scanner after correcting the data.

## Common mistakes

- **Fixing the product but not its variants.** The check reads every variant's GTIN. One bad variant fails the check.
- **Correcting the page but not the feed.** If your markup and your feed come from different fields, fix both.
- **Generating "valid-looking" numbers.** A random number with a computed check digit passes this check but identifies nothing, or someone else's product.
- **Using a GTIN-14 shipping case code for a single unit.** The case and the unit inside it have different GTINs.

## FAQ

### What is a GTIN check digit?

It is the last digit of every GTIN. GS1 calculates it from the other digits with alternating weights of 3 and 1. It lets any system catch a mistyped number without a database lookup.

### Can a GTIN pass the check digit and still be wrong?

Yes. The check digit catches most typing errors, but a number can be well formed and belong to a different product. Only the manufacturer's data or the GS1 registry confirms the match.

### Why does Google reject my GTIN when the scanner passes it?

The scanner checks length and check digit only. Google also rejects restricted prefixes such as 02, 04 or 2, and coupon ranges such as 05, 98 or 99. Its own systems may flag other problems the scanner cannot see.

### Is a GTIN with a wrong check digit worse than no GTIN?

For matching, yes. A missing GTIN can be replaced by brand plus MPN. A wrong one points systems at the wrong product or gets the listing flagged.
