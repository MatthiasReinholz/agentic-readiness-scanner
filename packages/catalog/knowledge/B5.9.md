## In short

BigCommerce offers a Storefront MCP server (MCP is the Model Context Protocol, through which AI agents call tools) that lets agents search products, manage a cart and hand a guest off to checkout. The store owner switches it on in the control panel. Eligible storefronts also carry a WebMCP bridge script that points browser agents to that server. This check reads the bridge from the home page and asks the server it names whether it answers. It runs only on BigCommerce stores and carries weight 2, expected.

## What this check looks at

MCP, the Model Context Protocol, is an open protocol that lets an AI agent call tools on a server through JSON-RPC 2.0 messages (a simple format for calling a method on a server with JSON). BigCommerce documents two pieces that work together:

- **Storefront MCP.** An MCP server for one storefront. BigCommerce's documentation says guests can use it to search products, manage a cart and hand off to checkout. Each storefront has its own MCP URL. The store owner enables it under Settings, API and MCP, MCP in the control panel, switches it on and accepts the terms. It can take up to ten minutes to become available.
- **WebMCP.** A bridge for agents that run in the visitor's browser. BigCommerce injects a script from `/.webmcp/bridge.js` into the page. Its `data-mcp-url` attribute names the Storefront MCP URL. BigCommerce turns WebMCP on by default for eligible Stencil storefronts and for Catalyst storefronts hosted on Cloudflare.

Because WebMCP is on by default and Storefront MCP is not, a store can advertise a server that is not there. In a sample of live BigCommerce stores taken on 2026-11-03, most stores that carried the bridge answered 404 at the advertised MCP URL. Their Storefront MCP was off.

## Why it matters for AI agents

Storefront MCP is BigCommerce's own structured way for agents to shop a store. An agent that reaches it can find products and fill a cart without reading theme pages.

The bridge makes a dead endpoint worse than none. A browser agent that follows it reaches a URL with no server behind it, and loses the shopping tools the page promised.

Passing shows that the advertised server answers. It does not show that an agent completed a purchase. This check is not a level gate, and it does not lift the commerce score's cap of 60. Only a pass on the [UCP checkout check](/knowledge-base/ucp-checkout-and-payment-handler) or the [ACP discovery document](/knowledge-base/acp-discovery-document) lifts that cap on a BigCommerce store.

## How the scanner decides

The check runs only when the [platform detection check](/knowledge-base/ecommerce-platform-detection) found BigCommerce. Reports for other platforms do not show it.

The scanner reads the home page HTML as served, without running JavaScript. It looks for a `script` element whose `src` contains `/.webmcp/bridge.js` and that has a `data-mcp-url` attribute. It accepts the URL only when it is on the store's own origin.

If it finds one, it sends one POST to that URL. The body is a JSON-RPC `server/discover` request, the read-only method the current MCP specification defines for clients to learn about a server. It creates or changes nothing. An older server that refuses this with a plain HTTP 400 gets the `initialize` handshake of the 2025 specification once instead, as any MCP client would send.

- **Pass:** the answer is a JSON-RPC message, including a JSON-RPC error, or arrives as an event stream. An HTTP 401 with a `WWW-Authenticate` header also counts, because it shows a server asking for credentials.
- **Warn:** the bridge points at a URL where no MCP server answers, such as a 404 or an HTML page. Storefront MCP is switched off.
- **Warn:** the home page has no bridge with a `data-mcp-url` on the store's origin. The store advertises no MCP server for agents to find.
- **Warn:** robots.txt disallows the MCP path for the scanner's user agent. The scanner honours robots.txt, so it did not ask.
- **Skipped:** the request failed before any answer arrived, for example on a timeout or a connection error, or the server answered with a rate limit (HTTP 429) or a gateway error (502, 503 or 504). Those answers say nothing about the MCP server behind them.

## How to fix it

Switch on the server the bridge already points to.

### BigCommerce

- **Enable Storefront MCP.** As the store owner, open the control panel and go to Settings, API and MCP, MCP. Switch on Storefront MCP for the storefront and accept the terms. Allow up to ten minutes before you test.
- **Keep the WebMCP bridge on.** It is on by default for eligible Stencil and Cloudflare-hosted Catalyst storefronts. Leave it on unless you have a reason to opt out, so browser agents can find the server.
- **Check robots.txt and firewall rules.** Make sure neither blocks POST requests to the MCP path that `data-mcp-url` names.
- **Test each storefront.** Each storefront has its own MCP URL. A multi-storefront setup needs the switch and a test for each one.

## Verify it yourself

Find the bridge and the URL it advertises:

```bash
curl -s https://example.com/ | grep -oE 'data-mcp-url="[^"]*"'
curl -s https://example.com/ | grep -c '/.webmcp/bridge.js'
```

Then call the advertised URL. Replace the address with the value from `data-mcp-url`, made absolute if it is a path:

```bash
curl -s -X POST 'https://example.com/PATH-FROM-DATA-MCP-URL' \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{}}'
```

A live server prints a JSON-RPC message that contains `"jsonrpc":"2.0"`, possibly after a `data:` line. An error inside that message still shows the server is live. A 404 or an HTML page usually means Storefront MCP is off.

## Common mistakes

- **Assuming the bridge means the server is on.** The bridge is on by default. Storefront MCP needs the owner to switch it on.
- **Testing straight after enabling.** The server can take up to ten minutes to become available.
- **Enabling one storefront only.** Each storefront has its own MCP URL and its own setting.
- **Blocking POST at the firewall.** A rule written for forms or bots can refuse the JSON-RPC request.

## FAQ

### How do I turn on BigCommerce Storefront MCP?

In the control panel, go to Settings, API and MCP, MCP, switch it on for the storefront and accept the terms. It can take up to ten minutes to become available.

### What is /.webmcp/bridge.js on my BigCommerce store?

It is BigCommerce's WebMCP bridge. It is injected into eligible storefronts by default and tells browser agents where the Storefront MCP server is, through its `data-mcp-url` attribute.

### Why does the scanner warn that my WebMCP bridge points to a dead endpoint?

The bridge is on, but Storefront MCP is not. The URL in `data-mcp-url` answers without an MCP server behind it. Switch Storefront MCP on in the control panel.

### Can agents check out through BigCommerce Storefront MCP?

BigCommerce's documentation says guests can search products, manage a cart and hand off to checkout. The scanner does not test checkout, and a pass here does not count as an agent checkout for the score cap or for a level.
