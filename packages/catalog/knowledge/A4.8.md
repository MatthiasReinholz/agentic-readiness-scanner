## In short

Wix documents a Model Context Protocol (MCP) server at `/_api/mcp` on every Wix site. Agents can call it over POST without authentication. This check sends a read-only request there and passes when an MCP server answers. It runs only on Wix sites and carries weight 1, nice to have.

## What this check looks at

MCP is an open protocol that lets an AI agent call tools on a server through JSON-RPC 2.0 messages. JSON-RPC is a simple format for remote calls: each request names a method, and the answer carries a result or an error.

Wix's developer documentation says every Wix site has a site MCP server at `https://{your domain}/_api/mcp`. It accepts POST requests and needs no authentication. You do not have to install or build anything.

Wix also generates an llms.txt file for sites that meet its conditions: a paid plan, a connected custom domain and search engine indexing switched on. The site owner can control it with the "Use your llms.txt file" toggle. Wix's help center says the generated file links the MCP endpoint, so agents that read llms.txt can find it.

## Why it matters for AI agents

An agent that finds a working MCP server can ask the site structured questions instead of parsing pages. On Wix the server is part of the platform, so the only question is whether it is reachable on your domain.

When the server does not answer, the cause is almost always in front of Wix: a proxy, a firewall or a robots.txt rule. Those are things you control.

Passing shows that an MCP server answers on your domain. It does not say which tools it offers, how good your content is, or whether an agent will use it.

## How the scanner decides

This check runs only on Wix sites, when the [platform detection check](/knowledge-base/ecommerce-platform-detection) found the platform. Reports for other platforms do not show it.

The scanner sends one POST to `/_api/mcp` on the site's origin. The body is a JSON-RPC `server/discover` request, the read-only method the current MCP specification defines for clients to learn about a server. It creates or changes nothing. The request asks for `application/json` or `text/event-stream`, as the MCP transport specification describes. If the server answers with a plain HTTP 400, as servers on the 2025 revisions do before a session exists, the scanner sends the `initialize` handshake once instead.

- **Pass:** the answer is a JSON-RPC message, or arrives as an event stream. A JSON-RPC error also counts, because only an MCP server sends one. An HTTP 401 with a `WWW-Authenticate` header counts too, because it shows a server asking for credentials.
- **Fail:** anything else comes back, such as a 404, an HTML page or a server error without a JSON-RPC body. No MCP server answers where Wix serves one for every site.
- **Warn:** robots.txt disallows `/_api/mcp` for the scanner's user agent. The scanner honours robots.txt, so it did not ask. Agents that honour robots.txt are kept out too.
- **Skipped:** the request failed before any answer arrived, for example on a timeout or a connection error, or the server answered with a rate limit (HTTP 429) or a gateway error (502, 503 or 504). Those answers say nothing about the MCP server behind them.

## How to fix it

Look at what sits between agents and Wix before you contact support.

### Wix

- **Publish the site on its domain.** Saving changes in the editor is not enough. Check in the Wix dashboard that the site is published and connected to the domain you scanned.
- **Check a proxy or CDN in front of Wix.** If a reverse proxy, CDN or firewall serves your domain, make sure it forwards POST requests to `/_api/mcp` unchanged, with their body and headers.
- **Review robots.txt.** Open SEO & GEO, Tools and settings, Robots.txt Editor in the Wix dashboard. Remove any rule that disallows `/_api/` for all agents.
- **Turn on the generated llms.txt if you qualify.** It links the MCP endpoint for agents that look there. It needs a paid plan, a custom domain and indexing switched on.
- **Contact Wix support** if the endpoint still does not answer. Give them the domain and the time of your test.

## Verify it yourself

Send a `server/discover` request:

```bash
curl -s -X POST https://example.com/_api/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"server/discover","params":{}}'
```

Or ask for the list of tools:

```bash
curl -s -X POST https://example.com/_api/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Either command should print a JSON-RPC message that contains `"jsonrpc":"2.0"`, possibly after a `data:` line. An error inside that message is fine. It still shows the server is live.

To see whether your llms.txt links the endpoint:

```bash
curl -s https://example.com/llms.txt | grep -i '_api/mcp'
```

## Common mistakes

- **Testing with GET.** The endpoint expects POST. A browser visit to `/_api/mcp` tells you nothing.
- **Blocking `/_api/` in robots.txt.** It keeps agents that honour robots.txt away from the MCP server.
- **A firewall rule that blocks POST requests.** A rule written for forms or bots can refuse POST requests to `/_api/` paths. The server then never sees the request.

## FAQ

### Does every Wix site have an MCP server?

Yes. Wix documents a site MCP server at `/_api/mcp` for every Wix site, with no authentication required.

### Do I need to install anything to get the Wix site MCP?

No. Wix runs it as part of the platform. Your part is to keep it reachable on your domain.

### Why does the scanner fail my Wix site when Wix runs the server?

Something in front of Wix did not let the request through, or the site is not published on the domain you scanned. Check a proxy, a firewall and the domain connection first.

### Does Wix's llms.txt link the MCP server?

Wix's help center says the generated llms.txt links it. The file is generated only for sites on a paid plan with a custom domain and indexing switched on, and the owner can turn it off.
