## In short

Googlebot reads the first 2 MB of an HTML document and ignores everything after it. On a heavy product page, that can cut off the description, the reviews or the structured data placed at the end of the body. This check measures the HTML size and response time of sampled product pages and warns well before the cutoff.

## What this check looks at

The scanner measures the uncompressed HTML of each sampled product page. When it found no product pages, it measures the home page instead. Compression does not help here. The limit applies to the HTML after it is unpacked.

Two numbers matter:

- **HTML size.** The number of bytes in the page's HTML. Images, scripts and stylesheets loaded from separate files do not count. Inline scripts, inline styles, inline SVG and embedded JSON do.
- **Response time.** How long the server took to deliver the whole page to the scanner. It is measured once per page and includes the network path, so treat it as an upper bound.

Google documents the 2 MB limit for Googlebot, with the HTTP headers counted toward it. The scanner reads at most the same 2 MB, so a page it had to cut short is a page past Google's cutoff.

## Why it matters for AI agents

AI answers draw on indexes that crawlers build. If Googlebot stops reading at 2 MB, nothing after that point enters Google's index. Product pages are especially exposed. Themes often place structured data near the end of the body. That is the JSON-LD block, machine-readable data in the page, that describes price and availability. Page builders and apps add large inline scripts and JSON state blobs. A page can reach 2 MB of HTML long before it looks heavy in a browser.

Size also costs agents directly. An agent fetching a page for a person reads the whole HTML, and every extra megabyte is time and tokens spent on markup instead of product facts.

Speed is a softer signal. Slow responses limit how many pages a crawler can fetch in a given time, and an agent waiting on a page has less patience than a person. The scanner treats response time as a crawl-health hint, not as an eligibility rule.

## How the scanner decides

- **Fail:** any measured page reaches 2 MB (2,000,000 bytes), or the scanner had to stop reading it at that limit. Anything after the cutoff, including late structured data, is not indexed.
- **Warn:** the largest page is 1 MB or more, or the slowest response took 3 seconds or more.
- **Pass:** every page is under 1 MB and answered in under 3 seconds.

If product pages were sampled but none could be fetched, the check is skipped with the reason. Pages that failed are named and never measured as empty. The evidence lists each page's size, response time and whether it was cut short.

The weight is 1, which means nice to have. It gates no level. A fail is still worth fixing quickly when structured data sits after the cutoff, because the checks that read it assume crawlers see it.

## How to fix it

Find out what makes the HTML heavy before you change anything. Save a product page and look for the largest blocks. The usual culprits are inline JSON state, inline SVG sprites, base64 images, repeated structured data and long lists of variants rendered as hidden markup.

### WordPress and WooCommerce

- Turn on full-page caching for visitors who are not logged in. A caching plugin or your host's cache cuts response time the most.
- Page builders often inline large CSS and JavaScript blocks. Use their option to load these as external files.
- Products with many variations can render large variation JSON into the page. WooCommerce loads variation data by request above a threshold, which a filter in a site plugin can adjust.
- Check for duplicate JSON-LD from several SEO or schema plugins and keep one.

### Shopify

- Large product pages usually come from theme sections and apps that inline scripts or JSON. Remove unused app blocks and uninstall apps you no longer use, since some leave code behind.
- Avoid rendering every variant, every image and every metafield into hidden markup. Load secondary data when it is needed.
- Slow responses on Shopify often come from heavy Liquid logic in the theme, such as loops over large collections on the product page.

### Any other stack

- Move inline scripts, styles and SVG sprites into cached external files.
- Do not serialise the entire application state into the HTML. Send what the product page needs and load the rest by request.
- Place structured data in the head or early in the body, so it falls well inside the cutoff even if the page grows.
- Cache rendered product pages at the server or CDN to bring response time under 3 seconds.

## Verify it yourself

Measure the uncompressed HTML size and the total response time of a product page:

```bash
curl -s -H "Accept-Encoding: identity" https://example.com/products/example | wc -c
curl -s -o /dev/null -w "%{time_total} s\n" https://example.com/products/example
```

The first number is bytes of HTML. Under 1,000,000 passes, and 2,000,000 or more fails. Run the timing a few times, since a single slow answer can be a cold cache.

## Common mistakes

- **Measuring the compressed size.** A 400 KB gzip transfer can be 2 MB of HTML. The limit applies to the unpacked page.
- **Counting images.** Image files are fetched separately and do not count. Base64 images inside the HTML do.
- **Putting JSON-LD at the very end.** It is the first thing lost when a page grows past the cutoff.
- **Testing a cached page only.** The first uncached request is what a crawler often gets.

## FAQ

### Does Google really stop reading at 2 MB?

Yes. Google documents that Googlebot reads the first 2 MB of a supported file type such as HTML, and that it ignores the rest. Separately loaded resources such as scripts and stylesheets each have their own limit.

### Do images count toward the 2 MB limit?

Not when they are separate files. Only the HTML document counts. Images embedded as base64 data inside the HTML do count.

### My page is 1.2 MB. Will it lose content?

Not yet. Everything up to 2 MB is read. The warning at 1 MB is a margin, since product pages tend to grow as apps, reviews and variants are added.

### Is 3 seconds a Google rule?

No. The 3 second threshold is this scanner's crawl-health hint. Google does not publish a response time that makes a page ineligible.
