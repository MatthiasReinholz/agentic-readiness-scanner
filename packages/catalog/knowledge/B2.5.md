## In short

The primary product image is how shoppers and agents confirm they found the right item. It must load, it needs alt text that describes it in words, and it must be large enough for shopping surfaces. This check tests the main image named in your Product markup on each sampled page. It warns when the image is small or blocked for Google's crawlers and fails when it does not load at all.

## What this check looks at

The scanner starts from the `image` property of the Product or ProductGroup node in your JSON-LD, which the [Product JSON-LD check](/knowledge/product-json-ld) already found. It takes the first image and checks four things:

- **It resolves.** The URL is absolute and answers with a success status.
- **It is rendered with alt text.** The scanner finds the img element on the page that shows the same image and reads its `alt` attribute.
- **It is large enough.** The longest side is at least 500 pixels.
- **Google's crawlers may fetch it.** The store's robots.txt does not disallow Googlebot or Googlebot-Image from a same-origin image URL.

Matching the markup image to the rendered img is tolerant. The scanner compares URL paths without query strings and without size suffixes, such as Shopify's `_1080x` or `&width=1080` and WordPress's `-300x200`. It looks in `src`, `srcset`, `data-src`, `data-srcset` and `picture` sources. One-pixel tracking images and images marked `aria-hidden` are ignored.

## Why it matters for AI agents

Many agents work from text. Alt text is how they learn what an image shows, and it is also what screen readers announce to people who cannot see the page. An alt text like "Blue stoneware mug, 350 ml, side view" confirms colour and size. A file name like "IMG_4412" confirms nothing.

Resolution matters for shopping surfaces. Google Merchant Center's image requirements set a minimum of 500 by 500 pixels for all products from 31 January 2027 and recommend 1500 by 1500 pixels or more. Google also says products whose images are blocked by robots.txt stop showing in free listings. Its guidance is to allow both Googlebot and Googlebot-Image.

This check has weight 1, nice to have, and gates no level. It is usually quick to fix, and a broken image is worth finding early.

## How the scanner decides

Each sampled product image gets its own verdict.

- **Fail** for that image when the markup has no image, when the image URL is not an absolute http or https URL, or when the image does not resolve.
- **Warn** for that image when it is not rendered as an img on the page, when the rendered img has no alt text, when its longest side is under 500 px, or when robots.txt blocks Googlebot or Googlebot-Image from it.
- **Inconclusive** when the scanner's request for the image got no response at all, and that is the only issue. Inconclusive images are not scored.
- Otherwise the image passes. An image between 500 and 1500 px passes with a note that Google recommends 1500 px.

The scanner reads the size from the JSON-LD `ImageObject` width and height, or from the img element's attributes and `srcset`. Only when neither gives a size does it send a HEAD request to confirm the image resolves.

The overall result is a **fail** when any image fails, a **warn** when any image warns, and a **pass** otherwise. It is a **skip** when no product markup was found or when no image could be checked.

## How to fix it

Fix the source images once in your media library or product admin. Themes then generate the smaller sizes from them.

### WordPress and WooCommerce

- The Product image set in the product editor becomes the image in WooCommerce's markup. Upload originals of at least 1500 px on the longest side.
- Set alt text in the Media Library, under Alternative Text for each image. WooCommerce gallery templates output it on the rendered img.
- Lazy-loading plugins sometimes move the URL to `data-src` and leave a placeholder in `src`. The scanner reads `data-src`, but make sure the placeholder is not the only img with alt text.
- Check robots.txt for rules like `Disallow: /wp-content/uploads/`. Some security plugins add them. Remove them.

### Shopify

- Upload product media of at least 1500 px. Shopify's CDN serves resized versions to the theme.
- Add alt text in the product admin: open the image under Media and use Add alt text. Themes output it on the product image.
- Shopify's default robots.txt does not block product images. Check `robots.txt.liquid` if your theme has one.

### Any other stack

- Serve the full-size image at a stable absolute URL and use that URL in the JSON-LD.
- Render the same image as an img element on the page with a descriptive `alt` attribute. Responsive `srcset` variants are fine.
- Add `width` and `height` to the JSON-LD image, which also saves the scanner a request:

```json
"image": {
  "@type": "ImageObject",
  "url": "https://example.com/images/mug-blue-1600.jpg",
  "width": 1600,
  "height": 1600
}
```

The fix on this page asks for at least 500 px, Google's minimum, and aims for 1500 px, Google's recommendation for the best results.

## Verify it yourself

Find the image URL in the markup, then check that it loads and how large it is:

```bash
curl -sI https://example.com/images/mug-blue-1600.jpg | head -n 5
curl -s https://example.com/images/mug-blue-1600.jpg -o /tmp/mug.jpg && file /tmp/mug.jpg
```

`file` prints the pixel dimensions for JPEG and PNG images. To check alt text, inspect the product image in your browser's developer tools. Google Search Console's URL Inspection tool and the robots.txt report show whether Googlebot may fetch the image.

## Common mistakes

- **Alt text that repeats the file name.** "DSC_0042.jpg" tells an agent nothing about the product.
- **A thumbnail in the markup.** The JSON-LD points to the 300 px catalogue thumbnail instead of the full image.
- **An image CDN on a host that blocks crawlers.** The image lives on a separate host whose robots.txt or firewall rejects Googlebot.
- **Upload folders disallowed in robots.txt.** A rule meant to hide private files also hides product photos.
- **A markup image that never appears on the page.** The JSON-LD names a photo the theme does not render, so there is no alt text to read.

## FAQ

### What size should product images be for Google Shopping?

Google Merchant Center requires at least 500 by 500 pixels for all products from 31 January 2027 and recommends 1500 by 1500 pixels or larger. Uploading 1500 px originals covers both.

### Does alt text help AI agents?

Agents that read the page as text cannot see the image. Alt text is the only description they get from it. It also makes the page accessible to people using screen readers.

### Should I block Googlebot-Image in robots.txt?

Not for product images. Google says products whose images are blocked stop showing in free listings, and recommends allowing both Googlebot and Googlebot-Image.

### Why is my image marked inconclusive?

The scanner sent a request for the image and got no response at all, for example a timeout or a URL its fetch policy would not request. That says nothing about the image itself, so it is not scored.
