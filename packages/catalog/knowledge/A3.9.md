## In short

A conditional request lets a crawler ask "has this page changed since I last saw it?" instead of downloading it again. The server answers 304 Not Modified when nothing changed. This check reads the ETag or Last-Modified header of a product page, repeats the request with that validator, and passes when the server answers 304. It has weight 1: nice to have, never blocking.

## What this check looks at

HTTP has two validators that identify a version of a page. RFC 9110 defines both.

- **ETag** is an opaque version tag, for example `ETag: "a1b2c3"`. A client sends it back in `If-None-Match`.
- **Last-Modified** is a date, for example `Last-Modified: Tue, 27 Oct 2026 09:12:00 GMT`. A client sends it back in `If-Modified-Since`.

When the validator still matches, the server answers `304 Not Modified` with no body. When the page changed, it answers 200 with the new page and a new validator.

The scanner reads the HTML response of the first sampled product page that answered, or the home page when none were sampled. It never judges a Markdown copy of the page negotiated with `Accept: text/markdown`, because converters serve those without validators.

## Why it matters for AI agents

AI assistants answer from indexes that crawlers keep fresh by revisiting pages. A store with thousands of products asks a lot of a crawler. Google's crawler documentation and Bing's webmaster guidelines both name ETags as a way they detect unchanged pages.

When a page answers 304, the crawler confirms it in one small response and can spend its time on pages that did change, such as a new price or a restock. That keeps the index closer to what the store really shows. It also saves the store bandwidth and server time.

This check does not prove that crawlers revisit faster. It shows that the store makes cheap revisits possible.

## How the scanner decides

The scanner fetches the page normally and looks for an `ETag` header, then a `Last-Modified` header. If it finds one, it sends a second request with `If-None-Match` (for an ETag) or `If-Modified-Since` (for a date). This is the only request in the whole scan that repeats a URL.

- **Pass** when the conditional request answers 304.
- **Warn** when the page sends a validator but answers 200 to the conditional request. The validator is decorative: the server ignores it.
- **Warn** when the conditional request answers some other status.
- **Warn** when the page sends neither ETag nor Last-Modified.
- **Skip** when the page or the conditional request could not be fetched at all.

When the first sampled product page could not be fetched, the scanner judges the next one and says so in the message.

## How to fix it

The goal is simple. HTML product pages should carry a validator, and the server or cache in front of them should compare it with `If-None-Match` and `If-Modified-Since`.

### WordPress and WooCommerce

- WordPress pages are generated by PHP, which does not send an ETag by default. A full-page cache is the practical way to add one, because it serves a stored copy that can carry a stable validator.
- Many cache plugins and host caches handle conditional requests for static files only. Look for a setting that covers HTML pages, or ask your host whether their page cache honors `If-None-Match`.
- If you run nginx in front of a page cache that writes HTML files, `etag on;` (the default) sends ETags for those files and answers 304 automatically.
- Personalized fragments, such as a mini cart rendered into the HTML, change the page on every request and defeat validators. Load them with JavaScript after the page instead.

### Shopify

- Shopify serves storefront pages through its own infrastructure, and you cannot set response headers from a theme. Check the result with the commands below. If the validator is missing or ignored, there is nothing to configure in the admin, and this check is a low-priority finding.

### Any other stack

- Let the framework compute an ETag from the response body, or from a version field such as the product's last update time. Most frameworks offer middleware for this.
- Make sure a 304 answer is actually produced. Some setups send an ETag but never compare it.
- On a CDN, enable conditional request handling for HTML, not only for images and scripts.
- Use strong ETags where you can. Some proxies and compression layers weaken or strip ETags when they change the body, so test through the full chain.

## Verify it yourself

Read the validator from a product page:

```bash
curl -sI https://example.com/product/stoneware-mug/ | grep -iE '^(etag|last-modified)'
```

Then send it back. Replace the value with the ETag you got:

```bash
curl -sI -H 'If-None-Match: "a1b2c3"' https://example.com/product/stoneware-mug/ | head -1
```

The first line should read `HTTP/2 304`. If you only have a Last-Modified date, send it with `If-Modified-Since` instead.

## Common mistakes

- **Validators on assets only.** Images and scripts answer 304, but HTML pages do not. Crawlers care most about the HTML.
- **An ETag that changes every request.** A timestamp, a nonce or a session token in the page makes every ETag new, so nothing ever matches.
- **Sending an ETag but ignoring it.** The header is present, yet the server always answers 200. The scanner warns about exactly this.
- **Compression that strips the ETag.** A layer that gzips responses on the fly may drop or weaken the validator. Test through the CDN, not just the origin.

## FAQ

### What is the difference between ETag and Last-Modified?

An ETag identifies a version of a page with an opaque tag. Last-Modified identifies it by date, with one-second precision. Both let a crawler ask whether the page changed. ETag is more precise, and when both are present, RFC 9110 has `If-None-Match` take precedence.

### Does a 304 answer hurt SEO?

No. A 304 tells the crawler its stored copy is still current. Google's crawler documentation describes using these headers to avoid downloading unchanged content.

### Will a 304 serve stale prices to customers?

Not if the validator changes when the page changes. The server answers 304 only when the version the client holds still matches. Build the ETag from the content or from the product's last update so a price change produces a new one.

### Is this check worth fixing first?

Usually not. It has weight 1 and gates no level. Fix crawler access, server-rendered content and product markup first. Conditional requests are a refinement for large catalogs.
