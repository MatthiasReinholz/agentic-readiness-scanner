## In short

A canonical tells search engines which URL is the real address of a page. When a product page names itself, the index (the search engine's stored copy of the web) holds the page an agent was sent to, and AI answers cite that URL. This check reads the canonical and the hreflang alternates of sampled product pages and fails only when a page has no canonical at all.

## What this check looks at

**rel=canonical** is a link that names the preferred URL for a page. It can sit in the HTML head as a `link` element with `rel="canonical"`, or in the HTTP `Link` response header. Google documents both and treats the canonical as a strong hint about which of several duplicate URLs to index.

Product pages collect duplicates easily. The same product is reachable with and without a trailing slash, with tracking parameters, under a collection path and a plain path, or as a variant URL. A canonical that points every copy to one address keeps the index tidy.

**hreflang** alternates are links with `rel="alternate"` and an `hreflang` language code. They tell search engines which URL serves which language or region. The special value `x-default` names the page to show when no language matches.

For each sampled product page the scanner reads:

- every canonical in the HTML and in the `Link` header
- whether the first canonical is absolute, on the same host, on https when the page is, and equal to the URL that actually answered
- every hreflang alternate, its language code and whether its URL is absolute

The comparison with the page's own URL ignores a fragment and the case of the host name. Path and query must match as written, because `/mug` and `/mug/` are different documents to a crawler.

## Why it matters for AI agents

AI answers link to the URL the index holds. If a product page names a different URL as canonical, the sampled page is treated as a duplicate and the other URL is what gets indexed and cited. When that is intended, for example a parameter URL pointing to the clean one, it is fine. When it is a mistake, such as every product pointing to the home page or to an http address, the products may vanish from the index or be cited under the wrong address.

Missing canonicals leave the choice to the search engine. It may pick a URL with tracking parameters or an old path, and agents then land on a redirect or a stale page.

For stores in several languages, hreflang keeps the German shopper's assistant on the German page with euro prices. Broken alternates send people and agents to the wrong market.

## How the scanner decides

The check needs sampled product pages. When none were found, it is not applicable. When none could be fetched, it is skipped. Problems are reported in this order, and the first one found sets the verdict:

1. **Fail:** a page carries no canonical in the HTML or the `Link` header.
2. **Warn:** a page carries several canonicals that disagree, including an HTML value and a header value that differ.
3. **Warn:** a canonical is a relative URL.
4. **Warn:** a canonical points to another host.
5. **Warn:** a canonical uses http while the page is served over https.
6. **Warn:** a canonical names a different URL than the one that answered. The message names that URL, since it is what gets indexed and what your sitemap should list.
7. **Warn:** hreflang alternates appear on some sampled pages but not others.
8. **Warn:** an hreflang alternate uses a relative URL.
9. **Warn:** a page names fewer than two languages and no `x-default`.

**Pass** means every sampled page has one absolute canonical that names the page itself, and any hreflang set is consistent. The scanner does not fetch the alternate pages, so it cannot confirm that they link back.

The weight is 1, which means nice to have. It gates no level.

## How to fix it

Each product page should carry exactly one canonical: its own final URL, absolute, over https, with the same trailing slash the server uses and without tracking parameters.

### WordPress and WooCommerce

- WordPress core and SEO plugins such as Yoast SEO and Rank Math output a self-referencing canonical on product pages. Check that only one of them does it, since two plugins can print two tags.
- Check the per-product canonical field in your SEO plugin. A value copied from another product makes the page a duplicate.
- Under Settings, General, make sure both URL fields use https so canonicals do not fall back to http.
- Multilingual plugins add hreflang alternates. Check that every language version lists all languages and an `x-default`.

### Shopify

- Shopify themes print the canonical with `canonical_url` in `theme.liquid`. If the tag is missing, add it to the head of the layout.
- Product URLs under a collection path are canonicalised to the plain `/products/` URL by default. That is intended, and the scanner reports it as a different URL only when it sampled the collection path.
- Shopify Markets and translation apps add hreflang alternates. Check for duplicates added by an app on top of the theme's own.

### Any other stack

- Render the canonical from the product's primary URL, not from the request URL, so parameters and alternate paths collapse into one address.
- If you also send a canonical in the `Link` header, make it identical to the HTML value, or drop one of them.
- Generate hreflang from one shared list, so every alternate page carries the same set, with absolute URLs and an `x-default`.

## Verify it yourself

Read both places the canonical can live:

```bash
curl -s https://example.com/products/example | grep -ioE "rel=\"?(canonical|alternate)\"?[^>]*"
curl -sI https://example.com/products/example | grep -i "^link:"
```

Compare the canonical with the URL in your address bar after any redirects. Google Search Console's URL Inspection tool shows which canonical Google selected.

## Common mistakes

- **Two canonicals on one page.** A theme and a plugin each print one, and they disagree on a trailing slash.
- **Pointing every product to the home page or a category.** All those products become duplicates of one page.
- **An http canonical on an https site.** Usually caused by a hard-coded site URL.
- **Relative canonicals.** Google documents absolute URLs as the safe form.
- **hreflang on some templates only.** Products in one language list alternates, others do not, and the set no longer matches.

## FAQ

### Should a product page's canonical point to itself?

Yes, in most cases. A self-referencing canonical confirms the page is the original. Point it elsewhere only when the page really is a duplicate, such as a URL with filter parameters.

### Should product variants have their own canonical?

If each variant has its own URL with mostly the same content, pointing them to the main product URL is common. Make sure your sitemap then lists the main URL, not the variant URLs.

### Do I need hreflang if my store has one language?

No. The scanner only checks hreflang when it finds alternates. A single-language store passes without them.

### Does the scanner check that hreflang pages link back to each other?

No. It reads the sampled pages only and does not fetch the alternates. Use a site crawler that follows the alternates to confirm each page links back to the others.
