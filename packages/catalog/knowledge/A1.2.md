## In short

An XML sitemap is a list of the URLs on your site that you want crawlers to know about. Declaring it in robots.txt and serving it at a standard path lets search crawlers and AI agents enumerate your pages without guessing. This check passes when the scanner finds a sitemap that parses and lists at least one URL or child sitemap.

## What this check looks at

The Sitemaps protocol at sitemaps.org defines two kinds of file:

- A **URL set** lists page URLs, each in its own entry, optionally with the date the page last changed.
- A **sitemap index** lists other sitemap files. Large sites split their URLs across several child sitemaps, for example one for products, one for categories and one for pages.

The protocol also lets you announce a sitemap with a `Sitemap:` line in robots.txt. That line holds the absolute URL of the sitemap or the sitemap index. It is the one place every crawler looks.

The scanner looks for a sitemap in this order:

1. Every `Sitemap:` line in your robots.txt, in the order they appear.
2. `/sitemap.xml`, the conventional location and Shopify's default.
3. `/sitemap_index.xml`, the index that Yoast SEO and Rank Math publish.
4. `/wp-sitemap.xml`, the index WordPress core has generated since version 5.5.

The first candidate that answers HTTP 200 with valid sitemap XML is used. Only sitemaps on the same origin as the store count, because a sitemap on another host does not describe this store. The scanner reads at most four sitemap files per scan, child sitemaps included.

## Why it matters for AI agents

A crawler that only follows links finds what your navigation exposes. Products buried three levels deep, in filtered views or behind a "load more" button may never be reached. A sitemap closes that gap. It is a complete, cheap list of every URL you want known.

Agents that need to enumerate a catalog, rather than answer one question, benefit for the same reason: one request returns the list, where crawling would take hundreds. The [product URL check](/knowledge-base/product-urls-in-sitemap) and the [lastmod check](/knowledge-base/sitemap-lastmod) both depend on this one: without a readable sitemap, neither can run.

The check carries weight 2, the expected tier. It is not a level gate by itself. A product sitemap is one of the ways a store can show that its catalog is enumerable for Level 2, and that requires a sitemap the scanner can read first.

## How the scanner decides

- **Pass:** a sitemap index or URL set was found, parses as sitemap XML, and lists at least one URL or child sitemap.
- **Warn:** a sitemap was found and parses, but lists no URLs and no child sitemaps.
- **Fail:** none of the candidates answered HTTP 200 with parseable sitemap XML.

The report also records whether the sitemap it used is declared in robots.txt. That does not change the verdict, because the fallback paths are checked anyway. It is still worth fixing, because other crawlers may not try those paths.

## How to fix it

Use the sitemap your platform already generates before writing one by hand. A generated sitemap stays current as products are added and removed.

### WordPress and WooCommerce

- WordPress core publishes a sitemap index at `/wp-sitemap.xml`. WooCommerce products appear in it as their own child sitemap.
- Yoast SEO, Rank Math and similar plugins switch the core sitemap off and publish their own index, usually at `/sitemap_index.xml`. Make sure the sitemap feature is enabled in the plugin settings.
- Under Settings, Reading, the option that discourages search engines from indexing the site also disables the core sitemap. Turn it off on a live store.
- Add a `Sitemap:` line to robots.txt for whichever index is active. SEO plugins often add it for you; check the live file.

### Shopify

- Shopify generates a sitemap index at `/sitemap.xml` for every store, with child sitemaps for products, collections, pages and blog posts. There is nothing to switch on.
- Shopify's default robots.txt already declares it. If you customised `robots.txt.liquid`, keep the sitemap line in the template.
- On a store with several domains, check the sitemap on the domain customers actually use. The scanner reads the one on the host it scans.

### Any other stack

- Generate the sitemap from your product database, not from a crawl, so it lists every published product.
- Serve it as plain, uncompressed XML with status 200. Use absolute URLs on the same host as the pages.
- Keep each file under the protocol's limits of 50,000 URLs and 50 MB uncompressed, and use a sitemap index when you need more files.
- Declare the index in robots.txt with its absolute URL.

## Verify it yourself

Find the declared sitemap, then fetch it:

```bash
curl -s https://example.com/robots.txt | grep -i '^sitemap:'
curl -sS -D - https://example.com/sitemap.xml | head -n 30
```

You should see status 200, an XML content type and a body that starts with an XML declaration followed by `urlset` or `sitemapindex`. Google Search Console and Bing Webmaster Tools both report errors for sitemaps you submit to them.

## Common mistakes

- **A sitemap on a different host.** A sitemap served from a CDN or a separate domain is ignored here, because it does not prove anything about the store's own host.
- **A soft 404 at `/sitemap.xml`.** A storefront that answers every unknown path with its home page returns status 200 with HTML. That is not a sitemap.
- **A sitemap that lists nothing.** An index whose child sitemaps were all switched off, or a URL set generated before any products existed, parses fine but helps nobody.
- **A stale robots.txt line.** After changing SEO plugins, robots.txt sometimes still points at the old plugin's index, which now answers 404.

## FAQ

### Where should my sitemap be located?

At a stable URL on the same host as your pages, usually `/sitemap.xml` or the path your platform uses, and declared in robots.txt with a `Sitemap:` line. The declaration matters more than the path.

### Do I need to submit my sitemap to Google and Bing?

Submitting it in Search Console and Bing Webmaster Tools gives you error reports and faster discovery. Declaring it in robots.txt makes it findable for every other crawler and agent, including this scanner.

### Can my sitemap be gzip-compressed?

The protocol allows it, but serve plain XML if you can. The scanner reads uncompressed XML only, and reports a compressed child sitemap as unreadable.

### How many URLs can one sitemap contain?

The Sitemaps protocol allows up to 50,000 URLs and 50 MB uncompressed per file. Beyond that, split the URLs into several files and list them in a sitemap index.
