## In short

The Personal Agent Protocol, called Poppy, is an open draft protocol, published by Sierra, for how personal agents (AI agents acting for a customer) work with companies: through the website, through APIs, or by talking to the company's own agent. A company joins by publishing one file, `/.well-known/poppy.json`. This check reads that file and applies the checks a personal agent applies before it trusts it. The file is optional, so a site without one is not marked down.

## What this check looks at

Poppy's discovery document tells a personal agent how to work with the company: which channels it offers and how customers sign in. The spec is at version 0.4, which its authors call the 1.0 release candidate, and it publishes a JSON Schema for the file.

The check requests `/.well-known/poppy.json` and looks at:

- **Where it was served from.** Every redirect must go to HTTPS, and the last address must be exactly `/.well-known/poppy.json`, with no query. Otherwise anyone able to upload a file somewhere on a domain could make it speak for that domain.
- **Who it speaks for.** `organization.domain` must be the host that served the file, so a copy on another domain cannot speak for the company.
- **The required fields.** `protocol_version` as major.minor, `organization` with a `name`, and at least one channel: `agent` (the company agent's conversation endpoints), `apis` (each with a type such as `openapi` or `mcp`, an HTTPS URL and a description) or `web` (the website).
- **HTTPS everywhere.** Every URL the file names must be HTTPS.
- **The sign-in issuer.** The company's sign-in runs on an OAuth issuer. The check reads the domain's protected resource metadata at `/.well-known/oauth-protected-resource` (RFC 9728) and the issuer's own metadata (RFC 8414). The issuer's metadata must list the domain under `protected_resources`, so no domain can claim another company's issuer.

The check makes at most three requests. It never opens a session or signs in.

## Why it matters for AI agents

Personal agents act for one person: they check an order, start a return or change a booking. Without a shared protocol, every agent needs its own connection to every company. Poppy gives them one: a company describes itself once in `poppy.json`, and any agent that implements the protocol can find its channels and its sign-in.

The checks above are not the scanner's invention. The spec tells personal agents not to use a document that fails them. A file with the wrong domain, a redirect to another path or an issuer that does not list the domain is ignored by every compliant agent, so publishing it achieves nothing.

Poppy is a draft. No major assistant documents reading it from stores yet, which is why the check carries weight 1 and is optional.

## How the scanner decides

- **Pass:** the file meets the spec, and the issuer link holds or the domain has no issuer and the file declares no sign-in. The message names the channels offered and how customers sign in (Direct Sign-In, Device Sign-In, or signed-out sessions only).
- **Fail:** the file breaks a rule a personal agent applies. For example, it is not JSON, a field is missing, `organization.domain` is another host, a URL is not HTTPS, a redirect leaves the well-known path, the file declares sign-in but the domain names no authorization server, or the issuer's metadata does not confirm the domain.
- **Skipped as not applicable:** `/.well-known/poppy.json` answers 404 or 410. The file is optional.
- **Skipped as inconclusive:** a request was rate limited, failed, or is disallowed for the scanner by robots.txt.

The weight is 1, and the check gates no level.

## How to fix it

Only act if you want personal agents to use Poppy. Without a file, nothing is scored.

### WordPress and WooCommerce

- Place `poppy.json` in a `.well-known` folder in the web root, or serve it from a plugin. Make sure security plugins do not block `.well-known`.
- If you offer an MCP server or an OpenAPI description, list it under `apis`. Otherwise declare `web` so agents know they may browse the shop.

### Shopify

- Shopify themes offer no standard way to publish your own files under `/.well-known/`. Shopify exposes stores to agents through UCP and its [agentic storefront](/knowledge-base/shopify-agentic-storefront).

### Any other stack

- Serve the file from the same host as the site, over HTTPS, as `application/json`. If `www.example.com` redirects to `example.com`, set `organization.domain` to `example.com`.
- Start small: `protocol_version`, `organization` and `web` make a valid file for a store whose agents browse as signed-out visitors.
- If the domain already publishes OAuth protected resource metadata, for example for an MCP server, check that its `resource` is exactly `https://{domain}`. Then make the issuer's metadata list `https://{domain}` in `protected_resources`.
- Offer sign-in only with a working issuer: token and revocation endpoints and the `refresh_token` grant.

## Verify it yourself

Fetch the file and look at its organization and channels:

```bash
curl -sL https://example.com/.well-known/poppy.json | jq '{v: .protocol_version, org: .organization, agent, apis, web}'
```

Check the issuer link:

```bash
curl -s https://example.com/.well-known/oauth-protected-resource | jq '{resource, authorization_servers}'
```

## Common mistakes

- **Setting `organization.domain` to the brand's main domain on a country site.** Each domain needs its own file naming itself. Domains that share an issuer form one company.
- **Redirecting the well-known URL to a CMS page.** Agents use only a file served from exactly `/.well-known/poppy.json`.
- **Declaring sign-in without an issuer.** `auth.issuer`, `signed_in` access and the Mediated Sign-In extension all need an authorization server that lists the domain.
- **Plain HTTP URLs in the file.** Every URL Poppy exchanges must be HTTPS.

## FAQ

### What is Poppy?

Poppy, the Personal Agent Protocol, is an open draft protocol published by Sierra for how personal agents work with companies through their websites, APIs and company agents. Customers decide what access their agent gets, and companies set what agents may do.

### Where does poppy.json go?

At `https://{your-domain}/.well-known/poppy.json`, served over HTTPS. A redirect may move it to another host, but only to the same path.

### Do I need OAuth to publish poppy.json?

No. Without an issuer, agents use signed-out sessions: they can browse, read policies or check stock. Sign-in to customer accounts needs an OAuth issuer whose metadata lists your domain.

### Is Poppy the same as UCP?

No. UCP covers commerce, such as checkout. Poppy covers how personal agents find a company, sign customers in and get tasks done across channels, and it can carry checkout through UCP as an extension.
