## In short

This check records how a Salesforce B2C Commerce (Commerce Cloud) storefront is built: rendered by B2C Commerce on its own servers, with the Storefront Reference Architecture (SFRA) or the older SiteGenesis, or served by the Composable Storefront, a React application built with PWA Kit and hosted on Managed Runtime. The result is informational and never scored. It tells you where the fixes from the other checks belong.

## What this check looks at

The check reads the home page the scan already fetched. It makes no extra request.

| Trace                                 | What it shows                                                                 |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| assets under `/mobify/bundle/`        | the Composable Storefront. PWA Kit's runtime serves its bundle from that path |
| assets under `/on/demandware.static/` | a storefront B2C Commerce renders itself: SFRA or SiteGenesis                 |

SFRA and SiteGenesis load their assets the same way, so the page cannot tell them apart, and the check does not try.

The Composable Storefront loads none of B2C Commerce's own asset paths. The scanner therefore also uses the `/mobify/bundle/` path to recognise the platform, so these stores get the Salesforce checks at all ([platform detection](/knowledge-base/ecommerce-platform-detection)).

## Why it matters for AI agents

Agents read the HTML a store serves. SFRA and SiteGenesis render pages on Salesforce's servers. The Composable Storefront renders on the server too, then continues in the browser. Whether a page arrives complete still depends on the build, which [server-rendered content](/knowledge-base/server-rendered-product-content) checks.

The build also decides where a fix goes:

- In SFRA or SiteGenesis, markup, structured data and meta tags live in the ISML templates of the site's own cartridges.
- In the Composable Storefront, the React application renders every page, so fixes go into the PWA Kit project and are deployed as a new bundle.

## How the scanner decides

This check runs only when the scan recognised Salesforce Commerce Cloud. It has weight `info`: it is reported, never scored, and gates no level.

1. Assets under `/mobify/bundle/` mean the Composable Storefront.
2. Otherwise, assets under `/on/demandware.static/` mean a storefront B2C Commerce renders itself.

It always passes when it runs. The fact appears at the top of the report next to the platform, for example "Storefront: Composable Storefront (PWA Kit)". When neither trace is there, no fact is recorded.

## How to fix it

There is nothing to fix. If you want to change the storefront, these are the usual paths.

### Salesforce Commerce Cloud

- **Customising SFRA.** Override templates and scripts in your own cartridge on top of the base cartridge, and never edit the base cartridge itself.
- **Moving to the Composable Storefront.** Check that product pages render prices and structured data on the server, and that the sitemap and robots.txt are still served.

## Verify it yourself

Look for the two asset paths:

```bash
curl -s https://example.com/ | grep -oE '/mobify/bundle/|/on/demandware\.static/' | sort | uniq -c
```

## Common mistakes

- **Expecting SFRA and SiteGenesis to be told apart.** Their pages load assets from the same paths.
- **Reading `/dw/image/` as SFRA.** B2C Commerce's image service serves product images to every storefront, the Composable Storefront included.
- **Assuming the Composable Storefront is invisible to agents.** It renders on the server first.

## FAQ

### How do I know if a Salesforce Commerce Cloud store uses PWA Kit?

Its pages load scripts from `/mobify/bundle/`, the path PWA Kit's runtime serves its bundle from on Managed Runtime.

### Can the scanner tell SFRA from SiteGenesis?

No. Both load their assets from `/on/demandware.static/`, and nothing else on the page reliably separates them.

### Is the Composable Storefront better for AI agents than SFRA?

Not by itself. Both render pages on the server. What agents need is complete HTML with prices, structured data and working links.
