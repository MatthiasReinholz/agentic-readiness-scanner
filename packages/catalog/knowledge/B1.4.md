## In short

An agent can only quote a product it can price, link and confirm in stock. This check reads up to 20 products from the WooCommerce Store API, the public product interface built into WooCommerce, and looks for the fields an agent needs. It fails when any product lacks a name, link, price, currency or stock status, and warns when products lack images or categories. It runs only on WooCommerce stores and has weight 2: expected, not blocking.

## What this check looks at

The [WooCommerce Store API](/knowledge-base/store-api-reachable) returns each product as a JSON object. WooCommerce documents the products endpoint and its fields. The scanner looks at seven of them:

| Field                  | What it holds                   | Missing means |
| ---------------------- | ------------------------------- | ------------- |
| `name`                 | the product name                | fail          |
| `permalink`            | the product page URL            | fail          |
| `prices.price`         | the current price, as a string  | fail          |
| `prices.currency_code` | the currency, for example `EUR` | fail          |
| `is_in_stock`          | true or false                   | fail          |
| `images`               | a list of product images        | warn          |
| `categories`           | a list of product categories    | warn          |

A name, permalink or price counts as missing when it is empty. A stock status counts as missing when it is not a true or false value. Images and categories count as missing when the list is empty.

The scanner requests `/wp-json/wc/store/v1/products?per_page=20`, the first page of 20 products in the API's default order. It does not read the whole catalog.

## Why it matters for AI agents

Agents answer questions like "where can I buy this in stock under 50 euros?". Every part of that answer needs a field. Without a price there is no offer. Without a currency the number means nothing. Without a stock status the agent cannot say whether the product is available. Without a permalink it cannot send the buyer anywhere.

Images and categories matter less but still help. An image lets an assistant show what it found. Categories let an agent tell a mug from a mug warmer and place the product in the right comparison.

These are the same gaps that weaken a product page for people. Fixing them in WooCommerce fixes them everywhere WooCommerce publishes the product, including the shop pages and any feed built from the same data.

A passing check means the sampled products are complete in the API. It does not mean an agent will recommend or buy them.

## How the scanner decides

This check runs only on WooCommerce stores. On other platforms it does not run and reports leave it out. It also needs [the Store API to be reachable](/knowledge-base/store-api-reachable): when that check fails, this one is skipped.

- **Skipped as inconclusive** when the product list answers 429, 502, 503 or 504, or does not answer. A rate limit or a gateway error says nothing about the products.
- **Fail** when the product list does not answer 200 with a JSON list of products.
- **Fail** when the list is empty, because there is nothing to check.
- **Fail** when any sampled product lacks a name, permalink, price, currency code or stock status. An entry without a name and permalink as text counts as incomplete too.
- **Warn** when every product has those fields but some lack images or categories.
- **Pass** when all sampled products carry every field.

The report lists each incomplete product by ID and name with the fields it lacks, so you can go straight to it.

## How to fix it

Fix the data in WooCommerce, not in the API. The Store API only shows what the products contain.

### WordPress and WooCommerce

- **Find the gaps.** Under Products, All Products, sort or filter by price and stock. Products with an empty price show no price in the list. The image column shows a placeholder where no image is set.
- **Missing prices.** A simple product needs a regular price on the General tab. A variable product (one sold in variations, such as sizes or colours) needs a price on each variation. A product with no price cannot be bought in the shop either.
- **Stock status.** Set it on the Inventory tab, or enable stock management so WooCommerce derives it from the quantity.
- **Images.** Set a product image on every product. A gallery is optional.
- **Categories.** WooCommerce puts products without a category in "Uncategorized" by default. Products that end up with no category at all usually come from imports or custom code. Assign a real category to each.
- **Bulk fixes.** For many products, export them to CSV under Products, Export, fill the gaps from your supplier data, and import the file again. The built-in importer updates existing products when you choose that option.
- **Plugins that change the API.** If prices exist in the admin but not in the API, a plugin may hide prices for logged-out visitors, for example a wholesale or "price on request" plugin. That hides them from agents too.

### Any other stack in front of WooCommerce

- If product data comes from an ERP (business management system), a PIM (product information management system) or a supplier feed, fix the mapping there so every sync writes price, stock status, image and category.
- Run a scheduled script against the Store API that lists products with empty fields, and alert on new gaps before customers or agents see them.

## Verify it yourself

List the first 20 products with the fields this check reads and spot the gaps. This uses `jq`, a common command-line JSON tool:

```bash
curl -s 'https://example.com/wp-json/wc/store/v1/products?per_page=20' | jq -r '.[] | [.id, .name, .prices.price, .prices.currency_code, .is_in_stock, (.images|length), (.categories|length)] | @tsv'
```

Every row should show a price, a currency, `true` or `false`, and counts above zero for images and categories. Change `per_page` and add `&page=2` to look further into the catalog.

## Common mistakes

- **Prices hidden from guests.** A plugin that shows prices only to logged-in customers removes them from the Store API for agents.
- **Variable products without variation prices.** The parent product looks fine in the admin, but no variation has a price.
- **Imports that skip images.** A CSV import with broken image URLs leaves products without images and reports no error.
- **Only fixing the first page.** The scanner samples 20 products. The rest of the catalog may have the same gaps, so audit all of it.

## FAQ

### Why does the Store API show no price for my product?

Either the product has no price set, which is common for variable products whose variations have no price, or a plugin hides prices from visitors who are not logged in. The Store API answers as an anonymous visitor, so it shows what such a visitor would see.

### What format are Store API prices in?

They are strings, and WooCommerce's documentation shows them in the currency's smallest unit, with `currency_minor_unit` saying how many decimal places to apply. For example, `1105` with a minor unit of 2 is 11.05. The check only tests that a price and a currency are present.

### Does the scanner check every product?

No. It reads the first page of up to 20 products from the Store API. A pass means those products are complete, not the whole catalog. Use the command above with more pages to audit the rest.

### Are "Uncategorized" products a problem?

They pass this check, because the category list is not empty. But "Uncategorized" tells an agent nothing about the product. Assigning a real category is a quick improvement.
