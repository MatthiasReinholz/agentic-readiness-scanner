## In short

This check records how a WordPress site is built: a block theme, a classic theme, or a headless front end that only reads WordPress for its content. It also names the theme, any child theme and the page builder. The result is informational and never scored, because none of these choices makes a site better or worse for agents by itself. It tells you where the fixes from the other checks belong.

## What this check looks at

WordPress has two kinds of theme. A **block theme** builds every template from blocks, which you edit in the Site Editor. A **classic theme** builds its templates in PHP files, edited in code or through the Customizer. WordPress treats a theme as a block theme when it has a `templates/index.html` file.

A **headless** site uses WordPress only as a content store. Its pages come from a separate front-end application, often built with a JavaScript framework such as Next.js, that reads WordPress through its API.

The check reads the home page the scan already fetched and looks for these traces:

| Trace                                                           | What it shows                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| a `<div class="wp-site-blocks">` element                        | WordPress's block template canvas rendered the page: a block theme                    |
| `currentThemeIsFSETheme` in WooCommerce's settings script       | WooCommerce's own answer to "is this a block theme"; it wins when present             |
| a `wp-theme-<name>` body class                                  | the theme, or the parent theme when a child theme is active (WordPress 6.8 and later) |
| a `wp-child-theme-<name>` body class                            | the active child theme                                                                |
| assets under `/wp-content/themes/<name>/`                       | the theme, on sites without the body class                                            |
| a builder's body class or asset folder                          | Elementor, Divi, Beaver Builder, WPBakery or Bricks                                   |
| a framework's own markers, such as `__NEXT_DATA__` or `/_nuxt/` | a headless front end, when no theme rendered the page                                 |

It makes no extra request.

## Why it matters for AI agents

Agents read the HTML a site serves. Block themes and classic themes both render pages on the server, so both can serve complete product pages to an agent that does not run JavaScript. The theme type does not decide that; the theme's templates do. That is why this check is not scored.

The build still matters when something needs fixing:

- In a block theme, structured data, headings and links live in templates and template parts.
- In a classic theme, they live in PHP templates and hooks, ideally in a child theme so an update does not overwrite them.
- A page builder usually renders headers, product pages and footers itself. It often adds a lot of markup, which [page weight](/knowledge-base/page-weight-crawler-limits) measures.
- A headless front end renders every page itself. Whether agents see the content depends on whether it renders on the server, which [server-rendered content](/knowledge-base/server-rendered-product-content) checks. Fixes go into the front-end application, not into WordPress.

## How the scanner decides

This check runs only when the scan recognised WordPress or WooCommerce (see [platform detection](/knowledge-base/ecommerce-platform-detection)). It has weight `info`: it is reported, never scored, and gates no level.

1. When WooCommerce's settings script states `currentThemeIsFSETheme`, that decides block or classic.
2. Otherwise, a `wp-site-blocks` element means a block theme.
3. Otherwise, a page rendered by a recognisable theme (body class or theme folder) means a classic theme.
4. A home page that shows no theme at all but a JavaScript framework's markers is a headless front end.

It always passes when it runs. The facts appear at the top of the report next to the platform, for example "Theme: Block theme (twentytwentyfive)" or "Front end: Headless (Next.js)". A fact the page does not show is left out.

## How to fix it

There is nothing to fix. If you want to change how the site is built, these are the usual paths.

### WordPress and WooCommerce

- **Classic to block theme.** Install a block theme on a staging copy, rebuild the header, footer and shop templates in the Site Editor, and compare the product pages before switching. Structured data that the old theme printed must be printed again.
- **Block theme to classic.** The reverse: a classic theme takes over and the Site Editor templates no longer apply.
- **Page builder.** Builders render their own templates. Check product pages after builder updates, because a template change can drop prices or structured data.
- **Headless.** Make sure the front end renders product content, prices and structured data on the server.

## Verify it yourself

Look for the block template wrapper and the theme body classes:

```bash
curl -s https://example.com/ | grep -oE 'class="wp-site-blocks"|wp-(child-)?theme-[A-Za-z0-9_-]+|/wp-content/themes/[A-Za-z0-9._-]+/' | sort | uniq -c
```

In the admin, Appearance > Themes shows the active theme. If Appearance > Editor opens the Site Editor, the theme is a block theme.

## Common mistakes

- **Reading the wp-site-blocks CSS as a block theme.** WordPress also prints `.wp-site-blocks` rules in stylesheets for classic themes that have a `theme.json`. Only the element counts.
- **Expecting the body class on older sites.** The `wp-theme-` classes came with WordPress 6.8. Older sites, and themes that filter body classes, are recognised by their theme folder instead.
- **Assuming a headless site is invisible to agents.** A headless front end that renders on the server can serve complete pages; one that renders in the browser cannot.

## FAQ

### How do I know if my WordPress theme is a block theme?

A block theme has a `templates/index.html` file, and Appearance > Editor opens the Site Editor. On the live site, a block theme wraps every page in a `<div class="wp-site-blocks">` element.

### Is a block theme better for AI agents than a classic theme?

Not by itself. Both render pages on the server. What agents need is complete HTML with prices, structured data and working links, and either kind of theme can deliver or miss that.

### Why does the report say my site is headless?

The home page showed no WordPress theme, but it carried the markers of a JavaScript framework such as Next.js or Nuxt. That is how a separate front end that reads WordPress for its content looks.

### Why is no theme name shown?

The site runs a WordPress version before 6.8, or the theme removes the body classes, and no asset loads from the theme's folder. The kind of theme can still be recognised from the page.
