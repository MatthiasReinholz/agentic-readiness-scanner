## In short

Product JSON-LD is a block of structured data in the page that states, in a fixed vocabulary, what the product is. Search engines and the systems built on them read it to understand a product page without guessing. This check passes when every sampled product page carries a schema.org Product or ProductGroup node with a name and an image. It is a blocking check and a Level 2 gate.

## What this check looks at

JSON-LD (JavaScript Object Notation for Linked Data) is a way to embed structured data in a script tag of type `application/ld+json`. The vocabulary comes from schema.org, which defines types such as `Product`, `ProductGroup`, `Offer` and `Brand`.

The scanner reads every JSON-LD block on a sample of your product pages. Blocks may be single objects, arrays or `@graph` lists; all are flattened. It then looks for nodes whose `@type` is `Product` or `ProductGroup` and checks two properties:

- **`name`**: the product's name.
- **`image`**: at least one image URL, as a string, an array or an `ImageObject`.

Google's merchant listing documentation names `name`, `image` and `offers` as required. The `offers` part is checked separately by the [Offer check](/knowledge-base/offer-price-currency-availability). On a ProductGroup page, a name or image on any of the variants counts.

## Why it matters for AI agents

Product markup is the most direct statement a page can make about what it sells. Its documented uses are concrete:

- Google uses Product markup for product rich results and merchant listings, including free listings.
- Google Merchant Center can use structured data on your pages for automatic product updates and submission.
- Bing reads structured data as grounding for its results.

Be precise about the limits. Google says its AI Overviews and AI Mode need no special markup beyond an indexed page that is eligible for a snippet. ChatGPT shopping reads feeds and third-party data. So Product markup is not a ticket into every AI answer. It is the shared, machine-readable baseline that Google's shopping surfaces and Bing build on, and that any agent can parse without guessing.

That is why the check carries weight 3, blocking. It is a gate for Level 2 "Readable catalog" and every level above. Every other check in this group builds on it.

## How the scanner decides

- **Pass:** every sampled product page has a Product or ProductGroup node, and every one of them has a `name` and an `image`.
- **Warn:** some sampled pages have Product markup and others do not. A store where every page has markup but some lack `name` or `image` also gets a warning, and the report names the missing property and the page.
- **Fail:** no sampled product page has a Product or ProductGroup node.
- **Skip:** no product pages were sampled, or none of them could be fetched.

The evidence lists, per page, the number of Product nodes, their types, the missing properties, and any JSON parse errors. A block with a syntax error is ignored, so a parse error often explains a missing node.

## How to fix it

Output exactly one Product (or ProductGroup) description per page, generated from the same data that renders the page.

### WordPress and WooCommerce

- WooCommerce core outputs Product JSON-LD on single product pages. It includes name, image, description, SKU and offers.
- SEO plugins such as Yoast SEO with its WooCommerce add-on, or Rank Math, replace or extend that markup. Pick one source. Two Product blocks for one product confuse validators.
- If a theme or page builder removes the core output, restore it. Developers can adjust the core markup through the `woocommerce_structured_data_product` filter.
- Make sure each product has a featured image. Without one, the markup has no `image`.

### Shopify

- Most current Shopify themes output Product JSON-LD on product templates, often through Liquid's `structured_data` filter. For products with variants it emits a ProductGroup with each variant as a Product.
- Older or heavily customised themes may have dropped it. Open Online Store, Themes, Edit code, and look in the product section or snippet for an `application/ld+json` script.
- If an SEO app adds its own Product markup, disable either the app's or the theme's so only one remains.

### Any other stack

- Render the JSON-LD on the server, in the initial HTML. Markup injected later by JavaScript may be missed by crawlers that do not run scripts.
- Use absolute URLs for `image` and `url`.
- Use `ProductGroup` for a product with variants and `Product` for a single item. The [variants check](/knowledge-base/product-variants-markup) covers the group structure.

A minimal valid node needs little more than this. The fix snippet on this page shows a fuller example.

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Stoneware Mug, 350 ml",
  "image": ["https://example.com/images/mug-1200.jpg"]
}
```

## Verify it yourself

Paste a product URL into Google's [Rich Results Test](https://search.google.com/test/rich-results). It shows whether the page is eligible for product results and lists missing required fields. The [Schema Markup Validator](https://validator.schema.org/) shows every schema.org node on the page, including ones Google ignores.

From the command line, list the types on a page:

```bash
curl -s https://example.com/product/stoneware-mug/ | grep -o '"@type": *"[A-Za-z]*"' | sort | uniq -c
```

## Common mistakes

- **Two competing Product blocks.** WooCommerce core and an SEO plugin both output markup, often with different prices.
- **Markup only on some templates.** A custom template for one category drops the JSON-LD that the default template has.
- **Broken JSON.** A stray comma or an unescaped quote in a product description makes the whole block unreadable.
- **Client-side only markup.** A tag manager injects the JSON-LD after load, and the server HTML has none.
- **A relative image path.** `"image": "/uploads/mug.jpg"` should be an absolute URL.

## FAQ

### Do I need Product schema to appear in Google AI Overviews?

Google says AI Overviews and AI Mode need no special structured data beyond an indexed page that can show a snippet. Product markup is what Google's merchant listings and product rich results use, and it gives every agent a reliable reading of the page.

### Should I use Product or ProductGroup?

Use Product for an item with no variants. Use ProductGroup when one page sells several variants, such as sizes or colours, and list each variant as a Product under `hasVariant`. The scanner accepts both.

### Is microdata or RDFa accepted instead of JSON-LD?

Google accepts all three formats. This check reads JSON-LD only, because it is the format Google recommends and the one agents parse most easily.

### Why does the check warn when every page has markup?

At least one page lacks `name` or `image`. Google requires both for merchant listings. The report names the page and the missing property.
