## In short

WordPress has a setting under Settings, Reading called "Search engine visibility". When it is ticked, every page carries a `noindex, nofollow` robots tag and the core sitemap is turned off. This check reports whether your WordPress home page asks search engines not to index it, so you can untick the setting, or the SEO plugin rule that does the same, once the site is live.

## What this check looks at

The setting is meant for sites that are still being built. Its label reads "Discourage search engines from indexing this site". WordPress documents two effects when it is ticked:

- Core prints `<meta name='robots' content='noindex, nofollow' />` in the head of every page, through the function `wp_robots_no_robots()`.
- The core sitemap at `/wp-sitemap.xml`, added in WordPress 5.5, is turned off.

Since WordPress 5.3 the setting no longer adds `Disallow: /` to the virtual robots.txt. So robots.txt can look normal while every page asks not to be indexed.

SEO plugins can set noindex as well, for the whole site or for the home page alone. The check sees the result, whichever of them printed it.

The check reads two signals on the home page, both from the response the scan already fetched:

- the robots meta tag in the HTML head
- the `X-Robots-Tag` response header

## Why it matters for AI agents

A noindex tag asks search engines to keep the page out of their index. Google and Bing honour it. Their indexes are what many AI answers draw on, such as Google's AI Overviews and Microsoft Copilot. A store that is not in the index is rarely named or linked in those answers.

The missing sitemap adds to the problem. Crawlers lose the list of URLs that helps them find your product pages.

The setting is easy to forget. It is often ticked during a build or on a staging copy, and then carried over when the site goes live.

## How the scanner decides

The check runs only when the scan recognised WordPress, WooCommerce stores included (see [platform detection](/knowledge-base/ecommerce-platform-detection)). On other platforms it is skipped and left out of the report. It makes no extra request.

- **Fail:** the robots meta tag or the `X-Robots-Tag` header of the home page contains `noindex` or `none`. The message says whether the tag is exactly `noindex, nofollow`, the tag WordPress core prints for the setting. Any other noindex points to an SEO plugin, the theme or custom code.
- **Pass:** neither signal carries `noindex` or `none`.

An `X-Robots-Tag` header aimed at one named crawler, such as `bingbot: noindex`, is ignored. It is not a site-wide setting. The check looks at the home page only, so a noindex on single product or category pages is not reported here.

The weight is 1, which means nice to have. It is not a gate for any level.

## How to fix it

Untick the core setting, then check that nothing else still prints noindex.

### WordPress and WooCommerce

1. In the WordPress admin, open Settings, Reading.
2. Untick "Discourage search engines from indexing this site" under Search engine visibility, then save.
3. If you use an SEO plugin, open its settings and look for a site-wide noindex option and for the home page's own robots setting. Switch noindex off for both.
4. Search the theme and any custom plugin for code that filters `wp_robots` or prints a robots meta tag directly.
5. Check the server or CDN configuration for an `X-Robots-Tag: noindex` header left over from a staging setup.

Once the core setting is off, WordPress also serves its sitemap again, unless an SEO plugin replaces it with its own.

## Verify it yourself

Look for the robots meta tag and the header on your home page:

```bash
curl -s https://example.com/ | grep -i 'name=.robots'
curl -sI https://example.com/ | grep -i x-robots-tag
```

No output, or a value without `noindex` and `none`, is what you want. Then check that the core sitemap answers:

```bash
curl -sI https://example.com/wp-sitemap.xml
```

An HTTP 200 means the core sitemap is on. An SEO plugin may serve its own sitemap at another path instead. Rescan to confirm.

## Common mistakes

- **Unticking the box but keeping the plugin rule.** An SEO plugin can print its own noindex. Check both places.
- **Copying a staging site to production.** The setting is stored in the database, so it travels with a database copy.
- **Checking only robots.txt.** Since WordPress 5.3 the setting leaves robots.txt alone. The noindex lives in the HTML head.
- **Caching the old page.** A page cache or CDN may keep serving the noindex tag after you change the setting. Clear the cache.

## FAQ

### What does "Discourage search engines from indexing this site" do?

It makes WordPress print a `noindex, nofollow` robots meta tag on every page and turns off the core sitemap. Search engines that honour the tag, such as Google and Bing, keep the site out of their index.

### Does the setting block crawlers in robots.txt?

Not since WordPress 5.3. The setting now works through the robots meta tag only, so robots.txt can look normal while the site asks not to be indexed.

### Why does my WordPress site still say noindex after I unticked the setting?

Another source is still printing it. The usual causes are an SEO plugin's noindex option, a theme or plugin filter on `wp_robots`, a server header, or a cached copy of the page.

### Does a noindex keep my store out of AI answers?

It keeps the site out of the Google and Bing indexes, which many AI answers draw on. An assistant may still open a page when a person pastes the link, but it is much less likely to find or cite your store on its own.
