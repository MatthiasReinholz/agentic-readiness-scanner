## In short

Every Shopify Online Store answers `/products.json` with a JSON list of its published products. It is the simplest way for an agent to read a Shopify catalog without an account. This check requests it and passes when it returns a products array. It applies only to Shopify stores.

## What this check looks at

Shopify storefronts expose a few JSON endpoints next to the theme pages. Shopify's Ajax API documents the per-product form, `/products/{handle}.js`, which returns one product. The catalog-wide `/products.json` is not documented, but every Online Store theme has served it for years. It returns products with their handles, titles, variants, prices and images.

The scanner requests `/products.json?limit=5`. Five products are enough to prove the endpoint works without loading the full catalog.

Shopify now also points agents at a second, documented route. Its generated robots.txt and agents.md name the Universal Commerce Protocol (UCP) catalog at `/api/ucp/mcp`. The [agentic storefront check](/knowledge-base/shopify-agentic-storefront) covers that endpoint.

## Why it matters for AI agents

An agent asked to find a product in a store needs a list of what the store sells. On Shopify, products.json gives that list as structured data in one request. Without it, the agent must crawl the theme, parse HTML and guess which page is a product.

When products.json answers with a password page or an error, the agent learns nothing about the catalog from it. If the store is password-protected, nothing else on the storefront is readable either.

This check has weight 2, expected. It is one of the alternatives for the Level 2 "Readable catalog" gate. The UCP catalog, a product sitemap or a public feed meets that gate as well. A store that passes the agentic storefront check has a readable catalog even if products.json is blocked.

## How the scanner decides

The check runs only when the [platform detection check](/knowledge-base/ecommerce-platform-detection) found Shopify.

- **Skip** when the store is not Shopify.
- **Skip** when the storefront is headless: the domain only loads Shopify assets and is rendered by another system. Shopify serves neither products.json nor the UCP endpoint on such a domain.
- **Skip** when the endpoint answers HTTP 429. Shopify rate-limits this endpoint per IP address after a few requests, so the result says nothing about readability. The scanner retries once after `Retry-After` before it gives up.
- **Warn** when the store's own robots.txt disallows `/products.json` for the scanner. The scanner respects robots.txt, so it could not verify the endpoint.
- **Fail** on HTTP 401 or 404, on the storefront password page, on any HTML page instead of JSON, on a body that is not JSON, and on JSON without a `products` array.
- **Pass** on HTTP 200 with a `products` array.

When the answer is HTML, the evidence records the page title and a likely cause. A 403 usually means a CDN or bot manager refused the request. A 200 with HTML usually means a redirect to a theme page or a bot challenge.

## How to fix it

### Shopify

- **Remove the storefront password once the store is live.** Go to Online Store, Preferences, and turn off password protection. While it is on, products.json and every other page answer with the password page.
- **Check apps that touch routing.** Apps that redirect, localise or protect the storefront can intercept `/products.json`. Disable them one at a time and request the endpoint after each change.
- **Check a proxy or CDN in front of Shopify.** A firewall rule or bot manager on a custom proxy can block JSON requests or serve a challenge. Allow the path for honest, identified clients.
- **Review robots.txt.liquid.** If the theme template disallows `/products.json`, well-behaved agents will not request it. Remove that rule unless you mean to block it.
- **Publish products to the Online Store channel.** products.json lists only products available on the Online Store sales channel. A product published only to other channels will not appear.
- **For a headless storefront**, publish a public catalog on your own domain instead. A Google-format feed linked with a rel=alternate link tag works, as does the Storefront API with a public access token documented in llms.txt. The [public product feed check](/knowledge-base/public-product-feed) covers the feed route.

Shopify's own robots.txt points agents at the UCP catalog. Making sure that endpoint works is the more future-proof step, and the agentic storefront check covers it.

## Verify it yourself

Request the endpoint and count the products:

```bash
curl -s "https://example.com/products.json?limit=5" | jq '.products | length'
```

A number means it works. A `jq` parse error means the answer was HTML. Look at the status and content type:

```bash
curl -sI "https://example.com/products.json?limit=5"
```

Expect `HTTP/2 200` and `content-type: application/json`. If you request it many times in a row you may get HTTP 429. Wait a minute and try again.

## Common mistakes

- **Testing while logged in to the admin.** A store owner can preview a password-protected store. An anonymous agent sees only the password page. Test in a private window or with curl.
- **Blaming the theme.** The endpoint does not depend on the theme's templates. If it fails, look at apps, proxies and the password setting first.
- **Reading a 429 as a failure.** The rate limit is per IP and expected. It does not mean the endpoint is off.
- **Expecting the whole catalog in one request.** The endpoint returns a limited page of products. Agents page through it.
- **Running headless and expecting products.json on your domain.** It exists only on the Shopify-served storefront domain.

## FAQ

### Is Shopify's products.json an official API?

Not officially. Shopify documents `/products/{handle}.js` in its Ajax API but not the catalog-wide `/products.json`. It is a long-standing convention of Online Store themes. For a documented route, use the UCP catalog or the Storefront API.

### Why does my Shopify products.json return 404?

Usually an app or a proxy rewrites the route, or the domain is a headless front end that Shopify does not serve. Disable routing apps and bypass any proxy one step at a time to find which layer answers the 404.

### Can I hide products.json without hurting agents?

You can, but agents then need another route to your catalog. Make sure the UCP catalog, a product sitemap or a public feed is available. Any of them keeps the Level 2 gate met.

### Does products.json expose private data?

It exposes the same product data your storefront shows: titles, descriptions, prices, variants and images of published products. It does not include cost prices, inventory counts by location or customer data.
