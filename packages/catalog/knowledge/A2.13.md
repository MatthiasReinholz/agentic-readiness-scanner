## In short

A robots.txt rule only reaches a crawler that reads its name. Several names that block lists still copy around are not used by any crawler today: some were renamed, others were never documented by the company they are attributed to. This check finds groups for those names and warns when the company's current crawler names are missing, because then the rule does nothing.

## What this check looks at

robots.txt is made of groups. Each group starts with `User-agent` lines that name crawlers by their product token, such as `ClaudeBot`. A crawler follows the group that names its own token. If none does, it follows the `User-agent: *` group. It never reads a group written for another name.

The scanner keeps a registry of the tokens each operator documents, with the date each entry was last checked. It also lists names that robots.txt files still use although the operator documents them no longer, or never did: renamed tokens, such as Google-NotebookLM, and names found only in third-party block lists, such as anthropic-ai and claude-web. Each outdated name is paired with the tokens its operator documents today. The list is under "Crawlers this check reads" on this page, and the whole registry, with links to each operator's documentation, is on the [crawler registry page](/knowledge-base/crawlers).

## Why it matters for AI agents

A site owner who writes `User-agent: anthropic-ai` and `Disallow: /` believes Anthropic's crawlers stay out. Anthropic's documentation names ClaudeBot, Claude-SearchBot and Claude-User, so none of them reads that group. They follow the `*` group instead, which usually allows everything. The rule records an intent that no crawler sees.

The reverse happens too. A group that allows an old name on paths the `*` group disallows opens nothing for the current crawler. Either way the file says one thing and the crawlers do another.

## How the scanner decides

The scanner compares every `User-agent` name in robots.txt, without regard to case, with the outdated names in the registry.

- **Pass:** no outdated name appears, or each outdated name sits next to at least one of its operator's current tokens. The message notes the old names.
- **Pass with a note:** the name belongs to an operator that runs no crawler, such as Cohere. The group has no effect, which does no harm.
- **Warn:** robots.txt names an outdated token but none of that operator's current tokens. The message lists the tokens to add.
- **Not applicable:** the site has no robots.txt.

This check has weight 1 and gates no level. It does not judge whether you allow or block a crawler. The [training-crawler check](/knowledge-base/ai-training-crawler-policy), the [search crawler check](/knowledge-base/search-and-assistant-crawlers-allowed) and the [user-triggered fetcher check](/knowledge-base/user-triggered-fetchers-allowed) judge that, for the current tokens.

## How to fix it

Add the current tokens to the same group as the old name. The group keeps its rules and now reaches the crawlers that exist. Before you copy a training block onto a search or user-triggered token, decide whether you want that: `Disallow: /` for Claude-SearchBot or Claude-User removes the site from Claude's answers, not only from training.

```robots
# Training only: the old names plus the current training token
User-agent: anthropic-ai
User-agent: claude-web
User-agent: ClaudeBot
Disallow: /
```

### WordPress and WooCommerce

- Edit robots.txt in your SEO plugin's editor, or in the physical `robots.txt` in the web root if one exists.
- "Block AI bots" plugins often ship old lists. Update the plugin, or replace its rules with your own groups.

### Shopify

- Shopify builds robots.txt from the theme template `robots.txt.liquid`. Open it under Online Store, Themes, Edit code, and add the current tokens to the group that names the old one.

### Any other stack

- Edit robots.txt where your server or platform generates it.
- On Squarespace, the "Block known artificial intelligence crawlers" setting writes Squarespace's own list, which includes some old names next to current ones. The list is maintained by Squarespace.

## Verify it yourself

Fetch your robots.txt and look for the old names:

```bash
curl -s https://example.com/robots.txt | grep -inE "anthropic-ai|claude-web|facebookbot|mistralbot|cohere|notebooklm"
```

For each match, check that the operator's current tokens appear in the same group. Then rescan.

## Common mistakes

- **Copying a block list without checking the names.** Many lists online mix documented tokens with names seen in logs or guessed. A name no crawler reads is dead weight at best.
- **Assuming user-agent matching is fuzzy.** RFC 9309 matches the product token, not a substring. `Claude` does not match `ClaudeBot`.
- **Replacing a training block with a blanket block.** Adding Claude-SearchBot and Claude-User to a `Disallow: /` group also removes the site from Claude's search and answers.

## FAQ

### Is anthropic-ai still Anthropic's crawler?

Anthropic's crawler documentation lists ClaudeBot, Claude-SearchBot and Claude-User. It does not list anthropic-ai or claude-web, so a group for those names reaches none of Anthropic's documented crawlers.

### Should I delete the old names?

You can, but you do not have to. Once the current tokens are in the same group, the old names do no harm.

### Why does Cohere appear if it runs no crawler?

Many block lists name cohere-ai. Cohere states that it does not run crawlers at this time, so those groups have no effect. The check passes and says so.

### How does the scanner know which names are current?

Every token in its registry links to the operator's own documentation and carries the date it was last checked. Names that appear only in third-party lists are not treated as crawlers.
