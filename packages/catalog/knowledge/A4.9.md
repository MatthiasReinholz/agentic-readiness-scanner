## In short

From version 6.7.12, Shopware core can publish three agentic files for a storefront: `/llms.txt`, `/agents.md` and `/.well-known/ai-catalog.json`. Each is switched on per sales channel, Shopware's name for a storefront with its own domain, language and catalog. This check requests `/.well-known/ai-catalog.json` and passes when it returns a JSON object. It runs only on Shopware stores and carries weight 1, nice to have. It never fails: a missing file is a warning.

## What this check looks at

Shopware's developer documentation describes the agentic files as a core feature since 6.7.12. Each sales channel can publish them on its own domain:

- `/llms.txt`, a Markdown summary of the site for language models.
- `/agents.md`, a Markdown file with guidance for AI agents.
- `/.well-known/ai-catalog.json`, a machine-readable discovery catalog in JSON. For a headless sales channel (one used through the API, without Shopware's storefront), the documentation says it can list the Store API MCP server.

Shopware renders the files from Twig templates, its template language. Merchants can add their own notes on the sales channel's detail page in the Administration, and extensions can add to the templates. A file that is switched off answers 404 like any unknown URL.

The scanner requests only `ai-catalog.json`, because it is the one file a program can check without guessing. The [MCP server discovery check](/knowledge-base/mcp-server-discovery) reads the same path for a different purpose: it looks there for an MCP server entry.

## Why it matters for AI agents

The agentic files give an agent a short, stable description of the store in a place it can find without crawling. On Shopware they cost nothing but a setting, because core generates them.

No major assistant documents reading these files yet. That is why the check is weight 1 and why a missing file is a warning, not a fail. Treat it as cheap preparation.

Passing shows that the files are published. It does not check that their content is accurate or complete. Review what Shopware generates before you rely on it.

## How the scanner decides

This check runs only on Shopware stores, when the [platform detection check](/knowledge-base/ecommerce-platform-detection) found the platform. Reports for other platforms do not show it.

The scanner sends one request with `Accept: application/json`:

```http
GET /.well-known/ai-catalog.json
```

- **Pass:** HTTP 200 with a JSON object. The report lists the first keys of the object.
- **Warn:** HTTP 404. The catalog file is switched off for the sales channel, or the shop runs a Shopware version before 6.7.12.
- **Warn:** any other answer that is not a JSON object, such as an HTML page, a redirect to the home page or a JSON array.
- **Warn:** robots.txt disallows the path for the scanner's user agent. The scanner honours robots.txt, so it did not ask.
- **Skipped:** HTTP 429, a gateway error (502, 503 or 504) or no response at all.

## How to fix it

Check the version first, then the setting.

### Shopware

- **Check your Shopware version.** The agentic files are part of core from 6.7.12. On an older version, plan the update to the current 6.7 release before anything else.
- **Switch the files on for the storefront sales channel.** Open the sales channel's detail page in the Administration and find its agentic files settings, as described in the Shopware developer documentation. Switch on all three files, including `ai-catalog.json`, and save. Repeat for every storefront sales channel you want agents to read.
- **Purge a CDN or reverse proxy** in front of the shop if it still serves the old 404. Shopware handles its own cache invalidation for these files.
- **Review the generated content.** Open all three files and check that they describe your store, catalog and policies correctly. Add notes on the sales channel's detail page, or adapt the templates in a theme or plugin.
- **Check robots.txt and any proxy.** Make sure neither blocks `/.well-known/`, `/llms.txt` or `/agents.md`.

Shopware 6.7 storefronts still ship schema.org microdata for products. JSON-LD sits behind a feature flag and becomes the default in Shopware 6.8, according to the 6.8 upgrade notes. That is a separate topic from the agentic files.

## Verify it yourself

Print the status code of each file:

```bash
for path in /llms.txt /agents.md /.well-known/ai-catalog.json; do
  printf '%s ' "$path"
  curl -s -o /dev/null -w '%{http_code}\n' "https://example.com$path"
done
```

All three should answer 200. Then check that the catalog file is a JSON object:

```bash
curl -s https://example.com/.well-known/ai-catalog.json | jq 'type'
```

The second command should print `"object"`.

## Common mistakes

- **Switching the files on for one sales channel only.** Each storefront sales channel has its own settings.
- **Enabling only some of the files.** Each file has its own switch. The console command `sales-channel:file:enable`, available from 6.7.17, creates `llms.txt` and `AGENTS.md` but not the catalog, so this check still warns.
- **An old 404 cached at the edge.** A CDN can keep serving the 404 after you switch the files on. Purge it.
- **Publishing without reading.** Generated text can be out of date or incomplete. Read it as an agent would.
- **Looking for the setting on an older version.** Before 6.7.12, core does not have the feature.

## FAQ

### Which Shopware version publishes agentic files?

Shopware 6.7.12 and later. On older versions the files do not exist in core.

### Where do I switch on Shopware's agentic files?

Per sales channel, in the sales channel's agentic files settings on its detail page in the Administration, as the Shopware developer documentation describes. Each file has its own switch.

### Why does /.well-known/ai-catalog.json return 404 on my Shopware store?

The file is switched off for that sales channel, or the shop runs a version before 6.7.12. Shopware answers 404 for any agentic file that is off.

### Does a missing ai-catalog.json lower my score much?

Only a little. The check has weight 1 and a missing file is a warning, not a fail.
