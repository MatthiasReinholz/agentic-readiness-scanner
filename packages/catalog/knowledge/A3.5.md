## In short

A main landmark marks where a page's primary content starts. When product content sits inside one, and no cookie banner comes before it in the HTML, a script or an agent can find the product without guessing. This check is informational and never scored, because no answer engine documents relying on landmarks.

## What this check looks at

Landmarks are regions of a page that WAI-ARIA, the W3C's Accessible Rich Internet Applications specification, defines for assistive technology. The `main` landmark holds the primary content. HTML provides it through the `main` element, or through any element with `role="main"`. Screen readers use it to jump straight to the content, past headers and menus.

The scanner looks at each sampled product page, or the home page when no products were sampled, and asks two questions:

- **Is there a main landmark?** It looks for a `main` element or an element with `role="main"`.
- **Does a cookie or consent banner come before it in the HTML?** It looks for an element whose class or id contains cookie, consent, gdpr, privacy-banner or the token cmp (consent management platform), placed earlier in document order than the main landmark.

Elements that render nothing, such as a `script` with a consent-related id, do not count. Generic names such as modal, overlay or drawer are not matched, so a cart drawer or a closed country picker is not reported as a banner.

## Why it matters for AI agents

An agent reading raw HTML has to decide which text is the product and which is navigation, footer or legal notice. A main landmark answers that directly. A tool that turns pages into Markdown or plain text can use it to cut away the surrounding chrome.

Order matters too. A consent banner placed at the top of the body is the first text an agent or a screen reader meets. A long cookie notice then stands between the reader and the product.

The benefit is real but not documented by any search or answer engine. That is why this check is informational. It is also basic accessibility, which helps people using screen readers regardless of AI.

## How the scanner decides

- **Pass:** every judged page has a main landmark, and no cookie or consent banner precedes it in the HTML.
- **Warn:** a page has no main landmark. Or, when every page has one, a cookie or consent banner comes before it on at least one page. The message names the element, for example `div#cookie-banner`.

This is a heuristic based on class and id names, so it warns and never fails. The evidence records, per page, whether a main landmark was found and which banner preceded it.

The weight is informational. The result never changes the score or any level.

## How to fix it

Wrap the product area in one `main` element per page, and render consent banners after it in the HTML or inject them with JavaScript. CSS can still show the banner at the top or bottom of the screen.

### WordPress and WooCommerce

- Most current themes already wrap content in a `main` element. Check the product template, usually `single-product.php` in a classic theme or the Single Product template in the site editor of a block theme.
- In a block theme, set the group that holds the product content to use the main HTML element in the block's Advanced settings.
- Many consent plugins inject their banner with JavaScript or print it in the footer. If yours prints it at the top of the body, look for a setting that changes its position in the markup.

### Shopify

- Shopify's own themes wrap page content in a `main` element in `theme.liquid`. Check that a custom or older theme does the same.
- Consent banners from apps are usually injected by script. A banner section placed at the top of `theme.liquid` can be moved below the main content in the markup.

### Any other stack

- Use one `main` element per page and put the product title, price, description and buy button inside it.
- Render the consent banner at the end of the body, or mount it from a script, and position it with CSS.
- Do not nest one `main` inside another, and do not hide the main content until consent is given.

## Verify it yourself

Check for a main landmark and for consent markup in the raw HTML, and compare their line numbers:

```bash
curl -s https://example.com/products/example | grep -n -oiE "main[ >]|role=\"main\"" | head -3
curl -s https://example.com/products/example | grep -n -oiE "(id|class)=\"[^\"]*(cookie|consent|gdpr)[^\"]*\"" | head -3
```

The consent element should come later than the main landmark. Browser developer tools also show landmarks in the accessibility tree.

## Common mistakes

- **Using a div with a class of main.** A class name is not a landmark. Use the `main` element or `role="main"`.
- **Printing the cookie banner as the first element of the body.** Move it to the end and keep its on-screen position with CSS.
- **Several main elements on one page.** Only one should be visible at a time.
- **Hiding the product until consent is given.** An agent without cookies then never sees it.

## FAQ

### Does a main element improve SEO or AI visibility?

No search or answer engine documents using it as a ranking or eligibility signal. It helps tools that extract content and people using screen readers, which is why this check is informational.

### Is an article element enough instead of main?

The scanner looks for a `main` element or `role="main"`. An `article` for the product inside `main` is good structure, but on its own it does not satisfy this check.

### Will moving the cookie banner break consent compliance?

No. Its position in the HTML does not change whether it is shown or whether scripts wait for consent. CSS controls where it appears on screen.
